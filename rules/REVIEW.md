# 代码审查规则

按 AGENTS.md 的流程审查，只报有证据、能说明实际影响的问题。

## 独立审查

- 审查者未参与本次实现，使用不继承实现对话的新上下文；读取规格、规则、固定基线与 diff，以及必要代码、测试和验证证据。
- 跨模块状态、并发、数据兼容或权限边界等复杂改动，或需求理解、复现结果、影响判断存在争议时，主 Agent 按需增加验证子代理并说明验证目标。
- 验证者只核对指定疑点，以复现结果或明确的代码因果关系判定，不按多数票定真伪。

## 报什么

- 同时检查规格和仓库规则。问题须说清“什么情况 → 哪里出错 → 有什么影响”；文档误导实际用法、配置指错路径或目标也算问题。个人风格偏好、无实际影响的精简建议不报；工具已覆盖的格式问题交工具处理。
- 每项附文件名和行号、触发条件、实际影响及复现结果或代码依据；只发布已核实的问题，争议项先验证。
- 分清本次引入或加剧的问题与无关存量问题，再按严重性排序；无关存量问题记入独立任务，不阻塞本次交付。阻塞问题指会导致规格验收失败，或破坏数据、安全、兼容性的问题。
- 同一根因合并报告，已报问题只更新状态，不重复评论。每轮非阻塞建议最多 3 条；已确认的阻塞问题全部报告。
- 默认跳过 `target/`、缓存及未修改的生成文件、第三方代码；判断本次变更影响时可读取。没有问题不发逐行评论，最终报告只留一句审查结论。

## 何时停止

- 同一次交付最多审 3 轮，首轮也算；首轮按固定基线看完整任务 diff，包含未提交和新增文件。后续只复核已报问题和上一轮后新增改动，不扩大范围挖无关存量问题。
- 有明确证据的本次变更问题即使后几轮才发现也须处理，不能按发现轮次算成存量。同类问题集中修复，修复后的复验按 AGENTS.md 执行。
- 3 轮后仍有阻塞问题或未解决的争议，停止自动循环，列出剩余问题交人工判断，不得标记通过。
