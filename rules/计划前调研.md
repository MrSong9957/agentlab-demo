# 计划前调研

## 核心思想

收到任务后，在编写计划前，先明确真正想要的结果，再让不同领域的专家独立研究，结合近期社区讨论汇总方案，并保存汇总报告与原始输出。

## 详细说明

### 流程

1. 用一句话说清用户真正想要的结果，再列出与它相关的 3–5 个不同领域。
2. 并行启动多个独立子代理，各扮演一个领域的顶级专家。专家之间不交流，各自独立研究。
3. 额外启动一个“侦察兵”子代理，专门执行 `/last30days 话题或问题`，调研过去 30 天的社区讨论（Reddit、HN、YouTube 等），产出一份简报。这个代理不提方案，只汇总：大家在夸什么、骂什么、卡在哪、有什么意想不到的用法。
4. 所有子代理跑完后，进入汇总，完成后按落盘规则存档。

### 每个专家的输出

每位专家的完整输出限 300 字，包含以下内容：

- **我是谁**：一句话身份。
- **离谱目标**：常规怎么做 / 我的目标是什么（高几倍）/ 凭什么能做到。
- **我的方案**：3–5 个具体动作。
- **成立前提**：方案依赖什么条件。
- **验证方法**：用什么外部标准判断对错，禁止自评。

### 侦察兵的输出

完整输出限 200 字，包含以下内容：

- **民意速写**：用一句话概括主流看法。
- **吐槽集中营**：骂得最多的问题。
- **冷门亮点**：少有人提、但有价值的发现。
- **对专家的提醒**：社区共识里哪些是坑。

### 最后汇总

- **共识**：专家们一致的点。
- **冲突**：矛盾点及裁决理由。
- **社区校准**：侦察兵简报支持或否定了专家方案的哪些部分。
- **组合方案**：按优先级排列的行动清单。
- **背景知识**：专家带来的、用户原本不知道的关键认知。

### 落盘规则

- 统一存入项目的 `docs/think-tank/`，目录不存在时创建。
- 汇总报告：`docs/think-tank/日期-任务关键词.md`。
- 原始输出：存入 `docs/think-tank/raw/`，每位专家和侦察兵各存一份，文件名为 `日期-任务关键词-专家名.md`。
- 双向链接：提前确定文件名，汇总报告和原始输出使用同一套名称。
  - 汇总报告末尾添加“原始输出索引”章节，为每位专家和侦察兵添加一条相对链接。
  - 每个原始输出文件第一行写返回汇总报告的相对链接。
- 保存后在对话里报告文件路径，方便用户直接打开。

汇总报告中的链接示例：

```markdown
## 原始输出索引

- [性能专家](raw/2026-10-28-app启动时间-性能专家.md)
- [侦察兵](raw/2026-10-28-app启动时间-侦察兵.md)
```

原始输出文件第一行的链接示例：

```markdown
→ [返回汇总报告](../2026-10-28-app启动时间.md)
```

## 约束

- 全程大白话，不许空话套话。
- 任务确实简单、不涉及多领域时，直接说明，别硬拆。
