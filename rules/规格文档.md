# 规格文档

每个可独立验收的功能写一份规格。规格定义完整要求，计划安排实现顺序。

## 必填内容

1. **目标与边界**：写明目标、范围、运行条件和必须保持的现有行为。
2. **需求与验收**：每条需求编号，写明适用场景、预期结果和验证方法。按需覆盖接口、错误、权限、数据和并发。
3. **性能与资源**：只列需要限制的指标。阈值须有依据，并写明环境、负载和测法；无依据时先测基线。费用区分实付、估算和未测，缺数据不得写成零。
4. **实施计划**：按“验证关键假设 → 跑通最小完整路径 → 补齐延期项 → 全量验收”编排。标明最小实现覆盖的需求；正确性、安全和资源底线必须满足。
5. **延期清单**：逐项编号，关联需求，区分需求缺口与实现缺陷，写明延期理由和启用限制，引用或补充验收条件。按风险与依赖排序。
6. **验证与交付**：每阶段写明交付物和验证方法。测试随实现安排；收尾执行规定的全量验证，核对全部需求、延期项和文档。

## 验收规则

- 记录测试环境、命令、实际结果和证据位置。未验证的内容明确标注。
- 不得自行改变需求或降低验收条件。要求冲突或验证受阻时，记录原因和缺少的条件。
- 阶段通过不代表整体通过。实现方提交“待验收”，验收方依据规格、证据和可运行产物确认结果。

## 保存与维护

规格放在 `docs/specs/`，证据放在 `docs/logs/`。要求或验收结论变化时，同步更新内容、状态和日期。

本规则以 `wiki/规格文档.md` 为维护入口，同步更新 `rules/规格文档.md`。
