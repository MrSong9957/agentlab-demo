# 003 规格 exec_command 实现（2026-10-08）

规格：`docs/specs/docs/specs/003-exec-command.md`（同步命令执行，参考 Codex 同步版）。
实现：`src/exec.rs`（库模块，前后端分离——无终端依赖，前端可传取消标志与确认逻辑）＋ `tests/exec_command.rs`。

## 关键设计

- 入口 `exec_command(&Value, Option<&AtomicBool>) -> ExecResult`：JSON 工具边界（只接受 cmd/workdir/timeout_ms/max_output_chars，多余字段拒绝）；`ExecResult` 五字段始终存在，`Serialize` 契约有单测锁定（status 小写、null 语义）。
- Shell 固定 `/bin/sh -c`，stdin 关闭；`process_group(0)` 建独立进程组，超时/取消 `libc::killpg(pgid, SIGKILL)` 后 `wait()` 回收（libc 由传递依赖转为直接依赖，Cargo.lock 版本 0.2.189 未变）。
- 等待循环：`try_wait` 轮询 10ms，先查取消标志再查 deadline；被信号终止无整数退出码（code()=None → exit_code null）。
- 输出：两条读取线程各持 8KB 块读管道推入共享 `Mutex<TextSink>`（坑003：不能等退出后再读）；`TextSink` 流式按码点计数截断——跨块 UTF-8 序列用 pending 拼接、非法子序列按 from_utf8_lossy 语义替换 U+FFFD、EOF 未补全替换 U+FFFD；超限后继续读取丢弃（否则管道写满子进程阻塞），缓存不再增长。
- 状态语义：自然结束（含非零退出、自行被信号终止）= completed；成功 = completed 且 exit_code=0；error 时无进程执行（参数校验、workdir 不存在、spawn 失败均在执行前拦截）。

## 测试要点与证据

- 红灯先行：桩实现下 8/8 集成测试失败（错误信息断言不满足），再实现转绿。
- 全量：46 单元 + 9 exec 集成 + 38 llm_flow 集成全过；`cargo check` 通过。
- 规格第 5 节五场景全部覆盖（见规格"实测"列），副作用用 touch 探针与写文件日志双重验证。
- 变异验证（改坏 → 对应测试失败 → 恢复后全绿）：
  - M1 移除码点上限：`sink_cap_*` 4 个单测＋`oversized_output_truncated_to_char_cap`、`discard_after_cap_keeps_child_running_to_completion` 失败。
  - M2 只杀组长不杀进程组：`timeout_kills_process_group_and_stops_writes`、`cancel_flag_stops_managed_processes` 失败（孙进程继续写文件 146→160 字节）。
  - M3 校验接受零：`invalid_inputs_error_without_side_effects` 失败。

## 已知限制（按规格范围保留）

- 单次同步执行，无 PTY/session/write_stdin；命令内 `cd` 不影响下次调用（有测试）。
- 读取线程收尾上限 2s 宽限：若孙进程自行 setsid 逃逸进程组且持有管道，输出可能缺尾（超时/取消路径仍正确返回）。
- `cancelled` 需调用方持有 `AtomicBool`；CLI 尚未接入（规格未要求前端接线）。
