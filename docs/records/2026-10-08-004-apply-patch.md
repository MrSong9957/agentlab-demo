# 004 规格 apply_patch 实现（2026-10-08）

规格：`docs/specs/docs/specs/004-apply-patch.md`（文本补丁修改，参考 Codex 提交 `2fdf047c` 的 apply-patch crate）。
实现：`src/apply_patch.rs`（库模块，JSON 工具边界，同 exec_command 模式）＋ `tests/apply_patch.rs`（10 集成）＋ 模块内 23 单元测试。

## 关键设计

- 入口 `apply_patch(&Value) -> ApplyPatchResult`：只接受 `{"patch": string}`，多余字段拒绝（沿用宿主 exec_command 的严格边界惯例）；结果四字段 `ok / changed_files / state_known / error` 始终存在，动作小写 `add/update/delete`，路径为解析后的绝对路径。
- 解析器为 Codex streaming parser 的整段移植（非流式）：顶层/Add/Delete 块头按整行 `trim()` 匹配、Update 块内按 `trim_end()` 匹配（带前导空格的块头是上下文行）；空行按空上下文行；`*** End of File` 后只允许空行或新 `@@`；CRLF 补丁文本可解析。与参考逐分支对齐，错误带行号。
- 匹配：`@@` 定位行先推进搜索起点；old_lines 用 seek_sequence 三级容差（精确 → 行尾空白 → 两端空白），未移植 Codex 第四级 Unicode 标点归一化（MVP 取舍）；末尾空行“最终换行哨兵”找不到时裁掉重试；上下文行切分替换以保留原始行尾。
- 行尾（text_file 移植）：`SourceFile` 逐行保留换行符（LF/CRLF/CR），约定风格取原文件首个换行（无则 LF）；未涉及行原样保留；插入/替换行用约定风格；更新后为所有行补齐行尾；新增文件由解析器生成恒为 LF。
- 执行器：按补丁顺序逐块“先校验后执行”。新增用 `create_new`（不覆盖已有目标，含悬空符号链接；前置 symlink_metadata 检查给出更友好错误）；父目录缺失时 `create_dir_all`（对应 Codex `write_file_with_missing_parent_retry`）；更新先在内存算出完整新内容再写，匹配/UTF-8 失败不触碰文件；失败即停止，不回滚已生效变更。
- `state_known` 语义：参数/解析/存在性/读取/匹配类失败（未发生写入）为 `true`；写入、删除、建目录失败（变更操作，目标可能被部分修改，坑003）为 `false`，清单只含确认生效项。

## 测试要点与证据

- 红灯先行：桩实现（公共 API 返回“尚未实现”）下集成测试 **10/10 失败**（断言错误信息不满足）；实现后 10/10 通过，单元 23 个随实现交付。
- 全量：`cargo check` 0 警告；69 单元 + 10 apply_patch + 9 exec + 38 llm_flow 全过，无回归。
- 规格第 5 节五场景全部覆盖（实测列已回填规格），断言落在文件字节、存在状态、清单顺序与失败后重读。
- 变异验证（改坏 → 失败 → 恢复后全绿，恢复经字节比对确认）：
  - M1 新增允许覆盖已有文件（去 create_new 与前置检查）：`conflicting_targets_rejected_without_changes` 失败。
  - M2 插入行一律 LF：`line_endings_follow_spec_rules` 失败（CRLF 场景字节级差异）。
  - M3 写入失败仍声称清单可信（state_known 恒 true）：`second_file_write_failure_reports_partial_state`、`readonly_permissions_are_enforced_not_bypassed` 失败。
- 写入开始后故障的实测（最终验收补充，2026-10-08）：`second_file_write_failure_reports_partial_state` 扩为两阶段——
  - 阶段一（open 阶段拒绝）：0444 只读文件，写入在 open 即被拒，目标字节不变；
  - 阶段二（半写截断，坑003 实测）：`FileSizeLimit` 守卫设置进程级 RLIMIT_FSIZE=4096 并忽略 SIGXFSZ（Drop 恢复），第二项目标新内容 8364 字节 → `std::fs::write` 先落盘 4096 字节再返回 EFBIG(errno 27)。实测：目标恰为新内容前 4096 字节确定性前缀（O_TRUNC 已发生，原内容丢失）；第一项照常生效；`ok=false`、清单仅含第一项、`state_known=false`、错误含路径与「File too large」。测试框架外独立复现（rustc 直链 rlib）返回 `{"ok":false,"changed_files":[good],"state_known":false,"error":"写入修改目标失败 …/big.txt：File too large (os error 27)"}`，磁盘 good.txt=8 字节、big.txt=4096 字节。
  - 定向变异：M-A（mutating 失败仍 state_known=true）与 M-B（失败目标混入变更清单）均被该测试捕获后恢复。
  - 并行安全：rlimit 窗口仅包住一次 `call()`；本二进制其他用例单文件最大写入约 55 字节（注释载明约束：新增用例写入 >4 KiB 须先与本用例串行化）；全二进制 5 连跑稳定。
  - 未覆盖：真实磁盘满（ENOSPC）未构造——EFBIG 与 ENOSPC 在本实现走同一条 `write_all` 中途错误路径，截断语义已由 EFBIG 实测；二者差异仅在内核错误来源。
- 权限门（Security Testing Gate）：只读目录内新增/删除、只读文件（0444）修改均拒绝且 `state_known=false`，由 `readonly_permissions_are_enforced_not_bypassed` 覆盖并经 M3 证明有效；环境为非 root（uid 1000），chmod 语义真实生效。
- 真实调用（测试框架外，rustc 直链 rlib 宿主视角）：规格示例 config.txt `mode=dev→mode=test` 返回 `ok=true`+绝对路径清单；多文件（新增+删除）按序返回且磁盘吻合；空补丁 `ok=false` 带原因。

## Code review（双轴）与处置

- 采纳：单元测试三处 `context_line_indices` 簿记断言移除（AGENTS.md §3 不绑定内部写法，行为已由字节级集成测试与替换结果单测覆盖）；解析器重复错误文案提取 `unexpected_update_line`/`expected_at_at`，四处重复块初始化提取 `current_chunk`。
- 不采纳（经与固定提交参考源码核对为误报）：lone-CR 行尾（Codex text_file 原有 `LineEnding::Cr`）；Add 建父目录（Codex `write_file_with_missing_parent_retry` 原有）；块头 trim 分模式不一致（Codex 解析器原样：顶层 trim、Update 内 trim_end，且注释自述比语法宽容）；拒绝未知字段（宿主工具边界惯例）。
- 记录不处理：`from_value` 与 exec 同形的小段重复（跨 003 未提交改动提取公共 helper 收益低）；`Replacement` 元组（有类型别名，与参考一致）。

## 已知限制（按规格范围保留）

- 不支持 `*** Move to`、二进制、`*** Environment ID`（解析即拒绝）；未移植 Unicode 标点归一化第四级容差。
- Add 块按引用语法 `add_line+` 要求至少一行 `+` 内容，故无法新增 0 字节文件（刻意偏差，Codex 解析器更宽容）。
- CLI 未接线（同 003：规格只要求库级工具注册与真实调用可用，未要求 REPL 集成）。
- 真实磁盘满（ENOSPC）未构造（无 root/FUSE 不可稳定构造）；写入开始后失败已由 RLIMIT_FSIZE→EFBIG 确定性注入实测（同一条 `write_all` 中途错误路径），见上节。
- 写入为直接 truncate+write，非临时文件原子替换（规格明确按“可能截断→须重读”契约处理）。
- 补充验收的差异复审（新增仅 `tests/apply_patch.rs`）：无硬性违规；采纳 3 项判断性修复（注释字节数 8282→8364、断言消息改 `get(..24)` 防越界掩盖诊断、进程级串行化约束注释补强）。
