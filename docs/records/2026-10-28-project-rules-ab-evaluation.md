# 项目规则 v1 / v2：两轮独立实测评估

- 更新日期：2026-10-29（UTC）；两轮执行始于 2026-10-28。
- **最终结论：实测持平，没有证据认定 v2 的实际交付效果更好。**
- 本报告汇总两轮结果，是唯一保留的评估文档；实验代码不进入主分支。

第一轮两版均通过 43 项验收。第二轮针对并发隔离、真实进程计时、验证状态、JSON 断言和检查复用增加了五类任务，两版仍均通过 48 项验收，错误检出和合法变化容忍性也相同。

第一轮建议采用 v2，依据主要是条款更明确。第二轮没有把这些文字优势转化为可观察的交付优势，因此不能把 v2 称为实测赢家。重视规则维护清晰度可以偏向 v2；仅依据本次实际效果，两版应判平局。当前证据也不证明两版在所有项目中长期等效。

## 3. 测试能发现错误，也能容忍合法变化

协调者在副本中保持执行者的测试和断言不变，只改变被测行为。五种错误在两版中均被真实断言捕获：

| 故意制造的错误 | v1 | v2 |
|---|---|---|
| profile 忽略显式目录 | 检出 | 检出 |
| wait 立即查询后返回超时，忽略等待与取消 | 检出 | 检出 |
| budget 重新接受 0 和超限值 | 检出 | 检出 |
| metadata 丢弃可选 timeout_ms | 检出 | 检出 |
| normalize 不再 trim | 检出 | 检出 |

budget 的检出依据是新增的预算断言失败，已排除原有 catalog 失败；没有只凭退出 101 判定变异有效。这里只验证五个预先规定的错误，不是完整变异覆盖率。

另外只重排新 JSON 响应的键顺序与空白，保留全部字段、类型、范围校验和旧响应字节。独立 API 探针先确认该版本满足原契约，然后运行回归：两版均退出 0，均没有格式误报。两边都按 JSON 值和类型验证新字段，保留旧响应的黄金字节契约。

真实等待测试按预先约定各额外重复三轮，每轮 7 个用例均通过，无失败或忽略。测试实际启动不变的 job-worker、通过 READY/stdin 协议控制状态，使用宽松计时边界。三轮复验仅说明这次环境中的重复性，不证明永不抖动，也不是三次独立模型试验。

v1 交付 33 个通过用例、v2 为 31，来自拆分和组合方式不同；共同验收和错误检出相同，不能按用例数量排名。审计记录也混有版本查询、脚本包装和嵌套调用，不等同于独立检查次数或工作成本。

v1 执行者确实反馈了“系统时钟可控”与真实进程测试之间的解释空间，并用协议和固定延迟处理；v2 的条款对此更明确。但该文字差异没有在本轮产生验证失败、交付缺陷或可测的质量收益。

v2 对文档例外、修改前基线、并行环境状态、跳过/阻塞和检查去重写得更细。它们是可核对的文本优点；目前两轮没有证明这些优点提高了实际交付成功率、减少了污染或降低了误报。

## 6. 可信度与限制

- 每轮每版仅一个代理，固定顺序连续执行。每个具体任务每版只得到一份实现；43/48 个验收项和三轮进程复验都不是独立模型样本，没有统计显著性结论。
- 两轮均使用宿主默认模型配置，未覆盖模型或推理强度；未取得可归属本实验的完整 token、费用、服务端采样 seed 或精确型号记录，不做成本或速度排名。
- 第二轮减少了共同任务中的方法提示，但仍有规格、成熟技能、辅助规则、既有测试和安全记录器。不能把全部表现归因于候选规则，也不能把基础设施隔离算为模型主动遵循规则。
- 五类任务是离线最小项目。尚未验证真实大型跨模块开发、TUI/PTY、Windows、网络回放、长期会话和大量数据下是否出现差异。
- 两位执行者有本地安全检查记录；独立新上下文的代码审查等阶段受本轮固定代理数量与离线约束未执行，不能称完整规定工作流已经通过。真实 terminal-chat 的全量代码回归本轮未运行，最终交付仅更新文档。
- v1 曾因额度中断；恢复时源码和五项本地验证已经完成，只补命令与报告，没有重做任务。不把额度中断或含暂停的总时长算作规则效果。
- 评测曾发生采集先后错误：变异分析早于完整基线日志落盘，把缺失基线当空集合。已用失败后通过的回归验证“缺基线立即停止”，并依同一原始日志重新扣除既有失败。业务验收条件和被测实现未改；校正后两版仍检出相同五类错误。
- 按用户要求清理完整夹具、原始日志和脚本，仅保留本报告的关键证据；以后不能一条命令原样重跑，需要按保留契约重新搭建。摘要哈希不替代可运行资产。
