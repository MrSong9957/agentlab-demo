## 验收检查与反例

缺陷夹具只将原来的实现改为：

```rust
s.chars().take(max_chars.saturating_add(1)).collect()
```

正确行为是取前 `max_chars` 个 Unicode scalar value；不是按字节，也不是按用户看到的完整字形截断。

16 项独立检查包括：空串的零和非零上限、ASCII 零和一字符上限、超过长度、中文、emoji、组合字符、`usize::MAX`、换行/Tab，以及 CSI、OSC-BEL、OSC-ST、回车、未闭合 OSC、普通 Unicode 文本的过滤契约。

24 项 CLI 检查包括：help；HOME 默认；环境覆盖；参数覆盖环境；参数/环境覆盖在 HOME 缺失时仍可用；空参数、空环境目录、缺失 HOME、空 HOME；未知参数、参数缺值、多余参数；选中目录缺文件或非 UTF-8 时不回退；中文和空格路径；相对路径；高优先级有效值不受低优先级空值影响；输出不擅加换行；并发隔离；不改动配置文件；旧公开 API；含 shell 元字符的目录名按普通路径处理。并发检查用 8 个工作线程启动 24 个真实进程，交替使用两个用户目录。

错误输出、退出码和 stdout 均按冻结规格核对：参数错误为 `error: invalid arguments\n`，目录空值/缺失为 `error: invalid user directory\n`，读取失败为 `error: cannot read banner\n`；这些错误均退出 2 且 stdout 为空。成功退出 0，stderr 为空，文件文本原样输出。

协调者先运行原始夹具，文档检查为 1/3、缺陷检查为 10/16、CLI 检查为 8/24，确认验收能发现目标问题。原始 Cargo 基线中，缺陷项目为 7 通过、2 失败，其中一项为注入的截断错误，另一项为冻结的无关 `legacy_contract`；CLI 项目 3 项通过。两项失败均为本实验夹具设置，不能当作真实项目现有测试状态；负向基线也不是最终交付结果。

## 解释边界与共同问题

- 每版只有一个代理、一次连续执行，三个任务不能算三个独立采样；43 项验收断言也不是 43 个独立模型样本。没有换代理交叉、换 seed 或多模型复验，不能声称统计显著或普遍胜出。
- 两边共同说明已提供命令、冻结规格、隔离约束和不修无关失败的边界，宿主还有通用编码约束。这能保证安全与任务一致，也可能掩盖两版规则的增量差异。验收不是仅交规格的严格盲测。
- 本轮仅有文档、纯函数和普通 CLI；未覆盖真实 TUI/PTY、Windows、网络回放、大型跨模块变更、真实时间逻辑或真实项目全量回归。
- 实验不允许继续派生代理或安装/联网扩展。两边都报告独立安全/代码审查等环节有未执行部分；行为验收、clippy 和局部安全输入探针不能被包装成整个规定工作流已完成。
- 未按完成先后、用例个数或主观自评分判胜；并发运行下的耗时也未用作版本性能结论。

两版共同引用 `rules\计划前调研.md` 和根目录 `project-lessons.md`；本仓库实际经验文件位于 `rules/project-lessons.md`。迁入 Linux 项目时应统一真实路径，并填好第 8 节的命令与夹具信息。本次给两边相同的辅助文件，不把这些共同问题当作版本差异。两版仍包含固定的多阶段工作流，受能力限制时均需要如实报告缺口；仅修改文档的例外不能用来宣称代码工作流已经完成。

本报告保留结论、关键实测数值、命令和边界；按用户要求删除临时夹具、完整原始日志和脚本后，不再具备一条命令原样重跑实验的完整资产。后续复验需要按这里的来源和契约重新搭建，不能将摘要哈希当成可运行证据。
