## 实施前情况与依据

1. `.env` 仍在 Git 索引内，现有规则不匹配它。Git 忽略规则不影响已跟踪文件；实施时必须单独取消跟踪，并保留磁盘上的文件。[Git 官方说明](https://git-scm.com/docs/gitignore)。
2. 当前规则为 `/target/`、`*.pending-snap`、`*.snap.new`、`db`、`.agents`。`.pytest_cache` 通过自己的 `.gitignore` 中的 `*` 排除内容；全局 Git 排除文件未配置。
3. 入口 `src/app/src/main.rs` 从当前工作目录读取 `.env`；`catalog.rs::load_dotenv_from` 跳过空值、保留已有环境变量，不允许 `.env` 注入信任根控制变量。现有手动配置只引用 `env:DEEPSEEK_API_KEY`，不需要在示例中增加其他厂商字段。
4. `config/auto_catalog.json` 是可由内置资料离线重建的自动目录。当前存在一份查询缓存，其身份字段包括 `base_url`、`protocol`、`cred_name`、`cred_fp`，并保存查询时间和模型名单。它没有必要作为通用配置整体分发，适合作为本机缓存候选讨论；本轮未记录字段值。
5. `.agents` 当前包含 `agents/Security-Testing-Gate.md` 和 `skills/comprehensive-testing/`，属于代理／技能定义，不能仅凭目录名认定为缓存。需要确认它们是项目共享资料，还是个人同步安装副本。
6. 已跟踪的黄金快照共 724 份；另有 3 份已跟踪的 `.snap.new`，即使现有规则匹配它们，仍会继续被跟踪。3 份都与对应黄金主文件不同，关联测试已标记为 `008-TRIM`；处置需结合 008／009 范围讨论，不能直接接受或删除。
7. `docs/records/` 有正式验证 `.log`，测试夹具有 `.jsonl`、`.stdout`、`.stderr` 等文件。按扩展名整体排除会遗漏应交付的测试证据。
8. 当前本地 `main` 保留 48 次历史，`origin/main` 为重新发布后的单根历史。后续实施应以 `origin/main` 为提交基线，并保留本地旧历史，不能把旧 `main` 整体推回远端。

范围调查只读取路径、程序代码、配置结构和必要的非敏感字段名，没有读取真实 `.env` 内容。实施时仅在单个进程内比较真实文件取消跟踪前后的字节，未输出或记录内容、哈希、凭证值或指纹值。
