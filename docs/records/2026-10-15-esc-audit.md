# Esc 全用途审计（2026-10-15，只调查不改实现）

背景：用户决定——Ctrl+C 在任何页面/任务状态/选区状态下只退出 CLI（不再取消、不复制）；取消执行改用 Esc；该决定替代旧 Ctrl+C「运行中取消、空闲退出」契约。接线前先查明 Esc 既有用途与冲突。本文为调查结论与迁移方案，**未改任何实现**；探针（PTY/e2e 临时用例与视图单测）已全部删除，仓库回到审计前状态（148 项未提交、HEAD b0e8d48、v11 在库）。

## 2. 「先消费导致取消不到达执行侧」的路径清单（目标第 3 问）

1. **F4 聚焦态**（#3）：Esc 被 disclosure Cancel 消费——取消需第二次 Esc。
2. **详情页**（#4）：Esc 被页关闭消费——取消需先 Esc 关页再 Esc。
3. footer「?」展开态（#8，低频）：先收提示。
4. 空闲态本身无取消诉求，不构成问题。

另：P3 原始探针曾复现「F4→Esc 后中断链永久失效」，经判别实验（P3E：同间隔改 dwell 等待）**证伪为探针等待方式相关**（wait_screen_timeout 与 dwell 的差异），dwell 版 2 次复跑取消均生效；机制未查明，如实登记为未解探针异常（非生产缺陷证据；接线轮回归时若再现须先定位）。

## 3. 迁移方案（待用户决策，不自行分层让 Esc 兼职多项）

**结论：Esc 已有 5 类在用功能（#1-#5-#6-#7 已工作、#3-#4 为消费点）——不能简单「直接接线」，但运行中裸态/选区的取消链已天然在位（母本同款），真正要决策的只有 3 点：**

- **A. F4 聚焦态（#3）**：选项 A1＝维持现状（Esc 先清焦、第二次 Esc 取消——零改动，Esc 语义「逐层退出」）；A2＝聚焦态 Esc 直接取消并连带清焦（改动 `transcript_owns_key`/驱动序，聚焦导航的退出语义变化）。建议 A1（与页/选区的逐层退出一致，且零改动）。
- **B. 详情页（#4，B 方案核心）**：选项 B1＝维持「页内 Esc＝关页」，取消须关页后再 Esc（零改动；与 012 §8 需求④「Esc 一次返回」一致）；B2＝页内 Esc 在 turn 运行中改为取消且**页保持打开**（关页仍用现行 Esc——冲突：同一键两义，违背「不擅自分层」）；B3＝页内 Esc 在运行中＝先关页再取消一次完成（一键两效，同样两义）。建议 B1（页是全屏浏览态，「一次 Esc 返回对话」契约不变；取消回到主视图后一次 Esc 即达）。
- **C. Ctrl+C 统一退出**：改驱动两处 ctrl_c 分支为恒 `return Quit`（主视图 `chat_driver.rs:501-511` 去掉运行中取消＋`jump_to_latest`；详情页分支 `:448-456` 同步），Esc 侧零新增（#1 已在位）。退出须保留的收尾（现有 Quit 路径已全部具备，验收时逐项核对）：**工具进程处理**（Quit 后宿主 `set_cancel(true)`＋exec 进程组 SIGKILL 回收，`main.rs:56-71`/006 N2b）；**会话保存**（`flush_final_session` 退出排空，007）；**终端恢复**（`restore_after_exit`：备用屏/raw mode/键盘增强/焦点，008-A5）；空闲动画期 SIGINT 130 保留（001 规格）。
