### 4. ConPTY 驱动与场景断言（node-pty＋@xterm/headless，AGENTS.md 优先方案）
Node ≥18；`npm i node-pty @xterm/headless`。每个场景起一个新 probe 进程
（`TERM=xterm-256color` 等价环境；ConPTY 无 TERM 概念，程序内 terminal-detection 走
Windows 探测路径）。屏幕断言用 xterm Terminal buffer（`term.buffer.active
.getLine(n).translateToString(true)`）＋`term.buffer.cursorX/cursorY`。
| # | 场景 | 输入 | 断言 |
|---|---|---|---|
| 1 | 启动 | — | 原始字节含 `\x1b[?1049h`（进备用屏）；屏幕出现 footer 提示（"for shortcuts" 字样）；无 "No transcript content available"（启动为空 transcript） |
| 2 | 中文输入与光标 | 分字节写入 `你好世界`（逐字符 ≥30ms 间隔，避开 paste-burst） | composer 行（光标行）出现原文；`cursorX` 位于文本尾后（宽字符列宽×2）；每帧后光标位置稳定 |
| 3 | 回复渲染 | `你好\r`（文本与 CR 分开写，间隔 ≥150ms） | 屏幕出现 `完整回复：Windows-ConPTY-OK`；流式期间出现分块（Delta 行）后收尾为完整 cell |
| 4 | 滚动/resize | 多轮长回复后 `pty.resize(80, 24)`；PageUp（`\x1b[5~`） | resize 后无 panic、布局重排（composer 仍在底部、transcript 可读）；PageUp 后顶部能看到早期内容（分页视口），再 PageDown/最新消息键回底（母本键位：PageDown/End） |
| 5 | 粘贴 | `\x1b[200~多行文本\r\n第二行\x1b[201~`（bracketed-paste） | composer 草稿含两行（Enter 不被并入提交）；随后 \r 提交成功 |
| 6 | Ctrl+C 空闲 | 首次授权问句不涉及（probe 无授权门）；TUI 就绪后 `\x03` | 进程退出；尾部原始字节含 `\x1b[?1049l`（终端恢复）；（probe 不打印"再见!"——那是宿主 main 的行为；断言退出码 0＋恢复序列） |
| 7 | Ctrl+C 工具期 | spawn_turn 的 canned 线程 sleep 期间 `\x03` | `set_cancel_requested` 的 AtomicBool 置位被观测（stderr 标记）；probe 进程存活不崩；turn 结束后仍可继续输入（CLI 存活） |
| 8 | 退出恢复 | `/exit\r` | `\x1b[?1049l`＋退出码 0 |
- Windows 启动早期 Ctrl+C 等价说明：ConPTY 下 `CTRL_C_EVENT` 默认结果为
  `STATUS_CONTROL_C_EXIT`（0xC000013A/十进制 3221225786）＝Linux SIGINT 130 的对应物；
  probe 接管前窗口极小，可不单独断言（在报告注明）。
- 全场景通过标准：8/8 绿＋无 panic＋恢复序列齐备；任何场景红→保留现场（原始字节流＋
  xterm 屏幕转储）如实回报，**不得调整断言迁就实现**。
