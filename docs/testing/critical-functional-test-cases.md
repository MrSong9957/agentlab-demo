# 高风险功能测试用例（合并补充版）

> 日期：2026-10-10（Asia/Shanghai）　状态：用例设计，尚未执行本轮测试
> 范围：terminal-chat 001–006 的八个关键功能。行为以本地最终已批准规格为准。

合并本会话两份设计，修正不确定/错误预期，并为本地 Agent 提供自动化执行指令。本文件是跨功能覆盖索引，功能规格继续按原编号维护。

## 判据、前提与使用方法

每项同时检查返回数据、真实状态变化与副作用：校验拒绝无目标操作；执行中失败如实报告已发生变化。纯函数的精确返回值就是可观测结果；涉及 I/O 的路径必须核对真实请求、文件和进程。

- **定**：本会话已确认的契约或必要结果；落地仍要与本地最终规格对照。冲突时记录来源差异，不能直接改产品迎合清单。
- **核**：名单、具体语法或版本相关行为需要先确认。确认后写独立期望；规格不明确则转入需决策，不能自动把当前输出当正确。
- **待**：新增行为承诺尚未定，包括授权并发不丢记录、超时上限与实际 REPL 取消。仅做安全的受控调查，不擅自补功能或将缺口标为通过。

本清单共 **111 条**：正常 29、边界/并发边界 48、异常 34。契约标记：定 89、核 19、待 3。一条可含多个变体，多条可由一个有效测试证明；清单条数不等于需要新增的测试函数数。

统一夹具与独立期望：

- A 为批准目标，B 为未批准目标；两者都是受控服务。模型响应由本地 mock 给出并捕获请求。HTTPS 使用可信受控夹具；没有能力时明确受限，不能绕过证书校验。
- 假 Key：K1=`test-key-A-0001`，K2=`test-key-B-0002`。UTF-8 SHA-256 前16个小写十六进制字符独立向量分别为 `950c98f9171c8d90`、`3a9b550c0a9ac630`。只使用假凭证，不能从真实环境复制 Key。
- 所有用户根、配置根、凭证根、workdir、缓存和输出文件都隔离；所谓“未预设控制变量”也必须使可信回退根指向临时夹具。禁止用真实家目录作证据目标。
- 测试子进程使用受控环境，只保留必要运行信息并显式注入假 Key 和临时路径；不要继承真实凭证。隔离源码副本仅带本轮源码/测试状态，排除真实 .env、凭证、用户配置和缓存，环境文件由夹具构造。
- 基本字节向量：`21\n`=3字节；`warn\n`=5字节；`hello\n`=6字节；`mode=dev\n`=9字节；`mode=test\n`=10字节；`中🙂`=7 UTF-8字节、2码点。这里 `\n` 表示真实 LF 换行，不是反斜线和 n 两个普通字符。
- 响应上限 L=`10×1024×1024=10,485,760`字节。长度夹具必须是有效完整 JSON，并独立核对编码后的总字节长度。
- 权限与进程组用非 root Linux 环境。所有挂起/竞态/超时场景有外部看门狗和失败清理，回收工具自己的独立进程组，不能只杀 CLI。
- 时间用可控时钟或操作前后窗口。测试停止时间允许明确的调度余量，不能用临时睡眠碰运气构造同步点。
- JSON比较以字段值、角色顺序和关联关系为准；不钉死对象键顺序/外层转义书写。arguments 解码后的字符串需按历史契约保真。tool结果按独立预期核对，不能再次执行工具生成期望。

## 完整用例

### 1. origin 授权门

资金：阻止未经批准的凭证外发。

聊天和携带凭证的 refresh 都要覆盖。首次批准/拒绝必须走真实授权入口；预置 grant 只能用于已授权命中场景。

| 编号 | 类别 | 契约 | 输入／场景 | 必须核对的结果与实际变化 |
|---|---|---|---|---|
| AUTH-N01 | 正常 | 定 | 空授权记录，首次明确同意 A＋K1 | A 恰收一个预期请求，Bearer 值等于 K1，B 零请求；新增恰一条 grant，origin 为规范化 A，cred_fp 为独立计算值；added_at 落在操作前后时间窗；按已有 Unix 权限约定核对记录 0600、软件管理目录 0700。 |
| AUTH-N02 | 正常 | 定 | 已有 A＋K1 授权，同会话第二条消息及重启后再次使用 | 均命中原授权，无再次询问；每次请求只到 A；授权文件字节不变，mtime 可辅助核对。若要证明完全无重写，另观测写操作，不能只凭字节与 mtime。 |
| AUTH-N03 | 正常 | 定 | 首次授权时明确拒绝 | 目标服务零请求，不新增 grant；拒绝反馈包含目标 origin，且不包含 Key。其他正常初始化文件不算授权记录。 |
| AUTH-N04 | 正常 | 定 | 分别从聊天、携带凭证的 refresh 发起已授权操作 | 两个真实入口均正确发送凭证到 A；聊天回复与 mock 内容一致；refresh 收到预设模型列表并按既有规则更新目录。不能只测试授权 helper。 |
| AUTH-B01 | 边界 | 定 | 默认端口/无显式端口、路径变化、大写 scheme/host | 按 origin 规则独立计算预期：https 默认 443、http 默认 80 等价；路径不参与；scheme/host 规范化后匹配。可在 origin 计算层验证默认端口，无须绑定低端口。 |
| AUTH-B02 | 边界 | 定 | 改 scheme、host、有效端口；localhost、127.0.0.1、[::1] 互换 | origin 改变后不沿用旧授权；三个不同 host 表示分别匹配，各未授权目标收到零凭证请求。 |
| AUTH-B03 | 边界 | 定 | K1 换 K2，未批准 K2，随后换回 K1 | K2 不被 K1 的指纹放行，拒绝期间原记录不变；换回 K1 能复用仍存在的旧授权。不推定批准 K2 后旧记录如何保留。 |
| AUTH-B04 | 边界 | 定 | 合法空列表，以及同 origin 但指纹不匹配 | 均不能放行；非交互条件下零请求、零新增授权。空列表与损坏文件分开测试。 |
| AUTH-B05 | 并发边界 | 待 | 两个 REPL 同时首次批准不同 origin | 先调查读—改—写竞争。至少文件可解析且无未经同意的组合；是否必须两条都保留，取决于并发不丢记录的明确承诺。不能以“尽量都在”作为验收。 |
| AUTH-E01 | 异常 | 定 | 空文件、截断 JSON、JSON 数组、关键字段类型错误 | 不崩溃，不凭损坏记录放行；按既有契约返回解析错误或未授权。测试非交互/拒绝条件下零请求，未经明确恢复不得把损坏记录自动当成已授权。 |
| AUTH-E02 | 异常 | 定 | 用户同意，但持久化因权限或受控写故障失败 | 报持久化错误且不发请求；原记录按原子写契约保持；不能凭一次口头同意忽略落盘失败继续外发。使用非 root 和真正能触发拒绝的夹具。 |
| AUTH-E03 | 异常 | 定 | 非交互未授权；用户目录尚不存在或不可用 | 非交互不自动批准，目标零请求；目录创建与错误按已有规则；不可用路径明确报错，不泄露凭证。记录路径必须属于可信临时根。 |

### 2. 信任根与凭证围栏（F1 链）

资金＋数据：仓库输入不能重定位凭证与授权根。

关键区分：显式进程配置属于受控正例，仓库 .env 是攻击输入。测试根都放临时目录；凭证围栏不等于工具工作区沙箱。

| 编号 | 类别 | 契约 | 输入／场景 | 必须核对的结果与实际变化 |
|---|---|---|---|---|
| TRUST-N01 | 正常 | 定 | 无更高优先级 Key，.env 提供普通凭证变量 K1 | 解析值和请求头准确为 K1；可信用户根、配置根不改变；不得因屏蔽控制变量而屏蔽普通凭证变量。 |
| TRUST-N02 | 正常 | 定 | 进程显式设置可信临时 TCHAT_USER_DIR，合法预授权 | 使用该可信根读取 grant 并正常发送 K1；证明修复针对 .env 注入，不误伤用户显式配置。 |
| TRUST-N03 | 正常 | 核 | 合法的根内 file: 引用 | 按本地受支持的路径/字段语法取出准确的字符串值；JSON 字段式凭证不得把整个文件当 Key；源文件不变，请求头等于独立预期。 |
| TRUST-B01 | 边界 | 定 | 控制变量未预设，逐个向 .env 注入实际 TRUST_CONTROL_VARS | 攻击行被跳过，最终配置与授权根仍是测试预设的可信回退根；预置攻击 grant 不被读用。此场景必须独立于“已有变量不覆盖”。 |
| TRUST-B02 | 边界 | 定 | 控制变量已由进程设置，再向 .env 注入不同值 | 已有可信值不变，实际读写位置正确；仅该场景通过不能证明新黑名单生效。 |
| TRUST-B03 | 边界 | 核 | 黑名单中的小写、混合大小写变体 | 按项目已批准的大小写匹配规则逐项验证；源码审阅已指出的小写变体必须钉住。新增变体要求先确认规则，不能只检查提示字符串。 |
| TRUST-B04 | 边界 | 定 | 相似前缀目录、路径穿越及根内链接指向根外 | canonicalize 后按路径组成部分判断包含性；根外对象不能被当凭证发送；不泄露外部文件内容。目录名相似不代表子目录。 |
| TRUST-B05 | 边界 | 核 | 凭证根自身为符号链接；引用规范化后仍在根内 | 如既有规则允许，两侧 canonicalize 后合法引用仍可用，逃逸仍拒绝；不得只规范化引用而保留未规范化的根。 |
| TRUST-B06 | 边界 | 核 | .env 的空值、引号、行内注释、重复键、CRLF、BOM | 逐项核对受支持语法和优先级，独立预测最终值。不能未经规格核对就规定“重复键首个生效”或强制新增 BOM 支持。控制变量在所有受支持语法中都不能生效。 |
| TRUST-E01 | 异常 | 定 | 完整 F1：恶意 .env 改根＋攻击目录预置匹配 grant | 真实 CLI 仍用可信临时根；攻击 grant 不被采用；攻击服务零凭证请求；可信授权记录不变。正常凭证变量可生效，但不能造成静默外发。 |
| TRUST-E02 | 异常 | 定 | file: 的 ../ 逃逸、根外绝对路径、链接逃逸 | 解析拒绝、零请求；输出不包含目标文件内容；目标文件字节不变。 |
| TRUST-E03 | 异常 | 核 | file: 缺字段、字段非字符串、非法 JSON、空串值、缺失/不可读文件 | 按真实凭证格式构造非法输入；报解析/读取/缺凭证错误，零外发、不回显内容。若某格式并未支持，不为测试扩展能力。 |
| TRUST-E04 | 异常 | 核 | 无等号、非法键名、其他格式错误行 | 按既有规则忽略或报错，不 panic、不污染信任根；检查后续合法行是否按约定处理。 |

### 3. 重定向拒绝与 HTTPS 强制

资金：已授权首站不能转送凭证。

本节保留真正成功的请求正例。连接尝试和完整 HTTP 请求要分开计数；响应大小按字节计算。

| 编号 | 类别 | 契约 | 输入／场景 | 必须核对的结果与实际变化 |
|---|---|---|---|---|
| NET-N01 | 正常 | 定 | 已授权、证书有效的受控 HTTPS 端点 | 发送到预期端点，Key、方法、路径和 JSON 请求体准确；正常响应被正确处理；无额外请求。若缺本地可信 TLS 夹具，分别证明 URL 准入和共享发送路径，并明确 TLS E2E 受限，不能关闭证书验证凑通过。 |
| NET-N02 | 正常 | 定 | 项目允许的 loopback HTTP mock | 已授权时恰一次预期请求，正确 header/body，响应结果正确；豁免不能扩展到远程 HTTP。 |
| NET-B01 | 边界 | 定 | 300、301、302、303、307、308、399 | A 收到首个请求后拒绝继续；B 零请求、零凭证；按契约报告重定向错误。 |
| NET-B02 | 边界 | 定 | 3xx 指向同 origin；没有 Location；Location 非法 | 都不产生第二跳；不因同 origin 或缺 Location 放宽 3xx 拒绝。 |
| NET-B03 | 边界 | 核 | 回环名单：localhost、127.0.0.1、[::1]、127.0.0.2 及端口形态 | 按项目的精确豁免规则验收。127.0.0.2 也属于 127.0.0.0/8 回环段，只有项目明确限定名单时才规定拒绝。HTTP 豁免不代表 origin 授权可互相复用。 |
| NET-B04 | 边界 | 定 | 合法 base_url 有/无末尾斜杠 | 拼接点只保留一个分隔符；如 /v1/ 与 /v1 均发到 /v1/chat/completions；origin 和请求体不变。 |
| NET-B05 | 边界 | 核 | URL 尾随空格、默认端口 | 空白是拒绝还是规范化，按本地 URL 契约确认；若接受，实际目标不能发生意外变化；默认端口 origin 正确。 |
| NET-B06 | 边界 | 定 | 有效响应 JSON 总字节为 L−1、L、L＋1；L=10 MiB | 复用既有响应上限用例。正文必须是完整有效 JSON，并独立核对总字节长度：L−1 与 L 接收，L＋1 拒绝；结果和超限错误准确，不能把 JSON 解析失败误判为长度拒绝。若本地批准阈值定义不同，先标出规格差异。 |
| NET-E01 | 异常 | 定 | 远程 http base_url；正式路径的远程明文公共目录 URL | 发送前按既有 HTTPS 政策拒绝；合法授权不能旁路；公共目录刷新失败保留旧目录。 |
| NET-E02 | 异常 | 核 | 旧环境开关存在，试图放宽正式 HTTPS 规则 | 先确认真实旧钩子；若当前规则已明确不允许旁路，开关存在也不能放行。不虚构不存在的变量或新开关。 |
| NET-E03 | 异常 | 定 | userinfo 伪装、非法 URL、无效证书 | 按真实 host/origin 判断；不给伪装目标发 Key；证书失败不降级 HTTP，且无携带 Key 的 HTTP 请求被接收。 |
| NET-E04 | 异常 | 定 | 完整请求后连接重置、静默不响应、连接拒绝 | 错误分类符合契约，无自动重发。发送后断开用完整请求计数；更早失败用连接尝试计数，不强行要求每种错误都收到一条完整 HTTP 请求。 |

### 4. exec_command

权限＋数据：执行正确、终止可靠、输出完整。

目标命令是否执行以探针和存活进程判断，不要求内核从未创建启动失败的瞬时子进程。stdout/stderr 跨流时序没有契约就不写死。

| 编号 | 类别 | 契约 | 输入／场景 | 必须核对的结果与实际变化 |
|---|---|---|---|---|
| EXEC-N01 | 正常 | 定 | 指定 workdir，计算 3×7 并输出、写 sum.txt | stdout 为 21\n，sum.txt 也是 21\n，共 3 字节；退出码 0；文件确实位于指定目录，其他目录不多出同名文件。 |
| EXEC-N02 | 正常 | 定 | 分别输出 stdout、stderr，写文件后退出码 7 | 两流内容和各自顺序准确，真实退出码 7；已写文件保留，无自动回滚；不能伪报退出码 0 或未执行。 |
| EXEC-N03 | 正常 | 定 | 指定/省略 workdir，输出实际 cwd | 指定时 cwd 等于受控目标目录；省略时按会话 cwd；两种情况的文件落点准确。 |
| EXEC-N04 | 正常 | 定 | 工具层已有取消入口，在命令运行后触发取消 | 按 003 结果结构报告取消；目标进程组和后台子孙停止，日志不再增长；区别于尚未接好的 REPL 取消。 |
| EXEC-B01 | 边界 | 定 | timeout_ms 为极小合法正整数；省略为默认值 | 长命令确实在规定超时加测试调度余量内停止；不把 1ms 当成必能完成某个短命令的性能承诺；缺省值按现有默认。 |
| EXEC-B02 | 边界 | 定 | max_output_chars=1，输出中🙂A等单流多字节文本 | 保留完整第一个码点，不产生半个 UTF-8 字符；对中🙂，7 字节、2 码点，不能按字节截断。 |
| EXEC-B03 | 边界 | 定 | 单流输出恰为上限 N 与 N＋1 个码点 | N 时不误标截断，N＋1 时截断标记正确且保留精确前 N 码点；最大数按真实字段契约。 |
| EXEC-B04 | 边界 | 定 | stdout、stderr 同时 MB 级输出，输出上限很小 | 结果保持契约内前缀与截断标志；两路都继续消费到 EOF；命令正常退出，不因管道未排空而超时。 |
| EXEC-B05 | 边界 | 定 | 合法 UTF-8 字符被多次读取拆开 | 重组后与原文准确一致，不能因读取边界产生 U+FFFD；测试围绕字节流完整性，不硬绑 READ_BUF 常量。 |
| EXEC-B06 | 边界 | 核 | 真正非法 UTF-8 字节序列 | 按已有解码策略独立算结果；采用 lossy 时核对标准替换结果和数量，不把合法跨块字符当非法数据。 |
| EXEC-B07 | 并发边界 | 定 | A/B 独立进程组运行，只让 A 超时或取消 | A 和其后台写盘子孙停止；B 正常完成，内容正确；观察期间 A 的文件不再增长。 |

## 覆盖与剩余决策

不以设计表推断覆盖缺失。本会话已有：005 九类组装验收；006 工具循环 t1–t14 与非字符串 content 单测；chat_with_body 的核心字段覆盖守卫等。上一轮报告全量190通过，但本轮以实际基线为准。

优先盘点新补充：授权持久化失败、未预设变量的 F1 正反例、短错误回显 Key、输出截断后的管道排空、合法 UTF-8 跨读取边界、受控文件竞态。EOF/行尾/权限/链接/EFBIG/响应上限中已有充分覆盖的直接复用，不重复造测试。
