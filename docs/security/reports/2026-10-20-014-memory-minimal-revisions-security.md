# 014 记忆系统四项最小修订安全报告

范围：`feat/014-memory-minimal-revisions` 工作区候选（未提交）。方法：源码面核查＋既有测试引用；无渗透/模糊测试，不调用真实供应商，不触碰真实用户数据。基线＝013 V1 交付态（M9 安全报告之后无生产安全面变更）。

## 逐项核查

| 项 | 面变化 | 核查结论 |
|---|---|---|
| §1 `open_existing` | 新增只开既有库构造（READ_WRITE\|NO_MUTEX，无 CREATE；不建根/不迁移）＋反馈重排（先解析后开库）＋**符号链接根拒绝**（收口轮补齐） | **无新增攻击面**：无新输入路径；用户文本仍仅经既有 `cited_thread_ids` 解析（形状过滤不变）；打开标志收窄能力（拒绝创建）而非放宽；失败静默返回与既有 best-effort 一致。**收口修正**：初版未保留 M1 的符号链接根拒绝（反馈路径旧经 open 被拒、新入口曾接受——RED 用例实证绕过），已最小补齐为入口自带 `symlink_metadata` 检查（Err 拒绝；临时符号链接＋合成库验证目标库零写入）。既有边界保持：库文件 0600/根 0700 由创建路径设置；未新增锁面（reset 交错＝已删 inode 写入，M7 论证沿用） |
| §2 状态展示 | `last_error` 文本进入用户可见输出 | **三层防线**：写入前 api 层 `redact_credential`（凭证）＋phase1 `redact_secrets`（密钥正则）已脱敏；展示侧**再过 `redact_secrets` 一次**并按字符截断 200（顺序＝先脱敏后截断——截断可能切开密钥前缀使正则失效，顺序不可颠倒，有测试断言）；输出有界。残留面＝与既有错误展示同源（供应商错误文本进终端的既有通道，014 未扩大；本地 serr() 错误无控制字符来源）。只读承诺有测试（库文件字节与 mtime 前后不变） |
| §3 `generate_memories` | 配置新布尔字段＋`register_thread` 模式参数 | **无安全面变化**：`deny_unknown_fields` 保持；bool 经 serde 无注入；`memory_mode` 仅进入受控 SQL 参数（?2），值为内部两态字符串；无新命令/环境变量/路径 |
| §4 注释勘误 | 纯注释 | 无行为 |

## 结论

本轮四项修订**未引入可复现的新安全缺陷**：无新增信任输入、无权限/路径/锁边界放宽、错误展示新增脱敏＋截断防线、SQL 全参数化不变。既有安全契约（origin 门、显示边界、响应上限、0600/0700、F1 信任根名单）零触碰。该结论限于本轮 diff 范围，不扩大为全系统渗透通过。
