# 安全攻防测试报告：测试加固轮（016 候选，终端注入边界与指纹规则）

- 日期：2026-10-22
- 范围：本轮（测试加固与局部精简）改动的安全相关验证面——008 A7 终端注入边界的**原始字节证据**与 002 凭证指纹规则；复核 016 既有安全边界未受本轮影响。
- 结论：**未发现生产漏洞**；本轮零生产行为改动（catalog.rs 改动位于 `mod tests`，proc_session.rs 改动为缓存单测，其余为集成/e2e 测试文件，见 §1）。发现并修复了一处**证据强度缺口**（A7 检查器对真实形态 OSC 52 的漏检面），属测试检出力问题，不构成生产漏洞。

## 1. 改动面核实（攻击面判定）

`git diff HEAD -- src/` 核实：本轮仅测试代码变更（7 个测试文件＋catalog.rs/proc_session.rs 的内嵌单测）；无生产逻辑、配置、Schema 或依赖变化。生产过滤算法、连接配置（busy_timeout 5s）、渲染管线均未触碰。

## 2. 终端注入边界（008 A7）

| 检查项 | 方式 | 结果 |
|---|---|---|
| 原始字节证据（进入 VT100 解析器前） | `a7_full_pipeline…`／`a7_byte_level…` 新增 CapturingParser（先记录后转发）＋两层标记检查（引入符直接组合＋CSI/OSC/DCS/SOS/PM/APC 完整序列范围扫描，唯一标记 ATK7QZ） | 12/12 通过；vt100 消费序列、屏幕不可见时原始字节检查仍先行失败（变异 H1：注入 `\x1b]52;c;ATK7QZ…\x07` 于 writer 边界 → RED 于序列扫描层） |
| 误报控制（合法渲染控制不遭拒） | draw 路径正向对照：断言合法 CSI（`\x1b[`）确实存在于原始字节 | 通过——检查只拒标记携带序列，不一刀切拒绝 ESC；渲染器光标/样式/超链接控制正常直通 |
| 载体覆盖 | markdown cell、流式尾区、resume 投影、错误消息、启动审计、工具命令、diff、取消态、运行中会话 cell | 全部零动作（既有断言保留） |
| 真实 PTY 复验 | S33（剪贴板 OSC 52 合法通道）、S46（显式复制）、S57–S62 聚焦家族 | 24/24 通过；渲染/拖选自身不自发产生 OSC 52 |
| 过程发现 | 初版检查器仅判定「引入符＋标记直接相邻」，真实形态 OSC 52（`\x1b]52;c;…`）标记与引入符隔着参数，若发生旁路将漏检 | **已修复**：增补序列范围扫描层；该缺口为测试证据强度问题（生产过滤未变），按"覆盖缺口≠生产漏洞"如实定性 |

## 4. 016 既有安全边界复核（本轮未触碰，回归确认）

句柄归属、64 会话容量拒绝、输入 ≤64 KiB 整次拒绝、MemoryMerge 拒绝 write_stdin、PTY 输出过滤、阻塞写取消（停止后续提交）、进程组终止与退出清理、kill 失败如实上报——由 proc_session（28）、exec_command（18）、session_cli、e2e N2b 等既有用例承载，本轮全部通过（受影响目标见 §5）。

## 6. 剩余风险

- 本轮为测试加固，未引入新攻击面；A7 原始字节证据现覆盖六类序列与真实参数形态，但**未穷尽**全部 VT 序列变体（如 DA1/DEC 私有序列）——按标记机制，任意外来序列携带标记即可检出，不依赖枚举。
