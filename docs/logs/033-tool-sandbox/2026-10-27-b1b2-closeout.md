## 1. 全量唯一失败：根因分析与修复（RED→GREEN）

### 1.1 既有证据的不足与真根因

run1/run2 归因曾记为「git init 300ms 内部预算超时＝既有环境波动」——基线对照与单跑
通过是证据，但**不构成原因分析**（本轮 /goal 明确要求）。真根因（代码层＋复现双证）：

- 该测试**没有** 300ms 预算：`GIT_TIMEOUT_MS` 默认 60 000ms
  （`memory/workspace.rs:49`）；300ms 唯一写入点是
  `git_timeout_kills_process_group_with_descendants` 的 `OverrideGuard::new(…, 300)`
  （:885，测试可测缝：全局 `GIT_TIMEOUT_MS_OVERRIDE` 原子量＋假 git 程序覆盖）。
- **panic 报文中的「300ms 上限」即覆盖值指纹**——该测试的 git 调用被并发运行的
  超时测试注入了 300ms 预算。串行锁 `OVERRIDE_GUARD`（:805，「覆盖缝串行锁」）只有
  **写者**（超时测试，:861）持有；hooks 测试（:953）作为**读者**不加锁，全局态穿透。
  写者加锁≠隔离——读者-写者缺一边。
- run1 失败于 `init`（:962）、run2 失败于 `add .`（:964）：不同 git 子命令落在同一
  覆盖窗口内，与泄漏机理一致。

### 1.2 定向复现（RED，修复前）

两测试 `--test-threads=2`＋受控 CPU 负载（16 个自建忙环＋`taskset -c 0-3`，自建自清
理）：**第 1 轮即复现**，报文与 run2 全量失败逐字同款：

```
add 文件: "git [\"add\", \".\"] 超时（300ms 上限/取消）"

```

日志：`2026-10-27-closeout-memory-flake-red.log`（低负载定向基线也先跑过：两测试
并发不带负载不触发——git 操作快于 300ms，负载是把 git 操作拖过注入预算的共因子）。

### 1.3 修复与 GREEN

修复（测试侧一行级，**断言零变化**）：hooks 测试首行持有同一串行锁：


## 2. B1 元数据错误：链路核查发现 fail-open 并修复

### 2.1 链路核查三问（本轮 /goal 第二节）

1. **前置 exists/canonicalize 是否提前吞掉错误？** 是。`append_unreadable_root_args`
   曾以 `if !unreadable_root.exists()`（sandbox.rs:486 旧态）判「不存在」：
   `Path::exists()` 对**任何** stat 错误（EACCES/ELOOP/ESTALE…）都返回 false，非
   NotFound 错误被静默当 missing 走 no-op（不遮蔽、不拒绝），**根本到不了**审查轮
   补的严格 match——该分支仅 TOCTOU 竞态可达（与审查轮「仅竞态可达」的记录吻合，
   但意味着稳定条件下的承诺是空的）。另两处前置：锚定根 `canonicalize` 错误显式
   传播（:83，不吞）；可写符号链接遍历 `first_writable_symlink_component_in_path`
   对 lstat 错误 `Err(_) => break`（:685-688，上游逐字语义，保留不动）——遍历层
   不拦截的错误必须由 metadata 分类兜底。
2. **NotFound 与其他错误是否真正区分？** 修复后在单次 stat 处三分：NotFound/
   NotADirectory → missing no-op（既有已审差异不变）；其余 → 显式拒绝。
3. **非 NotFound 错误是否在任何工具启动前明确拒绝？** 是：拒绝发生在 argv 组装期
   （三面共用单一入口），先于任何 spawn/bwrap；端到端探针断言执行标记未出现
   （§2.4）。

### 2.2 稳定夹具（临时目录权限＋路径类型，零竞态）

- **ELOOP**：可写根之外的自指符号链接 deny（`metadata` 恒 ELOOP；遍历层对根外
  符号链接放行，不触发可写符号链接分支）。
- **EACCES**：deny 父目录权限 000（遍历层 lstat 失败 break 跳过，不拦截）。
- 控制组：**ENOTDIR**（组件为普通文件）与 NotFound 同类 → missing no-op 语义
  钉住不变。

### 2.3 RED → GREEN

RED（修复前，真实运行）：`deny_target_metadata_error_fails_closed` 与
`deny_target_parent_permission_error_fails_closed` 双双 `unwrap_err()` 拿到 Ok
——argv 照常组装＝fail-open 实锤（20 passed / 2 failed）；
`2026-10-27-closeout-b1-meta-red.log`。GREEN（修复后）：单元 22/22
（`-b1-meta-green.log`）。修复＝删除 `exists()` 判定，改**单次**
`fs::metadata` 三分类（`sandbox.rs` append_unreadable_root_args）：

```rust
let metadata = match std::fs::metadata(unreadable_root) {
    Ok(md) => Some(md),
    Err(e) if matches!(e.kind(), NotFound | NotADirectory) => return Ok(()), // missing no-op（既有差异）
    Err(e) => return Err(format!("受保护文件 {} 状态读取失败（{e}）：无法核实遮蔽目标与硬链接，拒绝启动沙箱工具（不回退普通模式）", …)),
};
```

nlink>1 检查改用同一份 metadata（消除原 exists＋metadata 双重 stat）。**语义微调
（如实声明）**：原「exists=true 后 TOCTOU 删除 → 落 bind → bwrap 显式失败」的
竞态分支被统一的 missing no-op 取代——与稳定缺失语义一致（路径已无凭据可保护；
沙箱内重建属写入面，本就开放），无安全增益损失；B1 的 TOCTOU 边界声明不变。

敏感性：RED（修复前）即「移除拒绝后测试能检出」的直接证明（项目规范 §4 修复前后
对照）；未重复变异（避免无新增信息的检查）。

### 2.4 端到端探针（真实 CLI，拒绝在工具启动前）

`b1_unverifiable_deny_target_refused_before_launch`（sandbox_matrix_probes）：
工作区 `.env` 为自指符号链接 → exec 面真实 CLI：`status=error`＋错误含
"writable symlink"（固定策略下该夹具先命中**可写符号链接 fail-closed 分支**，
同为启动前拒绝）＋执行标记未出现＋夹具未变。三分类分支的单元证据见 §2.2/§2.3；
产品固定策略（deny 恒为工作区 `.env`）下其稳定触达被更早防线拦截，瞬时错误
（EIO/ESTALE）由它兜底。探针文件 10/10 全绿（`-probes-e2e.log`）。

### 3.2 新暴露的失败：`seam_killpg_injection_deadline_not_fake_timeout`（既有例外）

run1/run2 通过、run3 失败；**run1/2/3 之间该路径代码零改动**（候选对
proc_session.rs 的 diff 仅 build_tool_command 沙箱分支 1 个 hunk，与本路径无交集；
closeout 轮也未触碰）——同一份代码不同结果，唯一变量是调度。归因链：

- **机理（代码层）**：killpg 注入失败时监控线程**保留 `kill=Deadline` 请求**在
  `MONITOR_POLL`（10ms）轮询中重试（proc_session.rs:1208-1212「保留请求在后续
  轮询重试」）。测试在解除注入后发显式 terminate；若 deadline 重试 tick 先完成
  终止（此时 killpg 已能成功），事由如实归 Deadline → Timeout——
  `request_kill` 的替换规则（:687-688「显式 terminate 优先」）管辖的是请求共存，
  竞态在于**哪个请求的 killpg 先落地**。进程必然被终止回收，仅事因报告随调度翻转，
  两种结果都符合各自语义；无泄漏、无生命周期误报。
- **定向复现（负载 on/off 对照）**：空闲 4/4 通过（7.27s 恒定）；同款负载
  （16 忙环＋taskset 0-3）第 8/15 轮复现，报文与 run3 逐字同款
  （`2026-10-27-closeout-seam-attribution.log`）。

**例外声明**：列为「未通过的既有失败例外」。影响范围＝该单测在共享负载全量下
偶发（10ms 竞态窗口）；空闲/单跑确定性通过；历史验收（专用容器）全量通过；
