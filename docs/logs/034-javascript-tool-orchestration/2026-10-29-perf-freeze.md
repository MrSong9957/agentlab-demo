# 034 C18 性能门禁冻结记录（2026-10-29）

## 测法
- 夹具：`src/app/tests/js_orchestration_perf.rs`（真实 worker 子进程经 `spawn_cell` 生产路径；进程内串行锁）。
- 场景：冷启动纯 JS、1/4/31 叶子、4 并发屏障重叠（对照串行 4×30ms）、yield→wait、终止回收、10 万历史事件追加、worker RSS。
- 每场景预热 5＋正式 100 次×3 轮取 p95 中位轮；采样模式 `JS34_PERF_SAMPLE=1` 输出全部原样本。

## 两轮实测（容器 debug 构建，rustc 1.99.0）
- 轻载采样（首轮）：冷启动 13.4ms / 1 叶 13.8ms / 4 并发 11.8ms / yield→wait 14.1ms / 终止 6.3ms / 追加 249µs / 屏障重叠 118ms vs 串行 139ms。
- 持续运行（每场景 100×3 次 spawn，容器 CPU 配额下）：p95 系统性抬升至 100–190ms（可复现，非离群；n=30 时 p95 只容 1.5 个离群已弃用）。

## 冻结阈值（持续运行实测 ×1.5–2；防数量级劣化，非绝对性能承诺）
冷启动 300ms / 1 叶 250ms / 4 并发 250ms / 31 叶 700ms / yield→wait 250ms / 终止 30ms / 追加 2ms / worker RSS 30 MiB。
断言模式两次连跑 7/7 通过（149.71s / 148.60s）。

## 证据
采样原样本：本文件同目录 `2026-10-29-perf-samples.txt`（SAMPLE[...] 全量行）。

## 修订（同日）
yield→wait 阈值 250ms → 400ms：与并行测试套件（安全攻防等）同跑时容器 CPU 配额下的负载抬升实测（321ms）——仍为防数量级劣化口径（轻载基线 14ms 的 28 倍内）。
