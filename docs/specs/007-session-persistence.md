## 1. 目标 & I/O

- **目标**：**默认自动保存**——正常聊天无须 `/save`，历史随每轮自动落盘，后续启动 `/resume` 即可恢复继续；`/save` 保留为**可选**命名快照。恢复的工具调用与结果**只作为历史投影进请求，绝不重新执行**。退出前自动排空；进程中断后下次装载以**有界、确定性**的修复继续，且修复不虚构执行结论。
- **命令面（定稿，见 §6-B）**：三条 REPL 斜杠命令，沿用现有 `handle_input` 分派与未知命令帮助（`src/main.rs`，帮助行同步更新）：
  - `/save <名称>`：当前全部历史（允许为空，§6-F）整体快照到 `<user_dir>/sessions/<名称>.jsonl`——目录 0700、文件 0600、**tmp＋rename 原子替换**（保存失败不得损坏旧快照）；**流式逐记录写入 tmp**（不构建全量 String）；名称 `^[A-Za-z0-9._-]{1,64}$` 且**不得以 `auto-` 开头**（保留前缀）；含超行上限记录（§6-E）时拒绝；成功输出单行含条目数。不加锁：并发 `/save` 末者胜（tmp＋rename 原子性，002 并发保存语义）。
  - `/resume [名称]`：**无参＝最近 auto 会话**（文件名字典序最大＝时间序最新——跨时间戳成立；同秒撞名 `-N` 候选间不保证字典序递增，见 §7；无 auto 会话时明确报错）；**有名＝指定文件**（auto 或手动快照均可，名称即 stem）。装载语义（§3"加载与修复"）：`auto-` 文件→**先获取独占锁，再在同一文件描述符上、持锁期间完成装载、尾置处理与 `persisted_upto`/`durable_len` 初始化，后续追加复用同一描述符**（§6-I 锁顺序）；获锁失败→**降级为只读装载**：原文件**零修改**（不补换行、不截断、不追加），提示"该会话正被另一进程编辑"，装载的是获锁失败时点的快照（写者进行中的半行按坏行跳过），本运行新记录写自己的新 auto 文件；手动快照→**只读装载**（快照文件字节不变），本运行新记录写本运行的新 auto 文件——该新文件创建时**以完整上下文开篇**（见下）。成功输出单行含恢复条目数与修复摘要；失败时当前内存历史不变。
  - `/sessions`：列出会话名称＋文件字节数（`readdir`＋`stat`，**不打开任何会话正文**；无会话时输出提示行）。
- **自动会话**：
  - **身份与命名**：每个 REPL 运行一个 auto 会话文件，`auto-<UTC 基本格式时间戳>-<pid>.jsonl`。时间戳与 pid 经**可注入提供者**（测试固定；生产取真实值），不引入 uuid/rand 依赖；pid 仅为新生成文件名去重。**跨进程恢复同一 auto 文件的并发写入由独占锁处理（§6-I）——文件命名不提供互斥。**
  - **创建时机与完整上下文**：本运行**首次需要追加落盘时**创建文件；若此时内存历史非空（典型：恢复手动快照或降级只读后继续聊天），创建时写入 **meta＋当时全部内存历史**，使新 auto 文件以完整上下文开篇（再次恢复它不丢失前缀）；随后游标＝该长度。全新运行＝meta＋首记录（一般情形）。仅执行 `/models`、`/refresh` 等不产生历史记录的命令不创建文件；恢复后未产生新记录即退出也不创建。
  - **追加时机**：每条记录**入史的同时**同步进入待写段并立即尝试提交（`src/turn.rs` 五个入史点：user `:155`、assistant 终文 `:191`、tool_calls `:198`、结果 `:213`/`:225`）——落盘记录集合＝内存历史记录集合，同序；请求失败的轮次其 user 记录同样落盘（与 006 t8 内存语义一致）。
  - **退出排空**：主循环退出（`exit`/Ctrl+C/Eof → `再见!` 路径，`src/main.rs:56-75`）后、进程结束前执行一次补写（§3 补写规则）；成功静默，失败打印明确错误。
- **输入**：名称字符串，约束见上；非法名称明确报错、零文件操作（canonicalize 包含性复核，方式同 `file:` 凭证围栏）。
- **输出/副作用**：仅会话文件读写与单行提示；不联网、不执行命令、不触碰授权记录与鉴权配置（§6-G）；三条命令仅在 REPL 输入边界处理（`handle_input` 轮间运行，非并发）。
- **范围外（明确不做）**：fsync/掉电保护（仅 `write_all` 到页缓存，§6-H）、持久层输出截断（母本有 `policy.rs` 64 KiB 截断先例，本地不采纳——保真优先，超限停用而非截断，见对照表）、通用脱敏（§6-G）、跨会话合并、压缩/摘要、SQLite/索引、临时/不落盘会话模式（母本有 `config.ephemeral` 先例，本地无当前需求，见对照表）、行内时间戳字段（文件名时间戳经注入时钟；记录行内无时间戳）。

## 2. 边界 & 风险

- [ ] **016 进程会话与持久化分离**：会话文件保存的 `running` 结果（含 `session_id`）只是**当时的记录**——恢复装载不重放、不重新连接旧句柄；进程会话管理器随对话切换重置（旧对话进程关闭），旧编号在新运行中失效（`write_stdin` 返回“未知或已失效”）。`/save` 只保存历史，不保存可恢复的控制对象。

- [ ] **凭证边界（§6-G）**：会话文件完整保存用户输入与工具输出，**可能包含秘密**；应用**不主动**将鉴权配置（凭证值、key 引用、.env/授权记录）写入会话文件，也**不新增脱敏功能**——秘密防护依赖 0700/0600 私有目录权限，不得声称文件不含秘密。**母本 rollout 层亦无秘密脱敏**：`policy.rs` 截断是大小控制、`normalize.rs` 是配对修复与不可用消息处理，均非脱敏证据。
- [ ] 名称穿越逃出 sessions 目录——严格名称规则＋`auto-` 前缀保留＋路径包含性多防线。
- [ ] **追加日志损坏**：进程中断或半写至多污染尾部未提交字节；**跳行必须伴随配对修复**（跳过一行可能拆散配对，未修复直接投影会发出非法请求）；修复只合成/丢弃记录文本，**绝不重放工具**。
- [ ] **修复不得虚构执行结论**：结果缺失只意味着**执行结果未知**（副作用可能已发生）——禁止合成"未执行/取消/失败"等确定性结论（§6-A）。
- [ ] **半写与重复**：`write_all` 失败可能已写部分字节——必须有截回与游标纪律保证记录完整、不重复、已提交记录不受损（§3 提交点）；续写前文件尾必须处于行边界（§3 尾置处理），否则新记录与残留半行粘连。
- [ ] **双进程同文件与锁顺序**：两个进程可恢复同一 auto 文件——**一切修改（尾置处理、追加、截回）必须发生在持锁期间**；先装载后取锁会让降级方的尾置处理与写者的进行中写入竞争（截断写者未提交的半行）——锁顺序统一为"先锁、同描述符持锁装载与尾置"（§6-I）；降级路径对原文件零修改；无锁修改路径仅 `/save` 的原子替换。
- [ ] **保存失败保护**：手动快照 tmp＋rename 原子替换（`write_private_file` 原地 truncate 不满足，§3 证据）；自动追加失败＝截回＋游标待写＋补写——**日志写入重试不得变成工具执行重试**。
- [ ] **内存与性能**：不得出现"完整文件字符串＋完整解析历史"双份全量缓存；行缓冲与丢弃缓冲均有界；`/sessions` 不读正文；恢复单遍完成。**不得虚称恢复过程为常量内存**——历史驻留是必要开销；**性能阈值须由同环境实测基线驱动，不得以未经验证的比例锁死实现**（§3 性能契约）。
- [ ] 恢复后重复执行副作用——恢复只装载历史；工具仅在 `run_tool_turn` 收到**新的**模型工具调用时执行（006 现状）。
- [ ] 恢复的超大历史与模型请求上限独立：下次聊天请求按既有 10 MiB 上限报错（006 t8 语义），不影响保存/恢复/列表（§6-E）。

3. 加载校验与修复——母本容差面向其 item 枚举且修复在其 `normalize.rs`（协议不同）；本地按 006 配对契约新写（含未知语义合成、重复 id 判坏、超长行有界跳过）。
4. REPL 接线——`handle_input` 三命令臂＋帮助行＋退出排空调用。
5. 名称/时钟/pid 提供者注入点——测试可控（AGENTS.md §3）；现无此类注入设施。

**序列化表征（定稿；serde tagged 派生承载，测试锁定往返一致）**：首行 meta `{"v":1}`；此后每行一个记录：

```json
{"type":"text","role":"user"|"assistant","content":"…"}
{"type":"tool_calls","tool_calls":[{"id":"…","name":"…","arguments":"<原始 JSON 字符串>"}],"content":"…"|null}
{"type":"tool_result","tool_call_id":"…","content":"…"}
```

与 006 契约一致：`id`/`name`/`arguments` 原样字节保留，`content` 保留字符串或 null；序列化往返逐字一致。**同一装载器通吃 auto 会话与手动快照**。

**自动保存语义（定稿）**：

- **提交点**：一条记录**已提交**＝其完整行（含结尾 `\n`）经一次 `write_all` 写入并返回 Ok；此后才推进游标 `persisted_upto`（内存历史下标）并更新 `durable_len`（已提交文件字节数）。半行（无 `\n`）＝从未提交。
- **写入顺序**：单写者、单 O_APPEND 文件；待写段 `history[persisted_upto..]` 按历史序逐行提交，每行独立 `write_all`＋独立推进——任何记录至多存在一份完整行（顺序、完整、不重复）。
- **半写失败处理**：`write_all` 失败（可能已写部分字节）→ 立即 `set_len(durable_len)` **截回已提交长度**（半写字节从未提交，删除不损已成功记录）；截回成功→游标不动、打印一次错误、待补写；截回失败→**停用自动保存**（文件尾部可能残留半行，由装载修复兜底），此后仅内存。
- **补写规则**：每次新记录触发追加前，先按序提交整个待写段，成功后才提交新记录；退出排空＝同一逻辑执行一次。**补写/重试仅针对日志字节，绝不重新执行任何工具**（工具结果以内存为准）。
- **背压与缓冲**：同步写即自然背压；无用户态队列（内存历史本身即待写缓冲，无重复缓存）。
- **行上限停用**：记录序列化行 >64 MiB（§6-E）→ 不截断、不写半行，停用自动保存并明确报错一次，文件停在最后提交点；手动 `/save` 对含该记录的历史拒绝。仅超长用户输入可实际触发。
- **flush 与掉电**：每记录一次 `write_all`（即达 OS 页缓存），**不 fsync**——进程中断安全（至多半行，截回/修复兜底）；掉电可能丢尾部若干行，不承诺更多（母本同样无 fsync）。
- **锁（第五批统一顺序；第四批补实新建路径）**：auto 文件成为续写目标时——**打开文件（O_RDWR｜O_APPEND）→ 立即 `flock(LOCK_EX|LOCK_NB)` → 获锁后持锁执行：装载（同一 fd）→ 尾置处理 → `persisted_upto`/`durable_len` 初始化 → 此后全部追加与截回复用同一 fd**；锁持有至进程退出或自动保存停用（§6-I）。"成为续写目标"**包括新建**：首次追加落盘时 `create_new` 打开新 auto 文件后立即取锁再写 meta——否则无参 `/resume` 扫到写者进行中的文件会形成双写者并行续写（坑009 补实，2026-10-10 第四批）；新建撞 Busy（该名字被并发恢复者抢先持锁）视同名字冲突换下一候选。获锁失败→降级只读：**不执行尾置处理**、零修改、新记录走自己的新 auto 文件。任何"先装载/先改尾、后取锁"的顺序都属违规（与写者竞争）。

**加载与修复（定稿；流式单遍，先装载进临时 `Vec`，成功才替换内存历史）**：

1. 首行必须可解析为 meta 且 `v==1`——**坏 meta 或未知 `v` 是唯一整文件拒绝情形**；仅含 meta＝合法空会话（§6-F）。
2. **流式逐行**（`BufReader`＋复用行缓冲，单行上限 64 MiB＋1）：完整 JSON 末行无换行可接受（EOF 即行尾）；坏行（非法/截断 JSON）跳过＋计数＋行号；**超长物理行**（读满 64 MiB＋1 未见 `\n`）记为超限坏行后转入**有界丢弃模式**——固定块（64 KiB）读并丢弃至下一个 `\n` 或 EOF，缓冲恒有界，随后从下一行继续解析。
3. **批内/跨批重复 id**：`tool_calls` 行内同一 id 出现两次，或某 id 已在更早的 `tool_calls` 行出现——该行按坏行跳过＋计数；其结果经孤儿规则丢弃。006 记录时已拒绝批内重复，装载侧对文件内容独立再校验，不信任文件。
4. **配对修复**（对临时 `Vec` 单遍处理，不重读不重解析文件；**结果归属按文件顺序分组**）：
   - 每个 `tool_calls` 批（含被拒判坏的批——**被拒绝的批仍是分组边界**）划定一段紧随的结果区；结果只归属其所在段对应的批，**不得归并到前一批**（把被拒批的结果贴给前批悬空调用＝伪造结果）。
   - **每个调用最多保留第一条合法匹配结果**：同 `tool_call_id` 的后续结果（重复）丢弃＋计数。
   - **缺结果的调用合成通用未知错误结果** `{"error":"会话中断，该调用可能已执行，执行结果未知"}`（`tool_call_id` 用原调用 id；**禁止**合成"未执行/取消/失败"等确定性结论——副作用可能已发生，§6-A）。
   - 不属于任何批、跨批交错的结果丢弃＋计数；修复后头部非 `user` 记录丢弃至首个 `user`（§6-F）。全程计数。
5. 装载成功输出单行摘要：`恢复 N 条（跳过 M 行，修复 K 处）`；修复只增删记录文本，**绝不执行任何工具**。
6. **修复与磁盘的一致性**：语义修复**不回写磁盘**——磁盘只含原始事实，修复是装载投影且**确定性**（固定文案＋原 id，无时钟/随机/环境依赖），任意次重新装载得到相同结果；续写只追加新记录，此后再次装载时旧损坏照旧跳过、修复照旧重现——内存与磁盘投影恒一致。合成记录视为"虚拟持久化"：游标初始化＝装载后的历史长度，补写不重写它们。

**续写前尾置处理（定稿；在持锁期间、成为续写目标时执行一次，保证后续追加从行边界开始、不与残留粘连；降级路径不执行本处理）**：

- 文件以 `\n` 结尾→就绪。
- 尾行完整 JSON 但无 `\n`（装载已接受该记录）→ 先追加恰一个 `\n`（保留该已提交记录、物理格式归一）→就绪。
- 尾行坏/截断/超限（装载已跳过）→ 从文件尾向前**块读**定位最后一个 `\n`，`set_len` 截到其后（丢弃从未提交的字节，不触碰已提交记录）→就绪。跨进程崩溃半写遗留即此类。
- 尾置处理完成后才执行首次追加；快照恢复后的新文件创建不受影响（新文件无尾）。

**替换、覆盖与续写规则（定稿，见 §6-C）**：

- `/resume`：当前内存历史为空→直接装载；非空→交互 `y` 确认丢弃（含续写目标切换）；非交互（管道）模式非空一律拒绝。
- `/save`：目标名不存在→写入；已存在→交互 `y` 确认覆盖；非交互模式拒绝覆盖（新名称不受限）。

**性能契约（定稿；阈值由同环境实测基线驱动，不预填实测、不以未经验证比例锁死）**：

- **保存**：自动追加开销 O(新增记录字节)，与全部历史长度无关；手动快照 O(全量)——用户显式触发，如实标注。
- **恢复**：单遍流式（逐行读→解析→入 `Vec`），无"整文件 String＋再全量解析"双份缓存、无二次扫描；**明确不是 O(1)**——历史驻留是必要开销。
- **列表**：`/sessions` O(会话数) `readdir`＋`stat`，不打开正文。
- **内存口径（明确定义，可直接执行）**：
  - **进程基线 B0**：独立 CLI 子进程**恢复一个仅含 meta 的空会话**后的 `VmHWM`（同二进制、同环境、同次测试运行内测量；父测试进程读 `/proc/<pid>/status`）。所有档位测量同法均在独立子进程上取值，杜绝进程内测量串扰。
  - **历史驻留单位开销 u（第六批修正校准）**：无量纲（字节/字节）。采用同形态（大量短记录）、**独立子进程**的 32/64 MiB 两档恢复峰值增量斜率：`u = max((H64 − H32) / 32 MiB, 0)`，其中 `H32`/`H64` 分别为恢复 32/64 MiB 会话各自子进程的 `VmHWM`。两档同形态、共享同一 B0 与固定开销，**做差将其全部消去**，得到纯斜率；**128 MiB 仅作为验收余量出现在断言式，绝不在校准中扣除**——从校准值扣除常数会把余量误差混入斜率、系统性扭曲 u。`max(·,0)` 消除噪声负值；u 同时记录为观测数据。
  - **理想线性模型核对（防误判）**：设真实模型 `H(N) = B0 ＋ s×N ＋ C`（s＝真实斜率、C＝真实固定开销），则两档差 `(H64 − H32)/32 MiB = s` **精确还原斜率**（B0 与 C 完全消去）；断言式 `H(256) − B0 ≤ u×256 ＋ 128 MiB` 在线性模型下等价于 `C ≤ 128 MiB`——即本式验证的正是"内存随文件大小线性增长，且固定截距不超过余量"，良好线性实现不会误判失败。超线性增长（无界复制等）会使 256 档断言失败；全域性斜率膨胀（意外双缓冲）不触发本断言，但体现为异常偏大的 u 观测值——双缓冲禁令由"流式单遍、无双份全量缓存"的实现约束与结构验收保障，不以本公式代劳。
  - **固定常数 128 MiB**（仅验收余量，不参与校准；分解：行缓冲 ≤64 MiB＋1、解析与测量噪声 32、安全余量 32；丢弃模式为固定 64 KiB 块）。
  - **形态一致性**：校准档（32/64）与断言档（256）使用**同一数据形态**（大量短记录）；少量长记录形态（行缓冲主导、已含于余量）单独跑行为断言，不参与 u 推算。
- **阈值形式（基线驱动）**：断言档 N＝256 MiB（大量短记录形态）：`VmHWM(N) − B0 ≤ u×N ＋ 128 MiB`——B0（空会话子进程）与 u（32/64 MiB 两档增量斜率）在同一次测试运行、同一环境内先测；128 MiB 仅为验收余量，不参与校准；1 MiB 档仅行为验证。环境漂移自动跟随基线。
- **数据档位**：1（行为验证）/ 32＋64（u 两档校准）/ 256 MiB（断言），校准档与断言档均为大量短记录（≤4 KiB/条）形态；256 MiB 另覆盖**少量长记录**（≥4 MiB/条）形态做行为断言（不参与 u）。
- **已有历史替换的内存口径（单独验收，第六批修正）**：`/resume` 替换非空内存历史时，替换窗口内新旧历史同时驻留（确认丢弃前旧历史仍在），属预期峰值：断言 `VmHWM(替换窗口) ≤ B0 ＋ u×(N_old ＋ N_new) ＋ 128 MiB`。**不设"释放旧历史后 RSS 必须回落"的硬断言**——分配器可能缓存已释放内存，RSS 不回落≠泄漏；改为验证两点：①**行为性**——替换后内存历史与后续请求**只含新会话**（首轮请求投影逐条＝新会话，无旧会话残留）；②**有界性**——反复替换同规模会话（如连续 5 次替换 32 MiB 会话），各次窗口峰值均满足同一上式、不随替换次数持续累积（无逐次抬升趋势）。`VmRSS` 全程采样仅作**观测数据**记录，不设阈值。
- **测量方法（测试内固定）**：耗时 `std::time::Instant`；内存 `/proc/<pid>/status` `VmHWM`（CLI 子进程存活期采样＋退出前终值；tests 已有读 `/proc` 先例）；写入字节＝前后文件大小差；每项 3 次取中位数。
- **目标阈值**：① 增量性——同尺寸记录（≤8 KiB）在 1 MiB 与 256 MiB 会话上的单条追加耗时比 ≤2×；② 恢复吞吐跨档稳定——256 档吞吐 ≥ 同次运行 1 MiB 档校准吞吐 × 0.5（流式不应随规模劣化过半；不设绝对 MiB/s）；③ 峰值内存满足上式；④ `/sessions`——256 MiB 会话在场、百文件 ≤50 ms（目录元数据操作量级依据）且**将某会话正文 chmod 000 后列表仍正常**（行为性证明不读正文）；⑤ 写入字节——自动追加后文件增长恰＝该行字节数；手动快照写入字节＝全量。

## 4. 坑记录 → 实测后同步到个人知识库

- 坑001：恢复≠重放——历史里的工具调用是"已发生事实"，装载后唯一的执行触发是模型**新**返回的 tool_calls。
- 坑002：跳行与修复必须成对——跳过一行可能恰好拆散配对；只跳不修会把非法请求发给服务端（母本 `load_rollout_items` 容差与 `normalize.rs` 修复并存先例）。
- 坑003：会话文件完整保留用户输入与工具输出，是秘密载体——权限必须在写入口强制；应用只承诺"不主动保存鉴权配置、不新增脱敏"；母本的截断（policy.rs）与配对修复（normalize.rs）都**不是**脱敏证据。
- 坑004：保存失败保护旧快照＝原子替换问题——原地 truncate 半写即毁旧文件（`write_private_file` 教训）；"加载时拒绝坏文件"不能替代旧快照保护。
- 坑005：日志写重试≠工具重试——游标只补写字节，工具结果以内存为准。
- 坑006：flush≠fsync——掉电丢尾部是预期行为，不承诺代码没有的保护。
- 坑007：性能与保真冲突时保真优先——超行上限停用而非截断；流式实现不能用"拒绝大文件"替代。
- 坑008：半写的危险性在于"部分字节已落盘"——没有 `durable_len` 截回纪律，补写会把同一记录写两遍或与残留粘连成坏行；提交点必须定义在"含 `\n` 的整行写入成功"。
- 坑009：文件命名不提供互斥——两个进程恢复同一文件与命名无关；锁必须附着在文件本身且随进程消亡自动释放（flock），锁文件方案要额外处理陈旧锁。
- 坑010：结果缺失≠未执行——进程可能在副作用发生后、结果入史前中断；修复文案写"未执行"就是在编造事实，只能表达"结果未知"。
- 坑011：快照恢复后若新 auto 文件只存新记录，再次恢复就丢上下文——新 auto 文件必须以完整上下文开篇（创建时写入当时全部内存历史）。
- 坑012：锁顺序——先装载后取锁的降级方尾置处理会与活动写者竞争（截掉写者未提交的半行）；一切文件修改必须在持锁期间、同一描述符上进行。
- 坑013：结果归属按文件顺序分组——把被拒批的紧随结果贴给前批悬空调用等于伪造执行结果；同 id 首条之后的结果是损坏痕迹，保留首条、丢弃其余。
- 坑014：生成与排序耦合的文件名时，前缀拼接错误会静默改变排序域——`auto-` 命名空间内"字典序＝时间序"的等价依赖所有文件同处 `auto-<数字>` 域；撞名候选对已含前缀的 base 再拼一层前缀产生 `auto-auto-*`，其第 6 字节 `'a'>'2'` 使之整体压过数字域且与时间戳无关，无参恢复（latest_auto）据此持续选中较旧会话。教训：任何改变文件名形态的生成逻辑（哪怕是防御性重试）都必须对照排序消费者的等价性断言（本例：`latest_auto` 注释"字典序即时间序"未被新形态检验）；普通 `-N` 后缀不保证字典序递增（`-10`<`-9`），同秒顺序不做承诺（§7）。

## 5. 预测 → 实测

全部自动化：mock HTTP＋独立 `TCHAT_USER_DIR` 临时目录＋注入时钟/名称提供者＋管道/PTY 驱动真实 CLI（`CARGO_BIN_EXE`，同 e2e/tool_loop 模式）；性能用例按 §3 固定方法与基线口径。

同名恢复契约（2026-10-10 合并前收敛，已验证；第四批更新实现方式）：当前写者恢复自己持锁的 auto-X 并确认后，X 仍是续写目标——后续记录追加到 X、不因自持锁另建 auto 文件；历史替换、独占保持、记录不重复、恢复零重放。不新增"自持锁即降级"的规格例外。实测（`tests/session.rs same_name_resume_keeps_original_as_append_target`）：原实现自持锁误降级（RED 复现）→ 修复 → GREEN。第三批曾以"先释放旧描述符再走正常打开即锁＋自释放后微重试"实现；第四批改为**复用已持锁描述符直接重装载**（rewind→装载→尾置→游标重置，锁全程不离开写者）——消除释放与重抢之间的竞争窗口，微重试随之删除。受控竞争验证（`same_name_resume_survives_concurrent_lock_poacher`）：高频抢锁者全程得手 0 次、200 轮同名恢复无一降级；变异（改回释放再重抢）第 9 轮即被挤成降级。新建 auto 文件第四批起同样打开即锁（上表 §3 锁序），任何 Writing 态都是持锁态，同名场景不再限于二次恢复。

实现记录（2026-10-10）：测试落点 `tests/session.rs`（装载/修复/写入器/并发快照，28 项）、`tests/session_cli.rs`（CLI E2E，15 项）、`tests/session_perf.rs`（性能档位，1 项综合）与 `src/session.rs` 内嵌单测（/dev/full 截回失败真实验证）；证据与坑记录见 `logs/2026-10-10-007-implementation.md`。审查整改：`.env` 注入 `TCHAT_SESSION_TS/PID` 已入 F1 跳过名单；/resume 确认丢弃前先排空旧待写段（失败中止恢复）。收尾补验（2026-10-10 第二批）：并发 `/save` 末者胜实测（`concurrent_save_last_complete_snapshot_wins` 双线程 barrier×10 轮＋e17 双进程，最终文件字节精确等于某一方完整快照、无混写、无 tmp 残留、受控顺序最后成功替换者生效）；性能原始逐次采样与公式核对行随 `perf-raw/perf-formula` 输出。合并前整改（2026-10-10 第三批）：八项高风险补测、同名恢复与授权写入完整性两项门禁（RED→GREEN＋变异）；新增 `new_auto_writer_lock_excludes_second_writer`（新建路径写者互斥）与 `same_name_resume_survives_concurrent_lock_poacher`（同名恢复受控竞争）。偶发锁失败根因重判与性能口径修正（2026-10-10 第四批）：详见实施日志第四批——"WSL2 close 释放滞后"与 overlayfs 两假说经 10 万次受控实验否定，真根因为测试进程并发 spawn 的 fork→exec 窗口短暂持有 fd 副本；追加耗时比改为库级纯追加路径 100 条累计计时（移除实现层 10ms 噪声底，规格阈值 2× 不变），实测比 1.089。

| I 独占写入与冲突（第四批新增，第五批统一顺序，第四批补实新建路径） | auto 文件成为续写目标时**先取锁**：打开（O_RDWR｜O_APPEND）→ `flock(LOCK_EX|LOCK_NB)` → 获锁后**在同一 fd 上持锁完成装载、尾置处理、`persisted_upto`/`durable_len` 初始化与后续全部追加/截回**；锁持有至进程退出或自动保存停用。**"成为续写目标"包括新建**（第四批补实：`create_new` 打开后立即取锁再写 meta；新建撞 Busy 视同名字冲突换下一候选——否则无参 `/resume` 可与新建写者形成双写者）。同名恢复＝**复用已持锁描述符直接重装载**（不释放再重抢，锁不离开写者）。冲突（WouldBlock）→**降级**：只读装载（**原文件零修改**——不补换行、不截断、不追加；装载为获锁失败时点快照，写者进行中半行按坏行跳过）＋提示"正被另一进程编辑"＋新记录写本运行新 auto 文件（完整上下文开篇）。`/save` 原子替换不加锁（末者胜，002 语义）。**撤销第三批"pid 命名已排除共同写入"判断**——两进程可恢复同一文件，互斥只能来自锁 | 母本 `writer_lock.rs` 文件锁先例（锁文件＋协调锁），本地以 flock 简化并保留"进程消亡自动释放"；**锁顺序必须先于一切文件修改**——先装载后取锁的降级方尾置处理会与活动写者竞争（截断其未提交半行，第五批坑012）；降级保可用性：被占会话仍可读、新对话不丢失；同名恢复的"释放再重抢"窗口会让第三方插入获锁（第四批受控竞争证实），复用描述符从结构上排除 |
| J 性能阈值方法（第四批新增，第五批可执行化，第六批两档斜率校准） | 阈值＝同环境同次运行实测基线驱动：**B0＝独立 CLI 子进程恢复空会话（仅 meta）的 `VmHWM`**；**u＝同形态独立子进程 32/64 MiB 两档增量斜率 `max((H64−H32)/32 MiB, 0)`，无量纲字节/字节**——两档做差消去 B0 与全部固定开销，得纯斜率；**128 MiB 仅作验收余量出现于断言式、不从校准值扣除**；256 档（同形态）断言 `VmHWM(N)−B0 ≤ u×N＋128 MiB`（余量分解：行缓冲 64＋解析噪声 32＋安全余量 32）。**已有历史替换单独验收**：窗口峰值 `≤ B0＋u×(N_old＋N_new)＋128 MiB`（新旧同驻计入）＋行为性（替换后历史与请求只含新会话）＋有界性（反复同规模替换峰值不逐次累积）；**不设 RSS 回落硬断言**（分配器可能缓存已释放内存，RSS 仅观测）；吞吐取跨档相对值（256 档 ≥1 MiB 档 ×0.5）；不设未经验证的绝对比例或绝对 MiB/s | **理想线性模型核对**：`H(N)=B0＋s×N＋C` 下两档差精确还原 s（B0/C 消去），断言式等价于 `C ≤ 128 MiB`——线性实现不误判；超线性增长在大档暴露；全域斜率膨胀不触发断言但体现为异常偏大的 u 观测值（双缓冲禁令由流式单遍实现约束保障）。校准与断言同数据形态；1 MiB 档常数主导仅行为验证；替换窗口新旧同驻是确认语义必要峰值，显式计入而非虚称 O(1) |

实现 /goal 下达前如需改判任一项，更新本节并同步 §1–§5 对应句即可。

## 7. 缺陷修复契约：撞名候选的重复 auto- 前缀（2026-10-11 审计补证；已修复，2026-10-11 批准交付）

> 本节由 2026-10-11 完成度审计补证轮确立契约，同日修复实现轮（分支 fix/007-latest-auto-session，基于 6231a78，未提交）完成实现与验证。审计夹具位于审计会话隔离临时目录（不属仓库）；行为复现与预测-验证表为本节事实来源。

### 复现条件与根因

- **复现条件**：`create_auto_file` 首选名 `auto-<ts>-<pid>.jsonl` 已存在（AlreadyExists——注入同 TS/PID、降级者新文件与既有 auto 文件同名等），或新建后 `flock` 被并发恢复者抢占（Busy——受控高频竞争下实测 1 次尝试即命中，窗口为 `create_new` 与 `flock` 之间的微秒级间隙），两者均触发候选名重试。
- **根因**：`src/session.rs` `create_auto_file` 候选名拼接对已含 `auto-` 前缀的 base 再拼一层前缀，产生 **`auto-auto-<ts>-<pid>-1.jsonl`**；该形态第 6 字节 `'a'(0x61) > '2'(0x32)`，字典序压过一切 `auto-<数字>` 开头的文件且与时间戳无关——`latest_auto`（字典序最大）据此选中时间较旧的撞名文件，破坏 §1"字典序最大＝时间序最新"等价。
- **实测复现（2026-10-11，真实 CLI＋隔离 TCHAT_USER_DIR）**：持锁者占 `auto-20260101T000000-55.jsonl` → 同 TS/PID 降级者真实生成 `auto-auto-20260101T000000-55-1.jsonl` → 更晚正常会话 `auto-20260102T000000-66.jsonl` 在场 → 无参 `/resume` 恢复 3 条＝撞名文件内容（种子＋降级者新消息＋回复），时间更新的会话（2 条）被跳过。

### 修复契约（最小范围）

- **预期行为**：候选名保持**单一 `auto-` 前缀**（`auto-<ts>-<pid>-<N>.jsonl`）；撞名文件与时间更晚的正常 auto 文件共存时，无参 `/resume` 必须恢复更晚文件。
- **最小修改范围**：仅候选名拼接一处＋新增回归测试；**保留现有撞名重试方式**（`create_new`＋打开即锁＋Busy 换候选＋50 次上限）。
- **已知限制（如实记录，不新增机制）**：普通 `-N` 后缀**不保证字典序递增**——`-1`…`-9` 字典序递增，`-10` 起小于 `-9`（`'9'>'1'`）；同秒多次撞名的候选间选择顺序不保证与创建顺序一致。本轮不新增同秒创建顺序机制（如时间戳推进），该限制仅影响同秒同 pid 多次撞名的极端场景。
- **0 字节残留（关联事实，本轮不修改删除逻辑）**：Busy 分支换候选时留下的 0 字节首选名文件不自愈——残留为字典序最大时无参 `/resume` 报错一次（符合 §3 meta 门契约：错误明确、内存历史不受污染、后续新会话保存正常）；显式 `/resume` 该 stem 持续报错；`/sessions` 列表多一项。2026-10-10 实施日志中"残留 stem 字典序更小、latest_auto 必得真文件、无参不受影响"的推断**作废**，以本节实测为准。
