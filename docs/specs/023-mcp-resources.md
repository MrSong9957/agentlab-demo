## 3. 实施顺序与验证

### 3.1 固化规格与验收清单

- 沿用用户私有 `mcp.json` 的服务器启用授权。
- `enabled_tools`／`disabled_tools` 仅约束外部工具，资源按服务器能力独立判断。
- 普通用户轮开放资源工具，内部记忆轮隔离。
- 明确资源接口与 022 工具接口的兼容关系；在实现前固定汇总的总字节预算、整体截止时间及部分失败返回形态。
- 实施前记录现有 MCP 测试状态，区分基线问题与本次新增问题。

**验证：** 每项行为都有对应验收项，权限、调用、结果及失败语义有明确依据。

### 3.2 先补回归测试，再扩展连接与快照

主要修改落点：[connection.rs](../../src/app/src/mcp/connection.rs)、[manager.rs](../../src/app/src/mcp/manager.rs)。

- 支持仅资源服务器，分别记录工具和资源能力、可用状态。
- 每轮冻结原始服务器 ID、能力、连接句柄及敏感值集合，声明与执行共用快照。
- 资源目录在实际调用时获取；准备阶段不预读目录或正文，不引入固定等待。

**验证：** 覆盖仅工具、仅资源、两者兼有、两者皆无，以及零工具名单等组合；先证明资源专用服务器回归用例在修复前失败，再验证修复后通过。

### 3.3 实现列举、分页与读取

- 指定服务器时返回一页并保留 `nextCursor`。
- 省略服务器时汇总有资源能力的服务器，完整分页并按服务器 ID 稳定排序。
- `cursor` 必须与 `server` 同时使用；游标原样传递，包括空字符串。
- 汇总遇到单台失败时保留成功结果，并明确返回脱敏错误。
- 读取按快照中的 `(server, uri)` 路由，支持模板展开后的 URI。
- 分页沿用 100 页、2048 项、64 KiB 游标及重复游标检测，并约束汇总的总字节和总时限。

**验证：** 两种传输均检查真实请求、游标、路由和调用次数；覆盖分页环、部分失败、取消与超时。

### 3.4 接通结果与安全边界

- JSON 结果保留服务器归属、`contents`、`uri`、`mimeType`、文本／base64 blob 和 SDK 支持的元数据。
- 资源 URI 交给指定服务器解释，宿主不自行打开路径或下载地址。
- 沿用 022 的凭证污染整份拒绝，覆盖元数据、正文、解码后的 blob 和错误；检查先于展示与保存。
- 接收继续遵守 8 MiB 限额，模型请求遵守 10 MiB 限额，超限明确失败。

**验证：** 覆盖多段内容、二进制、污染、畸形响应、超限和终端控制字符；被拒绝内容不得进入模型请求、会话或日志。

### 5.1 实施前固化的边界

以下规则已于 2026-10-24 固化（M0），其中 R1–R3 经用户裁决定稿（见 §5.1.4），不能由测试或实现反推需求。

| 边界 | 固化规则与理由 |
|---|---|
| 汇总输出预算 | 最终序列化 JSON 总计不超过 8 MiB，包含服务器归属、元数据和错误。与单条传输消息 8 MiB、完整模型请求 10 MiB 分别检查；超限返回明确错误，不静默截断目录或删除历史 |
| 汇总整体时限 | 单台服务器沿用其 `tool_timeout_sec`；汇总总时限取本轮参与服务器该值的最大值。与逐台时限求和相比，总等待不会随服务器数线性增长。首版按服务器 ID 串行遍历，整个操作到限即失败 |
| 单台分页预算 | 定向列举只请求一页，单页最多 2048 项；汇总时每台最多 100 页、累计 2048 项，游标最多 64 KiB。空字符串为有效游标，重复游标拒绝 |
| 部分失败 | 汇总保留完整成功服务器的数据，附 `errors:[{"server":"服务器 ID","error":"脱敏原因"}]`；无错误时省略该字段。某台分页失败时丢弃该台已收集的半份目录；全局取消、整体时限或总字节预算触发时整次失败 |
| 能力和连接状态 | `tools` 与 `resources` 独立判断；仅资源服务器不发 `tools/list`。某接口发现失败时不发布该接口的半份数据，连接仍健康时保留另一项能力；传输断开或损坏则两者均不可用，仅显式 reload 重连 |
| 声明与计数 | 本轮存在可用资源服务器时，三个固定工具各声明一次，与动态 MCP 工具共用同一快照。审计 `len`／`is_empty` 的现有调用方，避免用“零动态工具”等同“无资源能力”，实际工具总量以组装后的声明为准 |
| 敏感数据 | 资源能力独立持有本次连接准备时固定的敏感值集合，不依赖某条工具目录项。逐字段检查解码后的文本及 blob 原始字节，再检查投影结果；不能仅扫描 JSON 序列化字符串而漏掉转义值 |

#### 5.1.1 预算契约（M0 固化，2026-10-24）

预算分三层，按「单条传输消息 → 工具结果 JSON → 完整模型请求」依次检查，互相独立、逐层不豁免：

| 层 | 数值与单位 | 计数范围 | 达到边界的行为 |
|---|---|---|---|
| 单条传输消息 | 8 MiB（8,388,608 字节） | stdio 单条 JSON 消息、HTTP JSON 响应体或单个 SSE 事件的原始字节；在完整分配／反序列化前判定 | 沿用 022：关闭该连接并回报错误，不截断成合法成功 |
| 工具结果 JSON | 8 MiB（UTF-8 字节） | 该次工具调用最终序列化 JSON：含服务器归属字段、全部目录项／读取 contents、SDK 支持的元数据和 `errors` 数组；不含传输层帧／头开销 | 返回标准客户端错误（`isError:true`），整次失败；已收集数据不发布、不入史；不静默截断、不删历史。连接保留（未违反传输边界） |
| 完整模型请求 | 10 MiB | 006 既有完整序列化请求 | 沿用 006：明确失败，不删历史 |

- 8 MiB 结果预算统一覆盖资源列举、模板列举、资源读取三个工具的定向与汇总路径（2026-10-24 用户确认 R2=B）。
- 单台分页预算超限（>100 页、该台累计 >2048 项、游标 >64 KiB、重复游标）属于**该台失败**：丢弃该台已收集的半份目录、记入 `errors`、继续其余台；不是整次失败。
- 定向列举返回单页：单页项数 >2048 判该次容量超限失败，不截断。
- 页数、项数、游标大小按服务器独立计数；跨台总量由 8 MiB 结果预算约束，不另设全局项数或页数上限（不新增配置项）。

#### 5.1.2 计时与取消契约（M0 固化，2026-10-24）

| 模式 | 计时范围 | 时限 | 到限行为 |
|---|---|---|---|
| 定向调用（带 `server` 的两个列举及 `read`） | 自单次请求发出至完成 | 该台 `tool_timeout_sec`（缺省 300，正整数秒，022 配置校验规则） | 尽力取消并返回超时／远端状态未知错误，按普通工具失败继续循环；不自动重试 |
| 汇总（省略 `server`） | 自进入工具处理器起，至汇总完成或整次失败止的单一整体窗口 | `max(本轮参与且具备资源能力服务器的 tool_timeout_sec)`；按服务器 ID 升序串行遍历，页请求不再各自独立计时；进度通知不延长窗口 | 整次失败：返回标准客户端错误，已收集数据不发布 |

- 单次请求与整体窗口的关系：汇总中每台每页请求都运行在整体窗口内，各服务器和分页请求不重新获得计时窗口，任何单台耗时最终由整体窗口截断；定向模式不受其他服务器配置影响（2026-10-24 用户确认 R1=A）。
- 取消的结束条件：
  - 发送前取消＝该工具零外部请求（服务器侧零 `resources/*` 调用），返回取消失败。
  - 汇总进行中取消：立即停止本地等待，对在途请求尽力发送 MCP 取消通知（通知 I/O 不阻塞本轮结束，发送任务最多存活 1 秒，022 语义）；已收集数据不发布，整次失败；补齐同批剩余工具结果，保存后结束本轮，不继续请求模型。
  - 迟到结果按请求关联丢弃：不追加第二条 tool 结果、不进入下一模型请求、不污染下一轮。
  - 取消保留管理器与健康连接；已断开连接仅显式 `reload` 重连。
  - 取消优先于部分失败：即使已有成功台数据，取消后一律整次失败，不发布半份成功集合。

#### 5.1.3 分页、部分失败、容量与断连的错误返回（M0 固化，2026-10-24）

- 游标契约：`cursor` 仅与 `server` 同时使用，省略 `server` 而携带 `cursor` 属参数错误，在任何网络发送前失败；游标是 opaque 字符串，空字符串原样传回、不作结束；不 trim、不归一化（不采用 Codex 的 trim 行为）。
- 多服务器部分失败（仅汇总模式）：单台失败（连接／认证错误、方法不支持、该台分页预算超限、响应畸形）时，保留其余台完整数据并附 `errors:[{"server":"<服务器 ID>","error":"<脱敏原因>"}]`；无错误时省略 `errors` 字段；失败台不输出半份目录。全部参与台都发生可归属单台的失败时，返回空集合和完整、脱敏的 `errors`（2026-10-24 用户确认 R3=A）；该规则不覆盖取消、整体超时或工具结果预算超限，这些仍按整次失败处理。错误文案沿用 022 §2.1 脱敏：不回显凭证、认证头或指纹。
- 容量超限（8 MiB 结果预算）、整体时限、全局取消同属**整次失败**，与单台部分失败分层：台级软边界保留其余台数据，全局硬边界整次失败。
- 断连：确认断开的连接标记不可用（工具与资源能力同时不可用），不改绑其他连接、不从历史名反推身份；本次调用该台计入 `errors`（汇总）或返回不可用错误（定向）；仅显式 `reload` 重连。
- 不重放：任何失败——含超时、取消、断连、401／404 会话失效——不自动重试、不隐式多发；HTTP 关闭 POST 重放（022）；后续动作由模型或用户显式发起。

| R3 | 汇总中全部参与台都失败 | **A：返回空集合＋全部 `errors`**（模型可读各台原因）；取消、整体超时、结果预算超限仍整次失败，取消优先于部分失败 | 保持「台级失败是数据、不是协议错误」的一致性；模型可见原因后可自行改用定向调用或提示用户 |

R1–R3 已定稿，M1 起按上述结论实施，不再存在待裁决项。
