## 1. 要做什么，有哪些要求

### 1.1 目标与接入路线

让模型用 `tool_search` 在宿主已加载的 MCP 动态工具目录中搜索需要的工具，获得完整调用定义，再在后续模型请求中调用。减少当前请求中尚未用到的工具定义；宿主仍持有完整可搜索目录和原始身份映射。

本项统一采用**宿主本地 BM25 搜索＋普通函数工具＋后续请求追加定义**，复用 024 的五协议普通函数适配：`openai-chat`、`openai-responses`、`anthropic-messages`、`google-generate-content`、`google-interactions`。这是一条明确的本项目适配路线，不实现 Responses 的原生 `tool_search_call/tool_search_output`，也不实现其他提供方的托管搜索、延迟字段或服务端目录。

只延迟 022 发布的 MCP 动态工具；内置工具和按能力声明的 023 三个资源工具保持直接可用。内部记忆轮、MCP prompts、插件安装、JavaScript 编排和跨语种语义检索不在范围内。工具搜索不代替 MCP 初始化和 `tools/list`，也不用资源接口发现工具。

### 1.2 启用、来源概览与默认兼容

- 复用模型目录的 `experimental_supported_tools`；只有精确包含 `"tool_search"` 才启用，不按模型名或协议名猜测。缺省、空数组或其他名称均保留原来的全量声明路径，不新增独立配置文件或每服务器开关。
- 开关在用户轮开始时冻结，与当前 MCP 快照共同决定声明和执行；运行中的输入接续不重置已加载状态。`/refresh`、模型切换及 `/mcp reload` 的新状态只在后续用户轮生效。
- 开启且有经过筛选的安全动态工具时，首次请求声明：原有常驻工具＋`tool_search`，不发送动态工具的逐项名称、说明或 Schema。宿主在搜索工具的描述中附来源概览，仅列当前可搜索 `server_id` 及工具数量，按服务器 ID 排序；不伪造尚无来源字段的服务说明。 来源 ID 按 JSON 字符串编码呈现为明确的数据块，不把其中换行、标记或文字解释为宿主指令。
- 没有可搜索动态工具时不声明 `tool_search`；仅有资源能力的服务器仍可提供原有资源工具。模型伪造搜索调用必须失败，不能触发连接、发现或外部调用。
- 关闭搜索时，原有工具顺序、Schema、权限和超限处理不变；未新增搜索开关的配置无需迁移。内部 `MemoryMerge`／提炼轮既不声明也不执行搜索或 MCP 动态工具。

模型配置示例（放在已有模型记录内，保留原记录其他字段）：

```json
{"experimental_supported_tools": ["tool_search"]}
```

这表示选择本项目的本地搜索适配，不表示模型或提供方支持任何原生托管搜索协议。

### 1.3 输入、搜索和结果

工具名固定 `tool_search`，使用现有普通 JSON 函数接口：

| 字段 | 要求 |
|---|---|
| `query` | 必填字符串；按 UTF-8 原始字节计最多 4096 字节，去掉两端空白后必须非空。去空白后用于查询，但调用参数历史原样保留 |
| `limit` | 可选整数，缺省 8；范围 1–32；null、浮点数、布尔值、字符串及范围外值均拒绝 |
| 其他字段 | 一律拒绝；不得携带服务器连接、认证或权限参数 |

例如：`{"query":"send email","limit":2}`。参数错误返回失败，不改变加载集合，也不发外部请求。

搜索规则：

1. 只搜索当前用户轮的有效快照。工具必须已通过 022 的去重、Schema 校验、允许/禁用名单和凭证污染检查；新增来源与检索文本也须通过相应敏感值检查后才能进入概览、索引和结果。
2. 每个检索条目对应一个既有模型工具名及其 `(server_id, raw_tool)`。检索文本按固定顺序拼接模型名、原始工具名、服务器 ID、工具说明及排序后的顶层参数字段名；不加入连接地址、认证信息、宿主环境、服务器 instructions 或资源正文。不改写执行身份和原始路由。
3. 复用固定 Codex 提交采用的 `bm25 2.3.2` 与 English 默认 tokenizer、按语料拟合的 Embedder/Scorer；锁定依赖，不启用自动语言检测或并行拟合。模型可按目录用途词搜索，无须先知道准确名称；相同中文关键词须有固定夹具覆盖，不承诺翻译、跨语种同义词或中文长句语义理解。
4. 按实际 BM25 分数降序，只返回正分命中；同分按 `(server_id, raw_tool)` 字节序升序。无有效词或无命中，返回成功的空数组，不兜底加载全目录。输出不暴露分数，避免把排序内部数值变成接口。
5. 每次最多返回 `limit` 项，包括此前已经命中的工具。重复命中可以再次返回定义，但加载集合按模型名去重，不复制工具声明；搜索中不调用模型、网络或服务器业务接口。

返回固定三字段 `ok / tools / error`。`tools` 使用宿主当前采用的规范化普通函数定义，包含实际模型名、可选原说明及完整参数 Schema，不是只有名称的提示，也不包含工具实现代码。各协议通过 024 在下一次出站请求中转换为自己的普通函数格式。

成功结果示例（名称仅为示例，实际必须取当前快照映射）：

```json
{
  "ok": true,
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "mcp__mail__send_email",
        "description": "Send email to the selected recipient.",
        "parameters": {
          "type": "object",
          "properties": {"recipient": {"type": "string"}},
          "required": ["recipient"]
        }
      }
    }
  ],
  "error": null
}
```

无命中为 `{"ok":true,"tools":[],"error":null}`；参数、容量、取消或不可用等失败为 `{"ok":false,"tools":[],"error":"具体原因"}`。失败不得携带半份定义或部分结果。错误不回显凭证或把不可信说明当作指令。 该三字段契约适用于普通用户轮；内部记忆轮中的伪造搜索仍沿用已有未知工具通用错误契约，不能因此获得搜索入口。

### 1.4 加载时机与执行权限

用以下顺序定义一轮状态，避免把宿主目录中的全部条目误当成当前可调用工具：

1. 用户轮开始：冻结 MCP 快照，已加载动态工具集合为空；建立一次本地索引，或在第一次搜索前惰性建立，同轮只拟合一次。初始化和目录发现仍按 022 执行。
2. 每次模型请求发送前：声明常驻工具、搜索工具及已成功加载的动态工具；动态定义按快照中的原始身份顺序排列。为这次请求固定一份「已声明且可执行」集合；只有它能授权该响应里的动态调用。
3. 执行 `tool_search`：计算结果后，检查本次结果预算和累计加载后的工具数量，再返回完整结果、加入后续请求的加载集合。一次搜索要么完整成功，要么全部失败；此前成功搜索的集合不回滚。
4. 同一 assistant 批次中的权限仍以产生该响应的请求为准。批中先搜索、后猜测调用刚命中的工具，后者仍失败且零 `tools/call`；本来已声明的工具仍可在同批执行。不得因循环顺序让未见定义的调用获得权限。
5. 多次搜索可在一批出现，按现有串行顺序执行并累积下一次请求的集合；单次返回的定义和实际加入的定义必须完全相符。伪造名称、其他轮名称、未命中或被排除工具一律不调用服务器。
6. 批次仍先完整做 006/024 协议结构校验，再执行；超限或结构错误整批零执行。调用 ID 和 name 原样保留；调用失败逐项返回结果，不自动重放外部调用。
7. 整个用户轮结束、取消或出错后释放本轮加载集合和索引。下一用户轮从空集合重新发现；运行中收到 `tools/list_changed` 不改本轮快照，下轮由 022 重列后搜索新目录。

成功搜索只开放定义，业务调用仍经既有 MCP 路由、身份、参数和取消检查。连接在搜索后断开时，后续业务调用按现有断连失败处理，不自动重连或重放。

### 1.5 轮预算、保存、CLI 与 TUI

- 继续每用户轮最多 8 次模型请求、每批最多 32 次工具调用。搜索本身是本地调用，不额外请求模型；搜索后继续产生调用的模型请求照常计数，不豁免额度。第 8 个模型响应中的搜索及其他已接受调用照常保存完整结果，之后不得第 9 次请求。
- 取消前未执行的搜索按本工具三字段失败结构回填；搜索过程中在结果提交前检查取消，不发布迟到结果或加载新增定义。已经配对保存的成功结果保留，当前轮的临时状态在结束时释放。
- 搜索参数和结果作为普通工具调用/结果保存，不新增会话记录类型、不升级格式。保留 024 原生签名和块；`/resume` 只恢复展示与历史，不重放搜索、MCP 发现或业务调用。
- 恢复或新用户轮中的旧搜索结果是历史资料，不能据其重建执行权限；即使历史中有完整 Schema，也须根据本轮实际声明判断调用资格。不得将历史模型输出伪装成宿主新加载的工具。
- CLI/TUI 复用通用工具活动与文本结果展示：用户可看到 query、命中数及模型工具名，失败可见具体原因。恢复后的展示与实时一致；终端转义控制只过滤展示副本，不修改模型调用身份或 Schema。不设计独立交互页面。

### 1.6 容量与验证条件

以下是本项建议冻结的行为边界，不是实测性能数据；既有边界与新增边界分别标注，不新增配置项。

| 对象 | 约束与超限行为 | 依据 |
|---|---|---|
| 单服务器发现 | 保留 100 页、2048 项、64 KiB 游标及原有超时/取消 | 022 既有，不借按需加载放宽 |
| 当前轮可搜索目录 | 最多 2048 项；容量计量 JSON 为 `{"entries":[{"server_id":...,"raw_tool":...,"definition":...,"search_text":...}],"sources":[{"server_id":...,"tool_count":...}]}`，完整 UTF-8 序列化最多 10 MiB；标点与转义也计入 | 本项新增的跨服务器总量限制；分别复用现有目录和请求上限数值，不误称原有全局边界 |
| 查询 | 原始 query 最多 4096 UTF-8 字节，limit 缺省 8、最大 32 | 8 沿用上游默认；其他为本项新增输入边界 |
| 单次搜索结果 | 三字段完整结果 JSON 最多 1 MiB；Schema 和结果列表不得静默裁剪；超限整次失败且不加载本次结果 | 本项新增的工具结果边界 |
| 单次模型请求工具数 | 常驻工具＋tool_search＋累计加载的工具最多 128；超过时本次搜索失败，提示缩小 limit 或在新用户轮处理，不自动淘汰之前已加载工具 | 022 的 128 改为约束本次实际声明集合；未加载目录不占声明名额 |
| 最终模型请求 | 各协议实际序列化请求仍最多 10 MiB，含历史、原生状态、搜索结果和当前定义；超限拒绝，不删历史、不改 Schema | 006/024 既有；目录或结果未超限不保证后续完整请求能发送 |

- 开启模式的目录总量检查在首次模型请求前完成；超限明确失败，不先发出半份目录，不静默切回全量声明。目录中每个入选工具都纳入检查，不能通过搜索词避开总量边界。
- 索引、规范化定义和连接复用当前快照；只物化命中结果，顺序处理，不为每次搜索复制全目录。容量计量应有界，不能先无上限构造完整 JSON 再判断。
- 测试在当前 Linux 容器、锁定依赖、临时配置/HOME/缓存/会话目录下进行；实际记录 Rust/Cargo、OS、CPU、身份。模型与 MCP 使用本地固定响应边界，真实搜索、加载状态和路由不使用 Mock 替代。
- 速度、峰值内存和费用当前未测；不填写虚构阈值或零费用。M0 使用最小原型冻结词法、固定性能夹具及基线，再按同机同版本基线的 2–3 倍余量确定 p95/RSS 上限并更新本节，之后不得为过关改阈值；未完成该步骤不能标为待验收。
- 测法固定：单并发；96 与 2048 工具两档，另测空目录；索引构建和已建索引查询分别计时；预热 5 次、正式 1000 次、独立运行 3 轮取 p95 中位轮，同时保存三轮原始样本；独立进程记录峰值 RSS，并区分已加载目录基线与建索引增量。2048 工具夹具必须落在上述 10 MiB 边界内。
- 上下文效果用同一 96 工具单服务器夹具和仅需 2 工具的任务比较开关前后五协议真实请求：关闭时声明 96 个动态工具；开启时首次为 0，命中 2 个后下一请求为 2。分别记录 tools 数组、来源概览、搜索结果和完整请求的 UTF-8 字节数，不能只统计省掉的定义而漏算新增历史。固定夹具的首次 tools 数组字节数，以及使用两项工具后发出的最终完整请求字节数，均须小于关闭模式的对应对照；完整请求比较必须包含新增搜索历史。字节数不当成实际 token、费用或缓存收益。

## 2. 哪些情况容易出错

| 情况 | 期望结果 |
|---|---|
| 未配置开关、开关名称不完全匹配，或目录为空 | 原有全量路径/空目录行为不变；不注册虚假搜索工具；伪造调用零外部请求 |
| query 非字符串/全空白/超长；limit 为 null、浮点或越界；有未知字段 | 三字段失败，加载集合不变，参数中恶意连接或认证字段不起作用 |
| 英文用途词、中文相同关键词、参数字段名或准确工具名；零命中 | 使用冻结词法排序；返回完整可调用定义或空成功，不回退全量开放 |
| 元数据只有相同分数、相同原始名分属不同服务器、超长模型名或命名碰撞 | 排序和模型名稳定；沿用既有原始身份映射，不按 `__` 拆名路由 |
| 搜索成功后同批猜测调用新工具；未搜索直接调用 | 零业务调用；失败记录与原 ID/name 配对；只有下一请求实际声明后才允许调用 |
| 一批多次搜索、重复命中、先成功后容量失败 | 每次完整成功或完整失败；保留既有加载项，下一请求定义不重复，不越 128 |
| 定义带 required/enum/$defs 或协议转换差异 | 原 Schema 全量保留；024 按提供方格式转换；搜索结果里的 Schema 不单独改写 |
| 允许名单为空、禁用工具或已知凭证出现在定义/来源/检索文本中 | 被排除项不进入概览、索引或加载集合；普通日志不泄露敏感片段；不能靠猜名调用 |
| list_changed、reload、工具取消/断连、目录被服务端重排 | 本轮不漂移，下轮重新冻结；断连不重放；取消前未提交结果不加入加载集合 |
| 恢复后历史有旧完整定义，当前工具已移除或权限改变 | 历史只展示，不能激活旧能力；新轮只认当前快照及本次声明 |
| 第 8 次响应才搜索、批次 >32、响应中途断流 | 不增第 9 次请求；批次结构不完整或超限时零执行；已接受结果仍完整入史 |
| 目录、query、结果和模型请求恰好上限/多 1 字节 | 上限允许，超过失败；资源边界同时检查；不裁剪 Schema 或删除历史 |

## 3. 重要做法，为什么这样做

### 3.1 复用和本地适配

- Codex 固定基线 `d138398cef7d49e46fe33f1d0ddbd2ca0ed16aa4`：复用 [tool_search_spec.rs](https://github.com/openai/codex/blob/d138398cef7d49e46fe33f1d0ddbd2ca0ed16aa4/codex-rs/core/src/tools/handlers/tool_search_spec.rs) 的 query/limit、来源概览与默认 8 项，复用 [tool_search.rs](https://github.com/openai/codex/blob/d138398cef7d49e46fe33f1d0ddbd2ca0ed16aa4/codex-rs/core/src/tools/handlers/tool_search.rs) 的 BM25 目录搜索及 [MCP 检索字段](https://github.com/openai/codex/blob/d138398cef7d49e46fe33f1d0ddbd2ca0ed16aa4/codex-rs/core/src/tools/handlers/mcp.rs#L593)。不引入上游 Agent 调度、全局缓存或代码编排框架。
- 上游 [Cargo.toml](https://github.com/openai/codex/blob/d138398cef7d49e46fe33f1d0ddbd2ca0ed16aa4/codex-rs/Cargo.toml) 声明 bm25 2.3.2；该库的 [2.3.2 元数据](https://docs.rs/crate/bm25/2.3.2/source/Cargo.toml.orig)标明 MIT。实施时使用该固定版本并把新增传递依赖写入 Cargo.lock，不在本轮安装。词法设置以[库文档](https://docs.rs/bm25/2.3.2/bm25/)和冻结夹具共同核实。
- [OpenAI Docs](https://developers.openai.com/api/docs/guides/tools-tool-search)区分托管搜索与 client-executed 搜索，其原生调用/结果类型及加载注入属于 Responses 协议。030 选择普通函数方案以共用五协议；不宣称具备原生注入的缓存收益，后续也不自动改走托管路线。
- 当前 `McpSnapshot` 已保存全部动态条目、完整定义及原始路由；增加最小只读访问以区分动态工具和固定资源工具，保留原 `definitions()` 的全量兼容入口。索引和本轮加载状态放在本地搜索模块，不重写 MCP 管理器或协议层。
- 声明集合与执行集合共用同一请求快照；结果中出现工具名或历史里有 Schema 都不足以授予执行权限。优先把这个约束放在已有动态工具分派之前，避免只修改提示词列表。
