# 计划：用户问询分阶段接入

> 状态：**阶段 A 已获用户批准（2026-10-23），正在本地提交与合并；已完成验收、安全门禁、双轴审查与全量回归。阶段 B 未实施。**
> 日期：2026-10-22。
> 依据：[用户问询差异复核](../records/2026-10-22-codex-user-input-comparison.md)及用户体验讨论。
> Codex 基线：`d138398cef7d49e46fe33f1d0ddbd2ca0ed16aa4`，沿用已核对的固定提交。

## 1. 目标与阶段

让模型在缺少关键信息时，能向用户提问，拿到回答后继续原任务。

| 阶段 | 用户体验与适用场景 | 本计划的交付边界 |
|---|---|---|
| A：同步问询 | 先确定方向再动手。例如修改登录流程前，先问保留密码还是改验证码；用户回答后再继续 | 首版只接入 `request_user_input`，包含界面、回答回送、取消和历史恢复 |
| B：异步问询 | 能先做独立准备工作。例如边查项目资料，边等用户说明报告面向谁 | 同步版验收后另行实施；本计划只记录后续边界，不提前注册异步工具或实现其运行机制 |

两阶段可复用问询显示与输入收集部分。异步还需解决晚到回答如何影响正在做的工作，因此不与首版一起改造。

首版不引入 Plan Mode、其他新工具、独立问询数据库、通用任务调度或新的 API 协议。现有 `update_plan`、执行工具、内部记忆工具和普通聊天排队语义保持。

## 3. 阶段 A：接口约定

### 3.1 模型提交问题

```json
{
  "questions": [{
    "id": "login_method",
    "header": "登录方式",
    "question": "保留密码登录，还是改为验证码？",
    "options": [
      {"label": "保留密码", "description": "沿用现有登录方式。"},
      {"label": "改为验证码", "description": "调整为短信验证码登录。"}
    ]
  }]
}
```

- 字段名、选项结构和上游“优先一题、最多三题；每题提供两到三个选项”的使用指引保留。数量指引不冒充上游已有的运行时硬校验，也不另外增加数量配置。
- 同步工具要求每题提供非空选项；保留上游启用“其他”文字回答的归一化。首版不放宽为可省略选项的纯文字题。
- 模型面只接受 Schema 中声明的字段；未知字段、缺字段、错误类型和缺失／空选项返回参数错误，不打开问询界面。未知字段拒绝是本地现有工具严格入参惯例的适配。
- 另补避免无法显示或丢失回答所需的关联校验：问题数组非空，问题 `id` 非空且批内唯一。ID 只用 trim 判断全空白，不改写原值；不把这些校验说成上游已强制保证。
- `isBlocking / autoResolutionMs / isSecret / isOther` 不作为本地模型可填参数。宿主使用等效于上游 `isBlocking=true` 的问答路径，启用“其他”文字入口，不加入秘密输入或自动空答功能。

### 3.2 回答与失败结果

成功回答沿用上游结构，不另包 `ok`，不把用户回答转换成普通下一轮聊天：

```json
{"answers":{"login_method":{"answers":["保留密码","保留当前账号兼容性。"]}}}
```

`answers` 按问题 ID 对应，数组按上游问答界面语义承载选择与文字补充。返回前核对答案只属于本次请求，不接受未知问题 ID、重复提交或其他请求的回答。

失败沿用本地通用工具结果 `{"error":"具体原因"}`。问询执行前被取消，错误使用现有 `SKIPPED_BY_CANCEL_MESSAGE`；已经显示问题但未完成时，明确说明问询未完成，不伪称本调用未执行。

- 只有用户明确提交才返回回答。保留上游“存在未答题时确认再提交”的必要交互；用户确认提交未答题属于明确操作，不等同于自动空答。
- 推荐项预选、打开弹窗、等待时间流逝均不算提交。关闭自动空答后不会因倒计时结束而返回空回答。
- 用户回答只作为任务输入，不改变执行工具的权限边界，也不替代已有授权检查。

### 3.3 开放范围与循环

- TUI 和有交互终端的行式 CLI 提供问询宿主接口；普通用户轮及带记忆摘要的用户轮增加第五项工具。
- 没有回答通道的调用方维持原四工具面，不声明问询能力；即使模型返回该名称，执行层也明确拒绝。非交互管道不从后续聊天输入猜测答案，不等待人工输入。
- 内部记忆合并轮不声明、不执行问询工具，也不获得宿主回答接口。
- 每轮仍最多 8 次模型请求、每批最多 32 条工具调用。等待用户期间不额外请求模型；收到回答后，按现有循环继续。
- 同批多个问询按现有工具顺序串行处理，同一时刻只有一个当前问询。一个工具调用内的多题由同一问答界面收集。
- 第 8 次模型请求返回问询时仍按既有规则处理：收集并保存结果后报上限，不发第 9 次请求，不伪造最终回复。

## 4. 回答通道、等待与结束

**当前问询使用独立回送通道，普通聊天继续排队。** 不把 `queued_inputs` 改成万能输入池，也不自动消费已经排队的消息作为答案。

- turn 层增加最小宿主问询接口：把当前工具调用与已校验问题交给宿主，得到回答或结束原因。未提供接口时没有问询能力；保留无问询调用方的原有调用方式，不借此重构所有工具。
- TUI 工作线程每次问询新建一次性回送通道，通过驱动事件打开界面；UI 将提交结果送回该次通道。复用现有标准库通道与取消检查，不新增请求注册中心或全局问询管理器。
- 等待发生在工作线程，UI 继续处理输入、粘贴、渲染、取消与退出。回答／取消通路不获取 turn 持有的历史或自动保存锁，避免互相等待。
- 问答提交、取消等结束只接受一次；每个工具调用只记录一条终态结果。已受理成功的回答保留，重复或迟到回送不能产生第二条结果，更不能进入下一题。
- 因退出或问询通道关闭而结束本轮时，先记录当前问询错误，再按 006 的配对收尾方式为同批未执行调用补结果，错误说明真实的未执行原因；不能留下悬空调用或伪称已执行。

| 事件 | 首版约定 |
|---|---|
| 用户提交选择或“其他”文字 | 回送当前问询，保存配对工具结果，再按原任务继续 |
| 用户尚未提交 | 保持等待，不自动空答、不执行同批后续工具；此前已经启动的进程仍按原有管理器运行 |
| TUI Esc | 取消当前轮，关闭当前问询并结束等待；剩余调用按原取消契约处理 |
| TUI Ctrl+C | 按既有职责退出宿主；先唤醒等待、记录未完成结果，再走原有进程清理和会话排空 |
| 行式 CLI Ctrl+C | 按工具运行期间的既有语义取消当前轮，明确记录问询未完成 |
| 行式 CLI Ctrl+D／EOF | 结束问询并请求退出宿主；保存未完成工具结果后退出，不再向模型发起续请求 |
| 回答通道断开或界面异常关闭 | 返回明确错误、解除等待，不伪造答案；本轮结束，不自动重试问询 |
| 取消后迟到回答、旧请求事件 | 丢弃，不作为普通聊天、下一题答案或新一轮输入 |
| 会话恢复／切换 | 保持现有运行中命令处理规则；未完成问询须先结束，不能把等待状态迁移到另一会话 |

这里的用户等待没有自动提交时限；取消和退出仍须能及时打断等待。不得靠无限期阻塞读取，导致终端关闭或宿主退出时挂住。

## 5. 界面与保存恢复

- **TUI**：复用 Codex 问询 overlay 的选项、文字补充、多题前后切换、提交与未答确认；显示和布局按当前 BottomPane 接口适配。已有聊天草稿和排队消息不改作答案，问答结束后回到原输入状态。首版不恢复无关的图片、异步或 App Server 功能。
- **行式 CLI**：用现有 readline 显示题目、带说明的编号选项和“其他”入口，收集选择与文字补充；非法选择允许在当前题重新输入。仍由主线程唯一读取终端，不另启第二个 stdin 读取者。
- **显示过滤**：问题、选项、说明、自由回答及错误进入终端前，复用现有过滤函数；过滤展示副本，原始调用与回答按历史契约保留。显示过滤不能改写配对 ID，选择须保持与原始选项的对应关系。
- **保存**：沿用 V1 的 `AssistantToolCalls` 和 `ToolResult`；问题取调用参数，回答取成功结果，`display=None`。不新增持久化枚举变体、独立文件或数据库。
- **恢复**：配对记录重建已完成或已中断的问答显示；未完成调用遵守 007 的未知结果修复规则，不能显示为用户已回答。恢复不打开活动问询、不重新执行工具或自动请求模型。
- **同源投影**：TUI 实时问答结果与恢复共用转换及结果 cell；活动弹窗状态不入会话，只有工具调用和终态结果入史。

## 6. 修改落点与实施顺序

| 落点 | 本功能需要的改动 |
|---|---|
| `src/shims/codex-protocol` | 补共用问题／回答类型；后端和渲染共用这些类型，必要的上游类型名用局部导入别名适配，不恢复 App Server 参数封装或扩充其协议 shim |
| `src/app/src/user_input.rs`、`lib.rs` | 最小解析、归一化、关联校验、回答和错误结果处理 |

| `src/app/src/main.rs`、`tui_host.rs` | readline 问答；TUI 上行问题和一次性回答回送；EOF、取消、退出与结果恢复 |
| `src/tui/src/chat_driver.rs`、BottomPane、AppEvent／AppEventSender 及必要视图接口 | 当前问询事件、回答直送、等待结束与弹窗清理；不改普通输入队列用途 |
| 恢复的 `bottom_pane/request_user_input/`、`history_cell/request_user_input.rs` | 上游必要显示与输入逻辑，移除 App Server 依赖和自动处理路径 |
| 相关测试、005／006／007／008／010／012／017 的受影响说明 | 同步工具数、能力边界、问询与按键／恢复条款；不把新工具数改动误套到内部记忆轮或无问询宿主 |

实施分三步，每步先确认基线并按 TDD 验证：

1. **工具与回送 → 验证等得到真实回答。** 接入参数、能力声明和宿主接口，用本地 mock 驱动工具循环；提交前不执行后续工具，提交后按问题 ID 回传。
2. **CLI／TUI 与结束路径 → 验证用户能完成问答。** 恢复上游必要界面，打通提交、取消、EOF、退出及一次性清理，证明输入不会误入普通队列或串题。
3. **保存恢复与验收 → 验证可交付。** 接通同源投影，完成下表回归及有效性证明，再走项目规定的加固、安全测试、审查和全量验证。

## 7. 阶段 A 验收

测试复用本地 mock、[工具循环](../../src/app/tests/tool_loop.rs)、[会话 CLI](../../src/app/tests/session_cli.rs)、[E2E](../../src/app/tests/e2e_acceptance.rs)和 [PTY 辅助](../../src/app/tests/common/pty.rs)。所有测试隔离用户目录和配置，固定响应，不使用真实模型或密钥。

| 场景 | 必须证明的结果 |
|---|---|
| 参数与关联 | 有效问题沿用上游结构；非法 JSON、未知字段、缺字段、空问题／空选项和空／重复 ID 失败且不显示问题；输入与结果原文保留 |
| 能力与权限 | 交互用户轮五工具，无回答接口仍四工具；内部记忆轮不声明也不执行问询；模型伪造工具名不能绕过宿主能力检查 |
| 真正等待与继续 | 真实工具循环出现问题，提交前请求数和后续工具副作用不增加；提交后回答进入下一请求，实际工作继续；预选项和时间经过不算提交 |

| 取消／退出／EOF | 等待中仍响应取消和退出；只记录一次正确终态，剩余调用不执行；退出完成会话排空，既有进程生命周期仍按原契约处理 |
| 输入与迟到事件 | 已排队聊天不当作答案；答复不成为下一轮聊天；取消、界面关闭或旧请求迟到不会串题、重复记录或遗留等待线程 |
| 历史与额度 | 新旧 V1 会话可加载，恢复只展示、不重新问；未完成记录不伪造已答；8 次／32 条边界及第 8 批结果保存语义保持 |
| 显示与副作用 | 不可信问题、选项和回答不能控制宿主终端；原始记录保留；回答内容不直接执行或扩大工具权限 |

等待用就绪通知和可控事件验证，不靠长时间睡眠判断。关键新增用例以桩实现或可逆破坏证明有效，至少能检出“回答进入普通队列”“未提交即继续”“取消未解除等待”“迟到回答串题”和“恢复重新提问”等错误。

代码实施时依次执行 `TDD → comprehensive-testing → Security Testing → code-review → 全量验证和修复`；发现错误按项目要求使用 `diagnosing-bugs`。最终在 `/workspace` 执行 `cargo check && cargo test --workspace --no-fail-fast`，报告通过、失败、忽略及未运行数量；适用 lint 和 V1 兼容性检查如实记录。

## 8. 阶段 B：异步版后续条件

异步版参考固定提交的 [request_user_input_async.rs](https://github.com/openai/codex/blob/d138398cef7d49e46fe33f1d0ddbd2ca0ed16aa4/codex-rs/core/src/tools/handlers/request_user_input_async.rs)：接收问题，发布后立即返回 `{"accepted":true}`，用户随后回答。该确认只代表问题已发布，不代表用户已答复。

同步版验收后，再单独固定并验证以下规则：

- 独立工作继续时，晚到回答在哪个请求／工具边界送入当前上下文；不把回答插入一条已经发出的模型请求。
- 当下一步必须依赖回答时如何等待，以及回答与正在进行的工作冲突时如何处理；不能仅靠把消息排到任务结束后。
- 当前任务结束、取消、退出或切换会话后，问题是否仍有效，回答如何明确归属；不悄悄成为新任务输入。
- 模型支持条件、问询发布、重复／迟到回答与取消的独立验收。

阶段 A 不为这些规则预建后台运行时、异步存储、额外等待工具或第二套界面。后续按 Codex 的问题投递思路适配现有对话，不混入另一套 API 示例协议。
