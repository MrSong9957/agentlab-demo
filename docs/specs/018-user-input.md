## 1. 目标与阶段

让模型在缺少关键信息时，能向用户提问，拿到回答后继续原任务。

| 阶段 | 用户体验与适用场景 | 本计划的交付边界 |
|---|---|---|
| A：同步问询 | 先确定方向再动手。例如修改登录流程前，先问保留密码还是改验证码；用户回答后再继续 | 首版只接入 `request_user_input`，包含界面、回答回送、取消和历史恢复 |
| B：异步问询 | 能先做独立准备工作。例如边查项目资料，边等用户说明报告面向谁 | 本轮补齐 §8 契约草案；确认后另行实施，不提前注册工具或建设运行机制 |

两阶段可复用问询显示与输入收集部分。异步还需解决晚到回答如何影响正在做的工作，因此不与首版一起改造。

首版不引入 Plan Mode、其他新工具、独立问询数据库、通用任务调度或新的 API 协议。现有 `update_plan`、执行工具、内部记忆工具和普通聊天排队语义保持。

## 3. 阶段 A：接口约定

### 3.1 模型提交问题

```json
{
  "questions": [{
    "id": "login_method",
    "header": "登录方式",
    "question": "保留密码登录，还是改为验证码？",
    "options": [
      {"label": "保留密码", "description": "沿用现有登录方式。"},
      {"label": "改为验证码", "description": "调整为短信验证码登录。"}
    ]
  }]
}
```

- 字段名、选项结构和上游“优先一题、最多三题；每题提供两到三个选项”的使用指引保留。数量指引不冒充上游已有的运行时硬校验，也不另外增加数量配置。
- 同步工具要求每题提供非空选项；保留上游启用“其他”文字回答的归一化。首版不放宽为可省略选项的纯文字题。
- 模型面只接受 Schema 中声明的字段；未知字段、缺字段、错误类型和缺失／空选项返回参数错误，不打开问询界面。未知字段拒绝是本地现有工具严格入参惯例的适配。
- 另补避免无法显示或丢失回答所需的关联校验：问题数组非空，问题 `id` 非空且批内唯一。ID 只用 trim 判断全空白，不改写原值；不把这些校验说成上游已强制保证。
- `isBlocking / autoResolutionMs / isSecret / isOther` 不作为本地模型可填参数。宿主使用等效于上游 `isBlocking=true` 的问答路径，启用“其他”文字入口，不加入秘密输入或自动空答功能。

### 3.2 回答与失败结果

成功回答沿用上游结构，不另包 `ok`，不把用户回答转换成普通下一轮聊天：

```json
{"answers":{"login_method":{"answers":["保留密码","保留当前账号兼容性。"]}}}
```

`answers` 按问题 ID 对应，数组按上游问答界面语义承载选择与文字补充。返回前核对答案只属于本次请求，不接受未知问题 ID、重复提交或其他请求的回答。

失败沿用本地通用工具结果 `{"error":"具体原因"}`。问询执行前被取消，错误使用现有 `SKIPPED_BY_CANCEL_MESSAGE`；已经显示问题但未完成时，明确说明问询未完成，不伪称本调用未执行。

- 只有用户明确提交才返回回答。保留上游“存在未答题时确认再提交”的必要交互；用户确认提交未答题属于明确操作，不等同于自动空答。
- 推荐项预选、打开弹窗、等待时间流逝均不算提交。关闭自动空答后不会因倒计时结束而返回空回答。
- 用户回答只作为任务输入，不改变执行工具的权限边界，也不替代已有授权检查。

### 3.3 开放范围与循环

- TUI 和有交互终端的行式 CLI 提供问询宿主接口；普通用户轮及带记忆摘要的用户轮增加第五项工具。
- 没有回答通道的调用方维持原四工具面，不声明问询能力；即使模型返回该名称，执行层也明确拒绝。非交互管道不从后续聊天输入猜测答案，不等待人工输入。
- 内部记忆合并轮不声明、不执行问询工具，也不获得宿主回答接口。
- 每轮仍最多 8 次模型请求、每批最多 32 条工具调用。等待用户期间不额外请求模型；收到回答后，按现有循环继续。
- 同批多个问询按现有工具顺序串行处理，同一时刻只有一个当前问询。一个工具调用内的多题由同一问答界面收集。
- 第 8 次模型请求返回问询时仍按既有规则处理：收集并保存结果后报上限，不发第 9 次请求，不伪造最终回复。

## 4. 回答通道、等待与结束

**当前问询使用独立回送通道，普通聊天继续排队。** 不把 `queued_inputs` 改成万能输入池，也不自动消费已经排队的消息作为答案。

- turn 层增加最小宿主问询接口：把当前工具调用与已校验问题交给宿主，得到回答或结束原因。未提供接口时没有问询能力；保留无问询调用方的原有调用方式，不借此重构所有工具。
- TUI 工作线程每次问询新建一次性回送通道，通过驱动事件打开界面；UI 将提交结果送回该次通道。复用现有标准库通道与取消检查，不新增请求注册中心或全局问询管理器。
- 等待发生在工作线程，UI 继续处理输入、粘贴、渲染、取消与退出。回答／取消通路不获取 turn 持有的历史或自动保存锁，避免互相等待。
- 问答提交、取消等结束只接受一次；每个工具调用只记录一条终态结果。已受理成功的回答保留，重复或迟到回送不能产生第二条结果，更不能进入下一题。
- 因退出或问询通道关闭而结束本轮时，先记录当前问询错误，再按 006 的配对收尾方式为同批未执行调用补结果，错误说明真实的未执行原因；不能留下悬空调用或伪称已执行。

| 事件 | 首版约定 |
|---|---|
| 用户提交选择或“其他”文字 | 回送当前问询，保存配对工具结果，再按原任务继续 |
| 用户尚未提交 | 保持等待，不自动空答、不执行同批后续工具；此前已经启动的进程仍按原有管理器运行 |
| TUI Esc | 取消当前轮，关闭当前问询并结束等待；剩余调用按原取消契约处理 |
| TUI Ctrl+C | 按既有职责退出宿主；先唤醒等待、记录未完成结果，再走原有进程清理和会话排空 |
| 行式 CLI Ctrl+C | 按工具运行期间的既有语义取消当前轮，明确记录问询未完成 |
| 行式 CLI Ctrl+D／EOF | 结束问询并请求退出宿主；保存未完成工具结果后退出，不再向模型发起续请求 |
| 回答通道断开或界面异常关闭 | 返回明确错误、解除等待，不伪造答案；本轮结束，不自动重试问询 |
| 取消后迟到回答、旧请求事件 | 丢弃，不作为普通聊天、下一题答案或新一轮输入 |
| 会话恢复／切换 | 保持现有运行中命令处理规则；未完成问询须先结束，不能把等待状态迁移到另一会话 |

这里的用户等待没有自动提交时限；取消和退出仍须能及时打断等待。不得靠无限期阻塞读取，导致终端关闭或宿主退出时挂住。

## 5. 界面与保存恢复

- **TUI**：复用 Codex 问询 overlay 的选项、文字补充、多题前后切换、提交与未答确认；显示和布局按当前 BottomPane 接口适配。已有聊天草稿和排队消息不改作答案，问答结束后回到原输入状态。首版不恢复无关的图片、异步或 App Server 功能。
- **行式 CLI**：用现有 readline 显示题目、带说明的编号选项和“其他”入口，收集选择与文字补充；非法选择允许在当前题重新输入。仍由主线程唯一读取终端，不另启第二个 stdin 读取者。
- **显示过滤**：问题、选项、说明、自由回答及错误进入终端前，复用现有过滤函数；过滤展示副本，原始调用与回答按历史契约保留。显示过滤不能改写配对 ID，选择须保持与原始选项的对应关系。
- **保存**：沿用 V1 的 `AssistantToolCalls` 和 `ToolResult`；问题取调用参数，回答取成功结果，`display=None`。不新增持久化枚举变体、独立文件或数据库。
- **恢复**：配对记录重建已完成或已中断的问答显示；未完成调用遵守 007 的未知结果修复规则，不能显示为用户已回答。恢复不打开活动问询、不重新执行工具或自动请求模型。
- **同源投影**：TUI 实时问答结果与恢复共用转换及结果 cell；活动弹窗状态不入会话，只有工具调用和终态结果入史。

### 8.2 推荐范围与能力边界

首版仅给 **TUI 普通用户轮及带记忆摘要用户轮**提供异步能力；每轮同一时刻最多一项未决问询（一项可包含多题）。已接收但尚未入史的回答仍占用该项，完成入史后才释放；第二次发布返回占用错误，不替换旧题。不另加每次题数/选项数上限，沿用既有字节边界。

| 调用方 | 阶段 B 确认并实施后的拟定工具面 |
|---|---|
| 有同步与异步回答接口的 TUI 用户轮 | 七项：原四项＋同步问询＋异步发布＋本节拟议等待工具 |
| 有交互终端的行式 CLI | 继续五项，仅同步问询；不声明或执行异步/等待工具 |
| 无回答接口、非交互管道 | 继续四项，拒绝伪造问询能力 |
| 内部记忆合并轮 | 继续仅三项 mem 工具，不声明、不执行两个问询或等待，不获得任何回答接口 |

CLI 若同时支持边执行边回答，需要先分离主线程终端读取与 turn 执行，属于额外宿主改造；本最小方案后置，不用第二个 stdin 读取者补洞。异步宿主能力独立于已有同步宿主能力判断，不把七工具套到所有调用方。不增加模型白名单或协议：仍使用现有 Chat Completions function 通道；提供方兼容与实际工具使用效果不能由本轮调查宣称通过。

异步未决时的新同步问询也返回占用错误，提示先完成或等待原问题；不暗中把同步工具改成“等待旧异步题”的别名。没有异步未决状态时，阶段 A 的声明、执行及等待语义保持。

### 8.3 发布与真正回答的路径

拟议发布参数直接沿用上游：

```json
{"questions":[{"title":"保留密码登录还是改为验证码？","options":["保留密码","改为验证码"]}]}
```

`questions` 非空；`title` 仅用 trim 判断非空、不改原文；模型 Schema 允许省略 `options`，数组给出时须非空且各字符串非空白。运行时保留上游 Option 语义，省略/null 均视作纯文字题；顶层及每题拒绝未知字段。不接收模型填写任务归属、自动提交时间或权限参数。

- 发布：校验后为本轮建立独立回送通道、live 标志及未决项，将问题交给 UI 事件通道，随即产生一次发布 ToolResult。宿主拒绝接收时返回 `{"error":"具体原因"}`，不留下活动问题。
- 发布成功拟返回 `{"accepted":true,"request_id":"<原始工具调用 ID>"}`。`accepted` 沿用 Codex；`request_id` 是为显式等待/关联增加的最小本地字段，不另造随机 ID。它确认宿主已接收发布，不保证已显示、已读、已答或已持久化。
- 每题按上游规则，以原始调用 ID 和 0 起的题目序号生成 ID。`title` 映射 Question.question，header 用本地题号；字符串选项映射 label、description 留空，开启已有 Other/文字输入，复用阶段 A 的 Response。原始问题、选项、回答及 ID 不因显示过滤改写。
- 真正回答：用户在原有问答窗口明确提交后，经该次通道送到本轮工作线程；预选、时间流逝和普通聊天均不提交。UI 区分“已提交、待接入”和“已接入”；后者仅在批末写入原任务历史后标记，不等于模型已读或已落盘。
- 运行时关联为“会话代次＋本轮令牌＋request_id”，回送通道每次独立；模型提供字符串 ID 不能选择另一轮/会话。普通聊天始终走原 `queued_inputs`，不解析正文中的 JSON/标签来切换输入身份。

### 8.4 回答接入与依赖等待

工作线程可在工具完成/模型返回的检查点收取回答，但**在当前工具批全部配对之前只暂存，不把回答文本插入历史**。正式入史/模型可见时点固定为：完整工具批之后、下一次请求组装之前；无工具的模型回复结束检查也须先处理已受理回答。

已经发出的模型请求和在执行的工具按既有语义完成；回答不改写该请求/工具的参数或结果、不回滚已发生工作。提交到接入的延迟可能包含剩余在途请求/工具批，首版不承诺立即中断它们。模型必须只在此前安排不依赖答案的工作。

新回答入史后，下一个模型请求包含它；普通排队聊天仍待本轮结束。若模型已给出无工具终文，而结束检查前已有被受理回答，应继续原轮让模型处理，不把该终文提前交付为任务完成；没有新回答时正常完成，并关闭未答问题。未决问题本身不会触发轮询模型或自动续命。

下一步必须依赖答案时，建议额外接入 **`wait_for_user_input`**，这是本地新增适配，不将其冒充为上述异步处理器已有能力：

```json
{"request_id":"<本轮发布确认中的 request_id>"}
```

- 仅一个必填非空 ID，拒绝未知字段，按原值关联；仅能等待本轮的该次请求。在具备异步宿主的用户轮中，等待必须为该批最后一条调用，依赖动作应在拿到回答后的模型请求中重新生成；带后续调用的等待批在入史/执行前拒绝，避免预先执行尚不知道答案的动作。无接口调用方仍先按能力拒绝，不获得此处理器。
- 已有回答则立即返回 `{"ready":true,"request_id":"..."}`；尚未回答则停在同一次调用，复用标准库通道与可取消等待，不增加模型请求或重复轮询工具。成功后先补齐该批工具结果，再追加真正回答数据供下一请求使用；`ready` 不作为第二份回答或第二次提交。
- 已接入的同轮 ID 再等待只确认就绪，不重写回答；未知、其他轮或已关闭 ID 返回错误，不打开界面。真实通道异常按明确失败结束本轮；错误 ID 不夺取另一未决问题。
- TUI UI 线程仍处理输入/粘贴/重排、Esc 取消和 Ctrl+C 退出；回答与取消不获取 history 或 autosave 锁。等待结束先配齐工具结果，再保存答案/关闭事件，沿用既有会话排空。

不选“让模型不断调用发布工具检查答案”，也不通过改变阶段 A 或“终文即结束”来隐式创建等待模式。新增等待工具及其批末规则须在 §8.10 确认。

### 8.5 结束、迟到与额度

由本轮工作线程统一受理回答或关闭，二者只产生一次问询终态；UI 发出过文本不等于工作线程已受理。已受理答案保留，随后发生任务取消/额度耗尽也不把该问题重记为未答；未受理的迟到/重复回送不进入普通聊天或下一题。

| 事件 | 拟定处理 |
|---|---|
| 正常完成，问题仍未答 | 保存关闭原因 `task_completed`，问题失效、UI 清理；不等晚答、不启动新轮 |
| Esc 取消 | 结束等待/独立工作，剩余调用按 006 配对；保存 `cancelled`，旧事件/live 失效。已启动进程仍按 016 保留 |
| Ctrl+C 或终端关闭 | 先解除问询等待和收尾配对/保存，再走原有宿主进程清理；保存真实宿主退出原因 |
| 模型/协议/通道失败 | 关闭未决项并保存对应失败原因，不自动重发问询 |
| 8 次额度耗尽 | 保存已发生的发布/工具结果及已受理答案，关闭未答项为 `request_limit`；不发第 9 次请求 |
| 会话切换/恢复 | 运行中的 `/resume` 继续拒绝；先取消/结束才可切换。成功切换使旧会话代次失效；载入不恢复等待通道 |
| 重复提交、旧 UI 事件或晚答 | 只针对原通道处理/丢弃并反馈已失效，不创建任务、不触发模型请求 |

每个模型请求照常计入 8 次，每批所有新旧工具合计仍不超过 32 条。第 8 个请求不再发布新的异步问题，也不为未答问题开始阻塞等待，返回明确额度错误；已到回答仍保存但不能承诺用于续算。若第 8 次结束检查已受理新答案但无续算额度，明确报额度耗尽，不能把未读该答案的终文伪称为已按答案完成。32 条合法批/33 条整批拒绝、整批结构校验及第 8 批结果保存均保持；阶段 A 在第 8 批的同步收集规则不改。

### 8.6 保存、恢复与必要的 V1 扩展取舍

推荐继续使用原 JSONL、`{"v":1}`、`AssistantToolCalls` 和一次发布 `ToolResult`（`display=None`）；晚到回答作为**带宿主来源标记的 Text 用户数据**追加，模型仍接收普通 role/content，不增加 API 协议。原发布确认不被覆盖，原 ID 不出现第二个 ToolResult。

为可靠区分回答、关闭事件和长得一样的普通聊天，拟给 HistoryMessage 增加一个可选 `user_input_event` 字段，携带 `kind=answer/closed` 和原 `request_id`；只由宿主的专用回答受理或问询收尾路径设置。普通聊天、阶段 A 和旧记录均为 None、序列化省略，不能让用户/模型正文伪造该标记。此会话字段扩展已按 §8.10 确认实施（2026-10-23）。

回答正文保留现有 Response，并附 request_id，例如某题 ID 按上游生成后：

```json
{"request_id":"call_17","answers":{"[\"request_user_input_async\",\"call_17\",0]":{"answers":["保留密码"]}}}
```

关闭正文保存同一 request_id 与具体原因；来源标记分别为 answer/closed。两类事件只能在工具批配对完成后入史，走同一个 `on_record`/自动保存路径。若先前已受理但尚未落盘，UI 只显示相应进度；保存失败沿用 007 待写和告警，不把“已接收”冒充“已保存”。

恢复投影以发布调用＋发布确认＋有效来源标记关联，同源重建已答/关闭状态；标记与正文 request_id 必须一致，答案 ID 只能属于原题，孤儿/重复/矛盾记录不伪造已答。只含确认而无回答/关闭记录时显示“中断/未保存回答、已失效”，不假定未执行或已答。带残缺配对的调用仍按 007 修复。**任何恢复都不创建活动问题、回送通道、模型请求或工具执行**；普通用户文本即使正文完全相同也不作为回答解析。来源标记只用于数据关联，不构成执行授权。

兼容事实：新读者须继续读全部旧 V1；已有程序可读含该可选字段的文本，但再次保存会删除来源标记，正文内的 ID/答案仍在、可靠自动关联能力丢失（§8.1 已实证）。最小建议是接受此可选扩展及旧版重存降级并明确告知；如果要求旧程序不能静默丢关联，应另行确认版本隔离，不能仍宣称 V1 完整双向保真。本轮不擅自选成新版会话格式，也不增加独立数据库/回答文件。

### 8.7 复用界面的最小操作

- 发布后给出待回答提示，Agent 继续独立工作，不自动抢占聊天草稿。建议 **F6** 打开本轮唯一未决项，复用原 overlay 的选项、Other、文字补充、多题、未答确认及过滤；进入后提交或 Esc 取消当前轮，首版不再增加隐藏/多面板管理。F6 在当前主界面没有既有默认职责，源码中同键仅见测试自定义绑定；实施时仍须验证实际路由与冲突。
- 显式等待时可自动打开同一窗口，不创建第二次问询。主 composer 与普通队列独立保留；F6/提交/取消直接走驱动和该次通道，不经持 history 锁的命令处理回调。Ctrl+C、Esc、F4/Ctrl+T 原有职责保持。
- 复用原结果 cell 展示终态，发布阶段用现有提示样式标明“已发布、未答复”；后来回答更新同一关联展示，不伪造第二个 ToolEnd/工具结果。实时与恢复共用聚合投影；所有显示仅过滤副本，原始 ID/选项/答案不改写。
