# 计划：命令执行与进程交互能力补全

> 状态：**已实施并验证（2026-10-22，分支 feat/016-process-sessions），待用户批准交付**。
> 依据：[命令执行与进程交互调研](../records/2026-10-22-codex-command-execution-and-process-interaction.md) §9 的五项缺口与 §10 的未定边界。
> Codex 对照沿用调研固定提交 `d138398cef7d49e46fe33f1d0ddbd2ca0ed16aa4`；本项目取舍在下文单独说明。
> 本轮只更新计划：默认可续接、首版 Linux、取消当前轮与终止进程分开、满额拒绝新建且只保留一份待取输出缓存；总运行时限采用下文已定案规则，不保留旧的 60 秒上限。整体计划仍待审核，不修改既有生效契约，不代表功能已经具备；获准实施后再执行。

## 1. 目标与范围

补齐长测试、本地服务和交互程序所需的完整链路：**启动 → 返回会话编号 → 查询新输出或发送输入 → 确认退出或主动终止 → 回收资源**。

| 调研中的缺口 | 拟补充的能力 | 完成时应能证明 |
|---|---|---|
| 未结束时没有可续接编号 | `exec_command` 默认可续接 | 工具先返回，同一个进程继续执行，不重新启动命令 |
| 不能后续查询 | 新增 `write_stdin` 空输入查询 | 每次返回尚未取走的输出，最终返回真实退出状态 |
| 不能给程序输入 | 可续接模式支持 `tty=true` | 在真实 PTY 中发送回答，让原程序继续运行 |
| 没有持续进程的控制与回收 | 支持中断、主动终止和宿主清理 | Ctrl+C 能请求中断，忽略中断的程序仍可被明确终止 |
| 与旧超时、取消和权限契约未衔接 | 区分本次等待、进程寿命与当前用户轮 | 调用方能处理未完成状态；取消当前轮不误杀进程，权限和退出清理继续成立 |

首版限定为 **Linux 本地执行，同一宿主、同一对话内跨工具调用和跨用户轮保留进程**。支持普通管道和 PTY 两种方式，Shell 继续固定为 `/bin/sh -c`。

以命令实际执行的系统为准：在 Linux 容器中执行属于首版范围，直接执行 Windows 命令不属于首版范围。Agent 宿主重启后，恢复聊天历史也不能凭旧编号继续控制原进程。

不纳入首版：Windows／ConPTY、远程执行、跨宿主重启重连、普通管道文字输入、终端缩放、后台输出主动推送、新沙箱或审批系统，以及调研中其他工具能力。

## 2. 现状与需要调整的契约

已只读核对以下实现与契约：

- [exec.rs](../../src/app/src/exec.rs) 与 [003](003-exec-command.md)：同步执行，默认超时 10 秒、最多 60 秒，stdin 关闭；输出限制为 Unicode 码点数，超时或取消时终止进程组。
- [prompt.rs](../../src/app/src/prompt.rs) 与 [turn.rs](../../src/app/src/turn.rs)：普通用户轮目前只有 `exec_command`、`apply_patch`；内部记忆合并轮另有受限工具，权限检查发生在实际分派层。
- [005](005-minimal-prompt-assembly.md)／[006](006-tool-call-loop.md)：当前工具声明固定为两项；调用与结果配对、单批最多 32 条、每用户轮最多 8 次模型请求、失败不自动重试，以及取消后跳过剩余调用。
- [007](007-session-persistence.md)：恢复历史不重新执行工具；[012](012-tui-tool-details.md)：工具状态如实展示，展示数据不混入模型结果；[015](015-turn-context-injection.md)：用户轮上下文注入与记忆内部轮隔离。
- [main.rs](../../src/app/src/main.rs)、[tui_host.rs](../../src/app/src/tui_host.rs) 与 [TUI 驱动](../../src/tui/src/chat_driver.rs)：需要接入跨轮状态、取消、退出和历史投影。按键以已验收契约为准：TUI 的 Esc 取消当前轮、Ctrl+C 退出，不能沿用部分源码头注释中的旧说法。

实施时先明确修订 003／005／006：普通用户轮工具从两项改为三项，`exec_command` 默认改为可续接，取消当前轮不再自动终止已启动的命令；再同步 007／012 中涉及新结果的说明。旧调用方必须处理“尚未结束＋编号”，现有同步返回、超时默认值、工具数量与取消行为断言须按新契约调整，不能宣称旧调用原封不动兼容。旧会话文件仍可加载，恢复不重放工具；其余未涉及的已验收行为保持。

## 3. 接口计划：默认可续接，等待与进程寿命分开

### 3.1 `exec_command`

| 调用方式 | 计划行为 |
|---|---|
| 省略 `yield_time_ms` | 默认等待 10000 毫秒；进程未结束则返回 `running` 与 `session_id`，结束则返回实际状态 |
| 显式提供 `yield_time_ms` | 只调整本次等待时间，不切换执行模式，也不决定何时终止进程 |
| `tty=false` 或省略 | 使用管道，stdin 关闭；支持持续运行和后续查询 |
| `tty=true` | 分配 PTY，允许后续发送字符；不要求显式提供 `yield_time_ms` |

建议参数规则：

- 原有 `cmd`、`workdir` 的含义保持；`max_output_chars` 默认 10000 码点，上限 100000。短命令与长命令使用同一套返回规则。
- `yield_time_ms` 默认 10000，取 `250..=30000` 毫秒，越界拒绝，不悄悄调整。进程提前结束时可以立即返回；等待到期不会杀进程。

总运行时限规则已定案，与本次等待时间分开：

| `timeout_ms` 输入 | 行为 |
|---|---|
| 省略 | 不设固定总运行时限，不按固定时间自动终止；仍可自然退出、明确终止或随执行会话关闭而结束 |
| 正整数 | 从进程成功启动开始，按毫秒计算固定截止时间；到期若仍未结束，则终止并回收，报告 `timeout`；取消旧的 60000 毫秒上限 |
| 零、负数、小数或其他非整数类型 | 拒绝执行，明确报错，不启动进程或部分执行命令 |
| 无法安全表示、转换为时长或计算截止时间的数值 | 拒绝执行，明确报错；不截断、饱和计算、回退成不限时或另设业务上限 |

数值和时间计算的安全性须在允许命令执行前完成校验；实际可接受范围由整数类型与截止时间的安全计算能力决定，不再使用旧的 60 秒限制。使用单调时钟从成功启动时计时，后台计时持续生效，不依赖 AI 是否回来查询；读取输出、发送输入、进入下一用户轮或取消当前轮都不重置、不暂停该时限。`write_stdin` 不接受修改总运行时限的参数。

例如 `yield_time_ms=10000`、`timeout_ms=180000`：先等 10 秒，尚未结束就返回编号；进程继续运行，启动满 3 分钟后若仍未结束，就触发终止并报告超时。

默认不限时参考 Codex；保留可选总运行时限是**本项目的扩展**。固定版本中，可续接处理器把 `completion_timeout` 设为 `None`，仅一次性处理器读取 `timeout_ms`，不能把本项目两个参数同时使用的接口说成 Codex 原样接口。首版不再增加“显式开启可续接”的开关或额外同步模式。

### 3.2 `write_stdin`

| 参数 | 建议规则 |
|---|---|
| `session_id` | 必填，不透明字符串句柄；由宿主管理，不是操作系统 PID |
| `chars` | 默认空字符串；空值只查询，非空值发送原字符，不自动补换行；单次暂定最多 64 KiB UTF-8 字节，超限整次拒绝，不截断后发送 |
| `yield_time_ms` | 空查询默认 5000，范围 `5000..=300000`；非空输入默认 250，范围 `250..=30000`，单位毫秒；越界拒绝 |
| `max_output_chars` | 默认 10000，上限 100000，含义与执行工具一致 |
| `terminate` | 默认 `false`；`true` 表示终止并回收目标进程组，不能同时发送非空 `chars` 或指定 `yield_time_ms` |

- 普通管道拒绝文字输入；仅当 `chars` 恰为 `"\u0003"` 时发送中断信号。PTY 模式直接发送控制字符，由终端和程序处理。
- Ctrl+C 是中断请求，不能保证程序退出。`terminate=true` 提供确定的停止入口，是本项目建议增加的参数，Codex 调研版本的 `write_stdin` 没有这个参数。
- 终止只进行有界收尾，不进入空查询的长等待；明确终止后应在 3 秒内结束本次等待并完成受管理进程的清理。清理失败须如实报告，不能返回“已终止”。取消当前轮时，应在 3 秒内结束本次等待并停止后续写入，但保留已经启动的进程，不默认发送 Ctrl+C 或强杀。
- 句柄绑定宿主实例和当前对话，不跨实例复用；未知、失效或其他对话的句柄返回错误，不能当 PID 使用或重新启动旧命令。
- 参数、输入方式或句柄错误不应破坏其他有效会话；向不读输入的程序写入时，也必须能取消，不能阻塞整个宿主。
- 64 KiB 是本项目的首版暂定值，不是 Codex 标准。超过上限时不得先写入一部分再报错；取消发生前已成功写入的内容则无法撤回，应如实说明。

### 3.3 返回与展示

`exec_command` 与 `write_stdin` 统一使用 `{status, exit_code, output, truncated, error, session_id}`，无可续接会话时 `session_id=null`。旧调用方也必须适配新状态和新增字段，不再保留旧五字段同步结果的特殊分支。

- `running`：进程仍在运行，返回句柄，`exit_code=null`；不等于任务成功。
- `completed`：自然退出，如实返回退出码；非零退出不伪装成功，信号退出不编造退出码 0。
- `terminated`：明确终止指定进程；`timeout`：显式运行时限到期并已终止。两者与自然完成分开显示。
- `cancelled`：本次工具调用或等待被取消，不表示进程已停止；已启动且仍可续接时必须保留 `session_id`。取消前尚未执行的调用不启动进程，返回未执行原因与空句柄。
- `error`：参数、启动或交互操作失败；错误本身不表示已有进程必然退出，不应因此自动删除仍有效的会话。

新工具每次返回的输出只来自本次取走的待取部分。截断必须设置 `truncated=true`，被省略的部分不承诺下次补发。结果 JSON 与可选展示字段继续分开。

TUI 和行式输出都应明确显示“进程仍在运行／会话编号／实际结束状态”。取消时显示“已停止当前工作，已启动的进程仍由会话管理”，并列出仍有效的编号，不能把“已取消”显示成“进程已终止”。一次工具调用结束不等于进程结束；`write_stdin` 的展示应关联原命令，不能伪造一条新命令。恢复历史中的 `running` 只表示当时状态，不展示为当前活会话。

## 4. 生命周期、取消与资源边界

| 事件 | 建议处理 |
|---|---|
| 工具等待到期或用户轮正常完成 | 可续接进程继续运行，由当前对话持有；后台继续读取输出 |
| 下一用户轮 | 继续使用同一管理器和有效句柄；不重新启动进程 |
| 用户取消当前轮 | 停止 AI 本轮工作和当前工具等待，不再执行同批剩余调用；所有已启动进程继续由会话管理，包括本轮新建和正在交互的进程，不自动发送中断或终止 |
| 模型请求失败或达到 8 次请求上限 | 保留已启动的持续进程，不自动重试、不发第 9 次请求；宿主提示仍有效的句柄，允许下一轮继续处理 |
| `terminate=true` | 终止目标进程组并回收，返回已收集的输出与终止状态；不影响其他会话 |
| 显式 `timeout_ms` 到期 | 后台按启动时固定的截止时间终止并回收，报告 `timeout`；即使没有后续查询或当前用户轮已取消也持续生效，查询和输入不延长时限 |
| 进程自然退出 | 后台回收子进程并收尾输出，最后一批结果查询后移除记录；清理输出通道不能无限等待继承管道的后代 |
| 对话恢复／切换成功 | 关闭旧对话的全部进程；新对话从空管理器开始。恢复失败或用户放弃切换时不误杀旧进程 |
| `/save` | 只保存历史，不改变活进程归属，也不保存可恢复的控制对象 |
| 宿主正常退出，包括 TUI Ctrl+C | 显式关闭全部进程并回收，再完成会话排空和退出；不能只依赖析构，因为 TUI 入口使用 `process::exit` |

取消沿用原有触发键和取消后不再执行同批剩余调用的规则；行式 REPL 执行期间 Ctrl+C、TUI 的 Esc 仍取消当前轮，但不再自动终止已启动进程。TUI 的 Ctrl+C 则是退出宿主，须清理全部进程。通过 `write_stdin` 发送的 Ctrl+C 字符只针对指定进程，与宿主按键的含义分开。未执行调用仍按对应结构保存取消原因，保持调用与结果配对。

持续进程使用自己的生命周期状态，不能直接长期共享会被下一轮复位的全局取消标志。取消、查询、退出和终止之间的竞态必须串行更新同一条记录；等待进程或读写期间不持有整个管理器的全局锁。取消发生在启动前则不启动；已经启动则必须登记并保留句柄，不能因停止等待而漏管。管理器关闭后拒绝新启动，退出与在途启动并发时不能留下漏管进程。

资源建议：

- 每个对话最多 64 条会话记录，包含已退出但尚未取走最后输出的记录；已完全消费的终态及时移除。无空位时拒绝新启动，不自动杀死旧服务腾位；让 AI 明确查询收尾或终止不用的会话后再启动。这与 Codex 的清理策略不同。
- 每个进程只保留一份最多 1 MiB 的待取输出缓存，超限保留头尾并明确标记；查询取走后不再在缓存中保留。已返回内容复用现有会话历史，进程结束时只返回最后待取部分，不另做此前全部输出的汇总，也不另建永久输出日志或常驻完整副本。
- 每个进程的读取和等待任务数量固定；自然退出、明确终止、显式超时或启动失败时关闭相关描述符并回收。普通轮取消只停止当前交互，不能关闭进程或后台读取任务；不能每查询一次就留下一个后台线程。
- 默认等待 10 秒与空查询最多等待 300 秒都不是进程寿命。总运行时限仅按 §3.1 的独立规则处理，不再以旧同步默认超时限制所有进程。

工作目录仍不是沙箱。继续使用当前执行环境的权限，不增加权限提升参数；普通用户轮新增工具时，记忆内部合并轮仍只能使用原受限工具。工具输出经过已有终端显示过滤，PTY 控制序列不能借展示影响宿主终端。进程主动脱离受管理进程组及宿主遭强杀后的清理不作首版保证。

## 5. 实施步骤与对应验收

**以下步骤已于 2026-10-22 获准实施完毕；实测与证据见 §8。**

| 步骤 | 计划修改 | 验收标准 |
|---|---|---|
| 1. 固定接口与行为变更 | 依据审核结果补齐 003／005／006 等契约，明确旧同步及取消语义被替代，取消旧时限上限，记录相对 Codex 的取舍；先确认相关测试基线 | 所有调用默认可续接，10 秒只控制返回；正整数时限与截止时间的安全校验明确，旧调用方完成适配 |
| 2. 打通管道会话与查询 | 在 `exec.rs` 邻近新增最小进程管理模块；先做句柄、后台收集、等待返回、查询、退出回收、独立超时计时与容量限制 | 证明进程先返回后继续执行；无后续查询也会按显式时限终止，查询不重置时限；输出增量与非零退出码正确；按新契约调整旧同步断言，未涉及的断言保持 |
| 3. 补齐 PTY、输入和停止 | 复用已锁定的 `libc`、已有进程组控制思路，参考调研固定提交的必要 PTY 实现；实现控制终端、中断及强制终止 | 真实程序检测到终端、收到换行回答后继续；忽略 Ctrl+C 的程序能被主动终止；输入阻塞可取消 |
| 4. 接入工具循环与宿主 | `prompt.rs`／`turn.rs` 注册与分派；`main.rs`／`tui_host.rs` 持有跨轮管理器，把取消等待、终止进程、关闭会话分别接入 | 两种用户轮均可调用；取消后本轮新建及既有服务均继续运行，指定终止只影响目标，关闭会话清理全部；记忆内部轮拒绝；8 次／32 条限制和调用配对继续成立 |
| 5. 接入状态展示与恢复 | 沿用 `TurnNotify`、历史可选展示数据和现有 TUI 投影；仅补新状态与原命令关联 | 实时显示与历史事实一致；运行中不误报完成，恢复旧会话不重放、不连接失效句柄；旧会话仍可加载 |
| 6. 完成验证与交付 | 按仓库开发流程加固、审查、修复并做最终全量验证，回填相关记录和规格状态 | 五项能力缺口全部通过自动验收，未执行／不支持部分如实报告，等待用户验收 |

## 7. 已定案事项与首版暂定值

1. **默认可续接。** 省略 `yield_time_ms` 仍按 10 秒等待返回；旧调用方与同步测试按新契约调整，不保留显式开启的旧方案。
2. **首版只做 Linux，同一对话跨轮保留。** Linux 容器执行属于首版；不做跨宿主重启恢复与 Windows 原生命令执行，正常关闭执行会话时清理其进程。
3. **取消当前轮与终止进程分开。** 取消只停止本轮工作及等待，不自动杀已启动进程；保留 `terminate` 指定终止入口，关闭执行会话清理全部；界面必须明确区分三个动作。
4. **满额拒绝新建，先用一份待取缓存。** 保留旧服务，不自动淘汰；查询取走后缓存不保留旧输出，结束时不再汇总此前全部输出；缓存超限明确标记截断。
5. **总运行时限独立计时。** 省略 `timeout_ms` 不设固定总时限；显式传入正整数时，从成功启动计时，到期终止并报告超时，无旧的 60 秒上限；非法或无法安全表示、计算截止时间的数值拒绝执行。计时不依赖查询，也不因读取输出而重置。

首版暂定 64 条会话、单份缓存 1 MiB、单次输入 64 KiB，随整体计划一次审核；输入超限明确拒绝且不部分发送。运行时限已按 §3.1 定案，不再列为待决事项，也不能用 10 秒等待代替进程寿命规定。
