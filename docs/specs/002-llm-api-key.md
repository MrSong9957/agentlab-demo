# LLM API 配置与模型目录

## 1. 目标

统一管理厂商、请求地址、请求协议、Key 和模型，支持手动修改与自动更新。本文只负责配置与模型目录；统一数据、协议适配、请求执行、会话等其余接入能力按整体方案 `1.md` 实现。

**数据与保存：**

- **结构体：**厂商记录配置 ID、请求地址、协议、鉴权方式、Key 引用和模型列表；模型记录 ID、显示名称、`disabled`，以及已知能力：支持的参数、上下文长度和最大输出。查不到的能力留空表示未知，不按模型名称猜。
- **字典：**以厂商配置 ID 查厂商；模型按“厂商配置 ID＋模型 ID”识别，不能靠显示名称匹配。
- **手动配置：**铺开保存，方便人修改；只写需要覆盖或新增的内容。
- **自动目录：**程序读取内置资料、同步公共目录或查询厂商后生成，记录来源、更新时间和查询时的连接身份。连接身份＝地址、协议、凭证名＋实际凭证的本地不可逆指纹：凭证名只负责定位凭证，指纹识别实际 Key，同名引用下换了 Key，身份就算变了。自动目录不保存原始 Key。
- **最终字典：**运行时合并生成，供程序查询，无需单独维护。
- **Key：**单独放环境变量或凭证文件，配置只保存引用；运行时读取真实 Key。程序启动时读取项目根目录 `.env`（KEY=VALUE）补充环境变量，已存在的变量不覆盖。

**地址含义：**

配置里的请求地址统一是基础地址（如 `https://api.example.com/v1`），不包含接口路径。对话接口路径由适配器按协议补全，模型列表路径由目录查询按协议补全；全程序只有这两处拼接，避免重复拼接。发送前校验地址：必须是合法的 http(s) 绝对地址，远程主机要求 HTTPS，仅本机地址（127.0.0.1/localhost/::1）允许 HTTP 供本地测试；不做域名白名单，合法 HTTPS 不代表域名可信或没有拼错。

**合并规则：**

1. 先合并厂商连接信息（内置资料、公共目录、手动覆盖），得到生效的地址、协议和凭证身份。
2. 再按这个身份筛选自动查询名单：只保留身份一致的名单，不一致的旧名单排除，不能先整套复制进来再用。
3. 最后合并模型信息，叠加手动覆盖：按厂商配置 ID、模型 ID 找条目，相同条目只覆盖手动明确写出的字段，不存在就新增。

未写的字段沿用自动值。写 `disabled = true` 隐藏模型；删除手动覆盖字段恢复自动值，不会删除自动目录里的模型。覆盖与禁用方式参考 OpenCode。[OpenCode](https://opencode.ai/v2/docs/providers?utm_source=chatgpt.com)

基础资料和查询名单分开对待：名单因身份不一致失效时，只排除名单，不动该入口的基础连接信息。

**请求路由：**

1. 用“厂商配置 ID＋模型 ID”查最终字典，得到本次使用的配置。
2. 按协议找到对应的适配器。
3. 检查密钥能读到、模型未禁用，并按能力过滤参数：已确认不支持的参数发送前明确报错；能力未知不算不支持，不带这些可选参数的基础对话照常发送。
4. 全部通过才发起请求。

本次调用开始时固定生效配置和已读取的凭证，本轮重试不重新读取外部配置或 Key；目录刷新只影响之后的请求，不改变正在执行的请求。

**自动更新：**

1. 内置资料兜底，从公共目录同步基础资料。例如 Models.dev，无需厂商 Key。[GitHub](https://github.com/anomalyco/models.dev/blob/dev/README.md?utm_source=chatgpt.com)
2. 先合并厂商连接信息（内置资料、公共目录、手动覆盖），得到生效的地址、协议和凭证身份；按读取到的实际凭证算出指纹，再查询该厂商的模型列表；有分页就读完整。
3. 查询成功后把结果转成统一字段、校验，替换该入口的旧名单并更新自动目录，再按“合并规则”重新合成最终字典。厂商返回合法空列表就把名单记为空；查询失败或分页中断不算空名单。条目缺少 ID、空页却声明还有更多、游标不前进、分页超过 100 页，都按查询失败处理，不替换名单。
4. 查询失败只沿用同一入口、同一身份的旧名单，并提示刷新失败；换过地址或凭证（含同名换 Key）后查询失败，不能套用原名单。

查询必须先知道地址。请求地址由内置资料、公共目录或手动配置提供，不能靠模型列表接口发现新地址。

## 2. 边界风险

- **查询能力不同：**有 Key 不代表有模型列表接口；不支持查询时，仍允许手动配置。
- **配置不完整：**地址、协议、凭证或模型 ID 缺失、格式错误时，说明具体原因，不发送请求。手动配置出现无法识别的字段按格式错误处理，拼错字段名不能被静默忽略（`request_params` 里的扩展参数不受此限）。
- **更新失败：**超时、鉴权失败、限流、解析错误或分页中断，不能当作“厂商没有模型”，也不能写入半份名单。
- **缓存用错：**换地址、换凭证或同名引用下换了 Key，身份都不再一致，不能沿用旧名单。
- **Key 泄露：**Key 不写入日志、自动目录或 Git；普通日志不输出 Key 或指纹；同步公共目录时不携带厂商 Key。

## 3. 关键判断

- **字段覆盖：**手动明确填写的字段优先；未填写不等于空字符串或 `false`。
- **按能力发参数：**可选参数只在模型能力已确认时发送；能力未知不自动添加，要用就先在手动配置补上已确认的能力。上下文上限未知时不猜测，服务端返回超限错误时明确提示。
- **区分资料和名单：**公共目录提供基础资料，厂商查询更新该入口的名单与返回字段；没返回的能力信息不能凭空补造。
- **完整保存：**校验后先写临时文件，成功后替换旧文件，避免中途退出损坏目录。
- **保持用户选择：**刷新不自动切换默认模型；已选模型不可用时明确报错。
- **真正接通：**能查到模型不等于能成功对话，最后要用所选配置发送一次真实请求。

## 4. 踩过的坑

本轮讨论确认的误区：

- **把手动和自动当备份：**它们是两路输入，最终字典是合并结果。
- **把“获取模型”当实时查询：**软件可能只是读取内置目录。DeepSeek Harness 的内置厂商就读取安装好的目录，自定义厂商才尝试查询接口。[GitHub](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/providers.md?utm_source=chatgpt.com)
- **把 `401` 当接口存在的证据：**它只说明认证被拦住；猜测的路径是否支持列表查询，还得查官方文档。

## 5. 预测 → 实测

落地顺序：先手动配置一个厂商并完成一次真实对话，再扩展多厂商与自动目录。

先写预期，再运行程序核对。**实测标注区分两类证据：本地 = 单元/集成测试（mock HTTP 驱动真实业务代码，共 22 个用例）；联网 = 真实厂商 API（DeepSeek）。**未执行项保持“待测”。

| 操作 | 预期结果 | 实测 |
|---|---|---|
| 同一 ID，只手动改地址 | 地址用手动值，未覆盖的连接字段沿用基础值；原入口查询所得的自动名单失效 | 本地通过 |
| 删除地址覆盖字段 | 恢复自动地址 | 本地通过 |
| 写 `disabled = true` | 模型不可选择，自动目录中的记录仍在 | 本地通过 |
| 手动新增模型 ID | 加入最终字典，不覆盖其他模型 | 本地通过 |
| 已选模型写 `disabled = true` 后发起对话 | 路由检查拦截，报错且不发送请求 | 本地通过 |
| 模型列表分多页返回 | 收齐后保存；中途失败不写半份名单 | 本地通过 |
| 查询超时或 Key 无效 | 保留同一入口、同一身份的旧数据，提示失败 | 本地通过（401/500）；真实 401 已验证；超时待测 |
| 更换地址或 Key | 重新查询，不套用原入口或身份的旧名单 | 本地通过 |
| 换地址或凭证后刷新失败 | 身份不匹配的旧名单被排除，不套用原名单，提示失败 | 本地通过 |
| 环境变量名不变，只替换实际 Key | 凭证指纹变化，原查询名单失效 | 本地通过 |
| 刷新成功取得完整名单 | 该入口旧名单被替换；合法空列表把名单清空 | 联网通过（DeepSeek 名单已替换）；空列表本地通过 |
| 对话进行中刷新目录 | 当前请求仍用原配置完成，结果不受影响 | 本地通过（并发测试） |
| 模型只有 ID、能力未知 | 仍能发起基础对话，不自动添加未知可选参数 | 本地通过 |
| 选择模型发送一次对话 | 地址、鉴权和模型 ID 正确，能读到模型回复 | 联网通过（真实对话、PTY 交互、错 Key 401 均验证） |

这是结合成熟产品机制确定的本项目方案，各 Agent 的具体合并规则并不完全相同。
