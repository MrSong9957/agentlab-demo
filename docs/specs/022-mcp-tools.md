## 1. 目标与范围

让用户配置的 MCP 服务器成为外部能力的统一入口，完成：**配置并启用服务器 → 连接与发现工具 → 向模型声明函数 → 按注册表调用真实服务器 → 保存结果并供模型继续任务 → CLI／TUI 显示与恢复**。

首版支持本地 **stdio** 与远程 **Streamable HTTP**，复用官方 Rust MCP SDK `rmcp` 的协议、传输、请求关联和取消接口。本项目只补配置、工具注册、Chat Completions 适配与宿主生命周期，不自行实现 JSON-RPC 客户端，不整体引入 Codex core／App Server。

| 本次范围 | 后续另定范围 |
|---|---|
| 用户私有服务器配置、显式启用、环境变量凭证、工具允许／禁用名单 | 项目级配置、多层合并、插件市场、自动安装服务器、OAuth 登录与凭证刷新 |
| `initialize` 生命周期、完整分页 `tools/list`、串行 `tools/call`、工具目录变化通知 | 2026-07-28 `server/discover` 生命周期、MRTR 多轮输入、MCP Tasks、并行工具执行 |
| 结果 JSON 回传、错误与取消、会话记录、工具活动展示 | MCP 图片／音频的多模态投影、组件 UI、服务器事件订阅界面 |
| `/mcp` 状态、空闲时 `/mcp reload` 重新连接与发现 | `list_mcp_resources`／templates／read、prompts、`tool_search`、JavaScript 编排、通用权限审批系统 |

成功须由真实 MCP 服务收到预期 `tools/call`，且下一次模型请求包含对应调用及真实结果证明。只出现工具名、初始化成功或终端上的「调用成功」不能算接通。

性能维度（2026-10-24 增补）：接入不得为未使用 MCP 的用户引入可感知固定延迟；每轮准备（`prepare_for_turn`）中为通知可见性而设的等待必须是条件性的——仅存在活动连接且确有在途通知消费需要时发生，无 MCP 配置时零等待。性能基线、瓶颈证据与验收目标见[性能记录](../records/2026-10-24-022-mcp-performance.md)（工具归档 `scripts/perf/`，原始数据 `docs/testing/perf/022/`）。

## 2. 行为契约

### 2.1 配置、启用与凭证

首版只读取 `catalog::user_dir().join("mcp.json")`，沿用 `TCHAT_USER_DIR` 的测试覆盖；不新增配置根环境变量。该文件保存可执行命令和外部连接的明确选择，故与项目根 `config/` 下的模型目录分开。仓库内的示例、AGENTS、服务器返回内容及模型工具参数都不能新增或启用服务器。

文件缺失等同无 MCP 配置：不创建文件、不启动进程、不连接服务器，既有原生工具面保持原行为。JSON 顶层固定为 `mcp_servers` 对象，以服务器 ID 为键；拒绝未知配置字段、空白 ID／工具名、重复 JSON 键和错误类型，不用后一个同名字段覆盖前一个。

```json
{
  "mcp_servers": {
    "local_docs": {
      "enabled": true,
      "command": "/opt/mcp/docs-server",
      "args": ["--root", "/workspace/docs"],
      "cwd": "/workspace",
      "env_vars": ["DOCS_INDEX_TOKEN"],
      "enabled_tools": ["search", "fetch"],
      "startup_timeout_sec": 30,
      "tool_timeout_sec": 300
    },
    "remote_docs": {
      "enabled": true,
      "url": "https://mcp.example.com/mcp",
      "bearer_token_env_var": "DOCS_MCP_TOKEN",
      "env_http_headers": {"X-Tenant-ID": "DOCS_TENANT_ID"},
      "enabled_tools": ["search"],
      "disabled_tools": []
    }
  }
}
```

这是字段示例，路径和服务器均为占位，不是安装说明或可用服务承诺。

| 字段 | 首版规则 |
|---|---|
| `enabled` | 可选，默认 `false`；只有用户私有文件中显式 `true` 才连接。启用表示允许启动该服务器并调用筛选后的工具；不依据服务端 `readOnlyHint` 等提示授予权限 |
| `command`、`args`、`cwd` | stdio 专用。`command` 与 `url` 恰选一个；直接按程序和参数数组启动，不经过隐式 shell。`command` 支持绝对路径或从受控 PATH 查找的程序名；`cwd` 必须是已有绝对目录，省略时固定为本次宿主启动目录。带路径的相对 command 拒绝，避免受工作目录变化影响 |
| `env_vars` | stdio 专用，字符串数组，默认空；仅转交列出的宿主环境变量，缺失时该服务器准备失败。基础进程环境按 Codex 的平台白名单构造，先清空继承环境，不转交整份 `.env`、模型 Key 或其他服务器凭证；不提供内联秘密字段 |
| `url` | HTTP 专用，完整 MCP 端点，不拼接 `/mcp`；合法 http(s) 绝对地址，无 userinfo／fragment。远程 HTTPS，仅 localhost／127.0.0.1／::1 允许 HTTP，与 002 的地址边界一致；禁止自动重定向 |
| `bearer_token_env_var`、`env_http_headers` | HTTP 专用，均只保存环境变量名；初始化前读取实际值。未配置认证字段可匿名连接，配置后缺失／空值则失败，不能降为匿名。header 名按 HTTP 规则校验、大小写无关去重，拒绝换行；Authorization 只能有一个来源，Host／Content-Length／Connection／Accept／Content-Type／MCP-Protocol-Version／MCP-Session-Id 由传输层管理，不允许覆盖 |
| `enabled_tools`、`disabled_tools` | 按服务器返回的**原始工具名**精确筛选；允许名单缺省＝全部，显式空数组＝零工具；禁用名单优先。同名工具在不同服务器独立筛选。允许名单里的未知项在状态中提示，不生成假工具 |
| `startup_timeout_sec`、`tool_timeout_sec` | 正整数秒；缺省分别 30、300，来自本次 Codex 基线。拒绝零、负数、非整数和无法表示的截止时间。初始化及首次完整发现共用启动总时限；单次调用总时限不因进度消息延长 |

跨传输字段混用按配置错误拒绝；停用条目仍校验配置结构，但不解析凭证、不检查程序是否安装、不发网络请求。文件结构错误不发布任何新配置；单个结构合法服务器的凭证、启动或发现失败只让该服务器不可用，其余服务器及原生工具照常使用。

凭证只绑定本次具体连接，MCP 不复用模型提供方的 Key 或 origin 授权记录。客户端状态、错误、stderr 和诊断不输出已解析凭证、完整认证头或指纹；宿主不把配置及认证值写进工具定义、会话或记忆。程序未来若写入私有文件，复用现有 0700／0600 与原子替换规则；本功能不自动改用户配置。

显式启用是该服务器的启动及筛选后工具调用授权，首版不再逐次审批。stdio 以宿主用户身份运行，不提供文件系统或网络沙箱；环境白名单只控制自动转交的数据，不构成进程隔离。可执行文件与参数、工作目录、HTTP 端点均来自上述用户配置，服务器返回内容不能改变它们。

**凭证回显处理（2026-10-24 用户明确选择）：拒绝受污染数据。** 每个连接在准备时固定敏感值集合：Bearer 及 `env_vars`／`env_http_headers` 显式引用的非空实际值均按敏感值处理，不按变量名猜测，不遍历其他宿主环境变量。服务器定义、结果及诊断在进入模型请求、会话／记忆、展示或普通日志之前检查；认证值和其已发送认证头形式不得透传。污染的工具定义不发布并报告通用原因；污染的调用结果整份替换为 §2.4 的标准客户端错误，若调用已经发出则标明外部执行状态未知，不保留或显示原始回包。污染的错误／stderr 只保留通用诊断，不在提示中回显匹配值、原始片段或指纹。检测须先于截断，并覆盖跨读取块的回显；不能保证安全检查的诊断原文不输出。未受污染的标准业务数据继续按 §2.4 保留；这不是任意第三方秘密识别器，也不扫描原有用户历史。

### 2.2 连接、发现与动态更新

宿主持有一个 MCP 管理器，在首次普通用户轮准备时或显式 `/mcp reload` 时加载配置；帮助、模型目录、会话列表与单纯恢复展示不触发 MCP 启动。连接在普通用户轮之间复用，内部记忆轮不创建管理器或触发发现。

1. 按固定服务器 ID 顺序准备启用条目；每台服务器只保留一个当前连接，准备过程可取消。首版不增加后台预热、无限重连或每次调用新建 runtime。
2. 使用 `rmcp` 的 **Initialize** 生命周期，显式选择 `LATEST_WITH_INITIALIZE`（该 SDK 中为 `2025-11-25`），协商范围限定其已知的 initialize 版本；不使用默认的 `LATEST`。不兼容版本或未声明 tools 能力的服务器记为不可用；声明 tools 能力后返回空目录则是就绪、零工具。
3. `tools/list` 读到 `nextCursor` 缺省为止；游标是 opaque 字符串，空字符串也可作为游标传回，不能当成结束。沿用 Codex 的总计 ≤100 页、≤2048 项、游标 ≤64 KiB、已见游标重复拒绝及整体时限。失败不发布半份目录。
4. 先完成同服务器原始名字去重、定义校验、名单过滤，再生成模型名。原始名字重复属于服务目录错误，不能让后一条覆盖前一条。单项定义不受支持时排除该项并报告具体原因，其余有效项可用。
5. 每个普通用户轮开始时冻结一份**工具定义＋原始身份映射＋连接句柄**快照；所有本轮模型请求和实际分派共用它。服务器断开时返回不可用错误，不改绑另一个连接，也不从历史工具名反推身份。
6. `notifications/tools/list_changed` 只标记目录过期，在下一普通用户轮准备时完整重列该服务器。通知不插入聊天、不请求模型、不改变当前轮已声明的集合；刷新失败后该服务器在新轮不可用，不能装作最新目录成功，显式 reload 可恢复。通知计数的读取基准必须在重列**列出之前**取得（重列期间到达的新通知保留到下一轮，不被发布清除）；为同步计数而设的等待是条件性的：无 MCP 配置或无活动连接时为零等待，有活动连接且需要消化在途通知时的等待时长计入轮准备耗时（2026-10-24 方案 A 固化；无近期调用时收到主动通知的情形同样必须被下一轮重列覆盖）。

重列期间收到的新通知必须保留过期标记，不能在发布本次结果时误清除；至多每轮重列一次，后续变化留到下一轮，不形成无限刷新。准备被用户取消时结束本轮、不发送模型请求，关闭仍在初始化的候选连接及其进程，不发布半份目录；已经就绪的健康连接可保留。业务 `isError` 不等于断连；确认断开的连接不在后续新轮声明工具，只有显式 reload 才重连。

客户端不声明 sampling、roots、elicitation 或 Tasks 能力。服务器仍反向请求采样、根目录或用户问询时返回 method-not-found，既不调用模型，也不读取工作区或转接 018；ping 及已支持的目录变化通知由 SDK 正常处理。这里覆盖 SDK 默认 roots 返回空集合、默认 elicitation decline 的行为，是本项目的明确拒绝策略，不声称是上游默认值。

`/mcp` 只读显示配置加载状态、每台服务器的启用／连接状态、可用模型名与原始名、过滤数量及脱敏错误。`/mcp reload` 只在空闲时执行：运行中明确返回忙，不等待历史长锁或打断现有调用。`/refresh` 继续只负责模型目录。

reload 先完整解析新配置，再替换连接和目录；解析失败明确保留原配置，并提示「未应用新配置」，首次加载失败则保持无 MCP 工具。合法新配置中的移除／停用立即生效，关闭旧连接；新连接失败也不回用已删除或身份已改变的旧配置。身份包括传输、程序／地址、参数、cwd 和实际凭证，比较仅在内存中进行，不把指纹输出或落盘。首版允许 reload 重建全部启用连接，不要求跨版本连接复用优化。

### 2.3 模型声明、名称与执行隔离

通过现有 Chat Completions `type:"function"` 声明每项 MCP 工具，直接暴露其参数对象，不增加 `call_mcp_tool(server, tool, arguments)` 通用代理。

- 通常模型名为 `mcp__<server>__<tool>`；保留原始服务器 ID 和工具名用于协议调用。非法字符替换为下划线；发生净化／分隔歧义冲突或超长时附稳定短哈希并截断可读前缀，最终名称符合 `[A-Za-z0-9_-]{1,64}`。短哈希基于原始 `(server, tool)` 身份，使用现有 sha2；同一目录不同枚举顺序结果一致，剩余冲突显式拒绝，不覆盖注册表。
- 64 是本项目 Chat Completions 的上限；Codex 基线中的 128 不能直接照搬。模型定义、分派、保存和展示使用同一个最终名字；只按映射精确查找，禁止拆 `__` 或只检查 `mcp__` 前缀后转发。带首尾空白的调用名仍按 006 原样保留并拒绝，不做 trim 后执行。[Chat Completions 函数定义](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)
- 描述和 `inputSchema` 来自当前服务器，并先经过 §2.1 的凭证污染检查。首版保持普通 JSON Schema 的字段和约束，不开启 strict，不为迁就模型删 required／enum／`$defs` 或压缩 Schema。Schema 本身必须是 JSON 对象，根 `type` 缺省或为 `"object"`；显式其他根类型拒绝，`properties` 必须是对象，缺省／null 按 Codex 补空对象。其他 SDK 无法表示的结构排除该工具并说明。不在客户端新增完整 JSON Schema 执行验证器；嵌套业务值可为任意合法 JSON，约束校验由服务器负责。
- 宿主只从当前快照取得连接 URL、凭证、服务器身份及宿主 `_meta`，不从模型 arguments 解释这些配置。业务 Schema 中若包含 URL 等同名字段，仍按普通业务数据转交已选服务器，不改变客户端路由。有效 JSON 的根非对象是参数错误，在网络发送前返回失败；对象中的业务字段不被宿主擅自重写。
- 工具按原始身份稳定排序，追加在现有原生工具之后。首版本地工具总数上限取 128（含本轮条件原生工具，属于本项目边界，不承诺所有提供方都支持此数量）；超过时在模型请求前明确报错，请用户缩小名单，不静默截断。完整请求继续受现有 10 MiB 限制。
- 普通 `User`／`UserWithMemory` 轮可使用 MCP；MemoryMerge／内部提炼既不声明也不执行。执行层再次校验当前模式、快照命中及筛选结果；伪造名、停用项和其他轮快照的新增名零外部调用。原生同名如 `exec_command` 不会被 MCP 替换。

服务器 instructions、工具描述和结果均为外部资料。首版不把服务器 instructions 提升到 system／AGENTS，也不据其启动程序、读文件、授权或回答 018 问询；模型获得业务指引的入口是工具描述和正常结果。

### 2.4 调用、结果与取消

继续使用 006 的串行工具循环：先完整校验 assistant 批次，再入史和按序执行；保留每用户轮 8 次模型请求、每批 32 项、原始 call ID／name、不自动重发和第 8 批先保存全部结果的语义。MCP 初始化、目录发现和取消通知不消耗模型请求额度，MCP 工具调用与原生工具可在同批混用。

一次分派只发送一次业务 `tools/call`，参数为映射中的原始工具名及解析后的对象。CC call ID 与 MCP JSON-RPC request ID 属于不同协议，由 SDK 关联后再回填原 CC call ID；不能用工具名字匹配响应。HTTP 客户端关闭重定向及工具 POST 自动重放；固定 SDK 的 `reinit_on_expired_session` 显式设为 `false`，认证失败、404 会话失效、连接中断均返回错误，由用户 reload 后续新调用。

使用 SDK 单次请求／可取消请求入口；不使用会自动驱动 MRTR 的高层 `call_tool`。只接受普通完成结果（`resultType` 缺省或 `complete`）；`input_required`、Task 等后续交互响应作为不支持的协议响应失败，不驱动后续业务请求或偷偷开放客户端能力。

| 情况 | 历史及下一请求中的结果 |
|---|---|
| 正常 MCP 响应 | 先按 §2.1 检查凭证污染，再将标准 `CallToolResult` 序列化为 `role=tool.content` 的 JSON 字符串；保留 content 顺序、`structuredContent`、`isError` 和服务端 `_meta` 的数据语义，不只取第一段 text。缺省 `isError` 不擅自改成服务端明确返回了 false |
| 服务端 `isError:true` | 原样作为工具失败回传，模型可继续；不能把 HTTP／JSON-RPC 成功误画为业务成功 |
| 本地参数、未注册／停用、断连、协议或认证错误 | 返回标准失败形态 `{"content":[{"type":"text","text":"MCP 客户端错误（原因）：说明"}],"isError":true}`；区分调用未发送与已发送但执行状态未知。非法 arguments 属工具参数错误，不升级为整批协议错误 |
| 用户取消 | 发送前取消＝未调用；发送后尽力发对应 MCP 取消通知，立即停止本地等待，已发调用说明远端执行状态未知。补齐同批剩余未执行结果，保存后结束本轮，不继续请求模型 |
| 调用超时 | 尽力取消并返回超时／远端状态未知错误，按普通工具失败继续循环；不自动重试、不伪造回滚或终止远端成功。进度通知不重置总截止时间 |
| 回包含本连接敏感值 | 原回包不入史、不展示、不写普通日志；仅返回标准客户端错误及已发调用的状态未知，不自动重试或声称外部操作失败／撤销 |

取消通知自身也须有界，不因服务端不读输入而阻塞本轮结束；直接使用 SDK 的请求句柄／取消接口，并在本地等待侧绑定现有取消标志。等待侧结束不依赖通知 I/O 完成，通知发送任务最多存活 1 秒后回收；宿主退出同样收口。迟到结果按请求关联丢弃，不追加第二条 tool 结果、不污染下一轮。普通取消保留管理器，其余健康连接可复用；已关闭连接只有 reload 才重新启动。

首版支持 SDK 标准的 `text`、`image`、`audio`、`resource`、`resource_link` 五种内容块，按 JSON 数据回传；图片／音频的 data 保持编码字符串，不自动转成 user 附件，不打开 URL 或触发资源读取。`structuredContent` 可为任意 JSON 值，显式 null 与缺字段区分；`isError` 若存在须为布尔，`_meta` 按 SDK 元数据对象表示。未知内容类型、字段类型错误及无法解码的标准结构使整次调用返回客户端协议错误，不只保留已读 text 或伪造部分成功，原始错误回包不透传；未知扩展字段不承诺超出 SDK 表征的逐字节保真。019／020 原有图片路径照常使用。通过凭证污染检查的业务结果按 007 保存。

接收过程必须有界：stdio 单条 JSON 消息、HTTP JSON 响应体或单个 SSE 事件均以 8 MiB 为首版上限，在完整分配／反序列化前限制；不能仅在结果到手后检查。超限关闭该连接并回报错误，不截断成合法成功。stdio stderr 持续排空，仅保留有界、脱敏的诊断尾部（最多 32 KiB）；stdout 专用于协议。随后请求仍按 006 在完整序列化后检查 10 MiB，不为容纳大结果静默删历史。

### 2.5 展示、保存与退出

- CLI 在实际调用前输出并 flush 现有工具活动行；TUI 使用既有 ToolBegin／ToolEnd 及通用工具详情，显示名称、参数、结果和成功／失败。外部文字先经现有终端过滤，过滤只作用于展示副本。
- MCP 不产生普通 user 消息、通知工具消息或问询回答；与 018 的独立回答通道、019 的批末图片投影、021 的普通输入接续共用完整工具批边界，不在 assistant 调用和配对结果之间插入其他消息。
- 保存复用 V1 的 `AssistantToolCalls` 与 `ToolResult`，首版不增加会话格式、持久连接或凭证字段。恢复只显示已有调用及结果，缺失结果沿用 007 的未知状态；不因 `/resume` 重启服务器、补调工具或重放副作用。没有配置仍能读取旧工具记录。
- `/resume` 后下一次用户提交重新取得当前管理器快照；旧历史是事实记录，不能自动赋予当下执行权限。MemoryMerge 仍只得到原有受限工具，不转交 MCP 配置或认证数据。
- 宿主退出显式关闭全部 MCP 连接；stdio 关闭 stdin 后给予有限退出等待（沿用上游 3 秒），再终止并回收进程组和读取任务。TUI 的 `process::exit` 前必须执行清理，不能只依赖 Drop；远程服务只关闭本地连接，不宣称终止远端任务。016 的用户进程会话管理器不接管 MCP 协议进程或暴露其 stdin 句柄。

## 4. 容易误判的边界

- 2026 基线 SDK 的 `LATEST` 已是无需 initialize 的新生命周期；只调用默认构造不能证明实现了本文范围。
- SDK 的 HTTP 会话自动恢复可能重发原 POST；仅在本地 turn 写「不重试」无法保证业务调用一次，必须配置传输层并检查服务器收到的次数。
- 取消请求句柄不等于远端已停止。超时、断线或退出前发出的写操作都可能已经发生，记录必须保留未知语义。
- 名字是 API 标识，原始身份是路由依据，CC call ID／JSON-RPC ID 是响应关联；三者不能混用，名字净化也不能兼任终端过滤。
- 内部记忆轮不开放工具，仍不等于普通历史中的 MCP 结果从记忆提炼中消失；沿用现有历史参考边界，认证配置则从源头不进入历史。
- SDK 存在有界 stdio／SSE 辅助并不证明所有 JSON 接收路径都有界；8 MiB 需分别覆盖 stdout、HTTP JSON 和 SSE，不只测最终字符串长度。

以上为调研确认的设计风险，尚无本功能实现失败或性能实测；后续事实写入实施记录。

### 5.2 测试质量与完成条件

- 用真实 rmcp 客户端、真实 turn／API 投影和真实子进程；替身只位于模型与 MCP 服务边界。稳定请求、结果和屏幕用黄金值，并检查服务收到的原始名字、调用次数、文件字节、进程存活和退出码，防止只验证展示或测试空跑。
- 超时以注入时钟／Tokio 受控时间测试，竞态用通道和屏障，不靠睡眠碰概率；随机数据使用固定种子，locale／时区及依赖固定。L3 有界等候只作看门狗，不能代替业务完成信号。
- 关键用例保持断言不变，通过 RED／GREEN 或隔离副本可逆变异证明能检出：遗漏实际调用、错误身份映射、绕过名单／MemoryMerge、把 isError 画成功、只读第一页、过期目录中途替换、取消后迟到入史、404 或 MRTR 隐式多发、凭证污染数据透传、恢复重放及接收限额失效。恢复原始字节并核对，不能接受错误新快照。
- 实施遵守 `TDD → comprehensive-testing → Security Testing Gate → code-review → 全量验证和修复`。安全门禁为必做，按 [Security-Testing-Gate](../../.agents/agents/Security-Testing-Gate.md) 先审实现、再用受控本地服务实测越权分派、认证／凭证污染、参数与终端注入、重定向、超限、取消、跨轮快照及进程回收；不访问真实账号或第三方端点。最终报告保存到 `docs/security/reports/YYYY-MM-DD-022-mcp-tools-security.md`，同名已存在时另取后缀，不覆盖。
- code-review 也是必做门禁：实施完成后固定实际合并基线，按仓库标准与本规格两个轴审查实际差异、契约和范围；报告 findings 与未验证项。此准备轮没有程序差异，不执行或声称通过代码审查／安全门禁；后续任一阶段出错用 `diagnosing-bugs` 定位，修复后复验受影响项及最终全量。
- 真实完整验证入口按 [README](../../README.md) 与[后端回归说明](../testing/backend-regression.md)，在 `/workspace` 运行 `cargo check --locked --offline && cargo test --workspace --locked --offline --no-fail-fast`。覆盖 AGENTS.md §7 相同 workspace 全集，额外固定锁文件与离线依赖；须预先备好 Cargo.lock 对应缓存，不以联网账号或放宽 flags 绕过。CLI／PTY 验收纳入默认集合；按实际工具链补适用 lint。报告通过、失败、忽略／跳过、过滤和未运行数量，定向测试不作为交付依据；独立副本的两个 Cargo 命令均须使用副本专用 `--target-dir`。
- V1 与配置兼容通过固定夹具和往返验证；项目没有已采用的公开 crate API 兼容工具，不额外强加。新 MCP 配置不改变旧模型配置，回退旧程序时 MCP 文件不被读取。缺 Windows ConPTY／宿主条件时列出缺口。

本轮只核对内容、命名、JSON 示例、本地链接、固定源码及空白；不运行代码测试或功能门禁。检查结果记录于[同一份调研记录](../records/2026-10-24-022-mcp-tools-spec-research.md)，表中预期均不能当作实测。
