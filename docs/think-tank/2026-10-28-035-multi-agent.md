# 035 多 Agent：计划前调研与复核

- 日期：2026-10-28；倒序调研第 1/6 项。
- 目标：确认并行子任务、取消收尾和可靠记录的实施路径是否完整，不改变冻结功能、容量和验收条件。
- 输入：[035 规格与计划](../specs/035-multi-agent.md)、当前调度/存储/MCP/进程接口；三位专家独立研究，侦察兵独立运行 last30days。
- 结论：**需要补充 M2–M4 的接入与验证细节**。本轮仅静态调研和文档修订，功能仍待实现，测试仍待测。

## 共识

保留现有一层子 Agent、全应用子槽、可信 owner、根单写者、先提交后副作用、原生状态归属和恢复不执行等约束。主要风险在接入现有串行宿主：整轮历史锁、MCP 连接锁与进程创建队列都可能使取消门和事件落盘失效。

## 冲突与裁决

存储专家提出“先过滤子事件，再扣记忆预算”。但 013 与当前读取器采用近期记录先计费、序列化时再过滤的口径，见 [013 输入边界](../specs/013-memory-system-v1.md)及 [rollout_input.rs](../../src/app/src/memory/rollout_input.rs)。本轮不改变其 8 MiB/1 MiB 限额及既有计费语义；改为补洪泛与预算耗尽的降级证据，不能承诺窗外根事实必定入选。

“更强目标”是研究建议，不是新的性能阈值或已完成结果。MCP 短锁与创建队列交接仅用于落实现有 C12/C13，不能借机扩大工具或权限。

## 社区校准

近 30 天样本不足以代表社区共识。[近期实践文章](https://potapov.dev/blog/more-agents-slower-team/)提醒重复上下文、合并和资源竞争会抵消并发收益；[并发研究](https://arxiv.org/abs/2610.10263)也要求按任务区分收益，不能据此预测本项目性能。一个[故障注入研究](https://arxiv.org/abs/2610.10961)报告过进程回收期间取消缺陷，支持保留真实收尾与反证测试。直接支持消息持久化可靠性的近期讨论不足。

侦察兵实际执行两轮 quick 引擎，均退出 0。首轮实际只覆盖 Reddit/YouTube：Reddit 有 403/超时及不相关备用结果，YouTube 为零；第二轮覆盖 HN/GitHub，保留 HN 0、匿名 GitHub 1。quick 会裁为首个子查询、前两个来源；受阻、被裁剪及无结果分别记录，不能混称没有讨论。详见日期、来源和运行证据。

## 组合方案与计划文档检查

| 优先级 | 计划落点 | 修订与验证 |
|---|---|---|
| 1 | M2 | 明确拆分整轮 history 锁；MCP 连接只短暂持锁取得调用能力，模型/MCP 等待期间仍可提交子事件。 |
| 2 | M3 | 明确停止门与进程创建队列的交接；用屏障覆盖等锁/排队时取消，检查取消先赢时零新创建或发送、已受理进程可归属回收、根及兄弟不受损。 |
| 3 | M4 | 明确沿用记忆读取预算口径，增加子事件洪泛与根事实未提取的降级检查，保留来源及真实限制。 |
| 4 | 实施门禁 | 按现行 AGENTS 使用 ce-work、ce-debug、ce-code-review、ce-compound；原 TDD、测试加固、安全、全量和独立验收要求不变。 |

不新增功能或验收编号，不更改 §1、§2、§5 的冻结内容。032 仍须先交付；倒序调研不代表倒序实现。

## 背景知识

停止本地等待、阻止新动作和回收已创建进程是三个边界，必须在真实分派和创建队列上对齐。过滤后的提炼输入较小，也不代表此前的读取窗口没有被子事件占用。
