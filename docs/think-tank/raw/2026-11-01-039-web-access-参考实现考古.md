# 参考实现考古：pi-web-access 底层逻辑与证据

日期：2026-11-01。调研方式：只读拉取上游源码与 npm/GitHub 元数据，未运行任何外部代码。

## 1. 为什么参考它，而不是 pi 上游

- pi 上游（`earendil-works/pi`，原 `badlogic/pi-mono`）核心**刻意不带 web 工具**：内置工具仅 read、write、edit、bash、grep、find、ls（遍历 main 分支 `packages/coding-agent/src/core/tools/` 树证实，无 fetch/search；git 历史按路径查询 `packages/web*`、`tools/fetch.ts` 均无记录）。
- pi 生态的 web 能力由扩展提供；最完整、更新最活跃的是 **`pi-web-access`**（npm v0.46.0，作者 nicobailon，MIT）。同一套核心（`web-tool-core.ts`）驱动两个宿主：pi 扩展＋独立 MCP server——宿主无关核心＋宿主适配层的分层与本项目的模块结构天然对应。
- 包元数据（registry.npmjs.org/pi-web-access，2026-11-01 查询）：关键依赖 `undici`（HTTP）、`defuddle` 0.19.3＋`@mozilla/readability`＋`linkedom`（正文提取）、`turndown`（HTML→Markdown）、`unpdf`（PDF）、`p-limit`（并发）。

## 2. 工具面（三个工具，名称可配置）

| 工具 | 输入要点 | 输出要点 |
|---|---|---|
| `web_search` | query 或 queries（并发上限 3）、numResults、domainFilter（`-` 前缀＝deny）、recencyFilter、provider | 标题＋URL＋摘要列表；返回 `responseId` 供后续取全文 |
| `fetch_content` | url 或 urls（去重）、mode、可选 auth/proxy | 每 URL 一条 `{url,title,content,error,mimeType,status,duration}` |
| `get_search_content` | responseId、offset/limit 或 findText/findMode（exact/case-insensitive/fuzzy） | 从存储副本翻页或全文定位 |

`fetch_content` 的 mode 四值：`readable`（默认，转 Markdown）、`raw`（仅文本类型，原文）、`answer`（小模型读页回答 prompt）、`extract`（按字段结构化抽取）。

## 3. 抓取管线（`extract.ts` `extractContent`，约 550 行起）

1. 解析 URL，仅接受 http/https（ssrf-protection.ts:234）。
2. 请求前校验：SSRF 配置＋域名策略＋UA/curl 配置合法性（extract.ts:571-588，配置非法先于任何 provider 回退失败）。
3. `Accept` 首选 `text/markdown`（`MARKDOWN_FIRST_ACCEPT`，extract.ts:1306）——Cloudflare Markdown for Agents、Mintlify、Vercel 等服务器直接回 Markdown，省提取；协商到的 Markdown 过短（<MIN_USEFUL_CONTENT）则用浏览器 Accept 重取一次（extract.ts:1503-1518）。
4. 重定向**手动循环**（ssrf-protection.ts:283-317）：`redirect: "manual"`，≤5 跳，每一跳重新过 `validateRemoteUrl`；`allowLoopback` 豁免**不**传给跳转目标（308 注释：环回基址不得借跳转转向别的环回源）；可选 `redirects: "same-origin"` 拒绝跨源跳转；303 及 POST 的 301/302 降级为 GET。
5. 大小上限：先查 Content-Length 拒超限；再**流式读边计数**，超限即 `reader.cancel()` 中断（`readResponseBufferWithLimit`，extract.ts:1263-1290）。默认 5 MiB。
6. 超时：AbortController＋timeoutMs；取消信号贯通。
7. 并发：`p-limit` 常数上限（多 URL fetch），搜索查询并发 3。

## 4. 内容类型分支（extract.ts）

| 类型 | 处理 |
|---|---|
| `text/markdown` | 直接采用 |
| HTML | defuddle（readability 类，`markdown:true` 直出 Markdown，linkedom DOM）→ 不足 `MIN_USEFUL_CONTENT` 回退 `@mozilla/readability`＋turndown（extract.ts:1548-1582） |
| `text/*`、JSON、XML、JS | 按响应头 charset 解码原文（`TextDecoder`，extract.ts:1232-1240） |
| PDF | unpdf 提取，独立大小上限（`pdf.maxSizeMB`） |
| 图片 png/jpeg/webp/gif | 受开关门控，返回图片内容给模型 |
| JS 壳页 | 可见文本 <500 字符且可执行脚本 >3 个，或 Cloudflare 质询特征（extract.ts:1183-1194, 1210-1225）→ 报错提示换远端渲染后端 |

特殊路由优先于通用抓取：GitHub 仓库/issue/PR 走 GitHub API，YouTube/本地视频抽帧。raw 模式仅接受文本类型，非文本给出「去掉 mode 重试或用 answer」提示。

## 5. SSRF 防护六则（ssrf-protection.ts `validateRemoteUrl`:232-281）

1. `localhost`、`*.localhost` 主机名拒绝（显式 allowRanges 可豁免 localhost）。
2. IP 字面量直接判公网。
3. 域名本地 DNS 全量解析（`dnsLookup(hostname, {all:true, verbatim:true})`），**每个**地址都必须是公网地址；私网/环回/链路本地全拒。
4. 允许段仅来自配置 `ssrf.allowRanges`，默认空。
5. 每一跳重定向重复全部校验；环回豁免不随跳转传递。
6. 经远程解析型代理（http/https/socks4a/socks5h，代理解析域名）时可跳过本地解析，但必须显式 `ssrf.trustEnvProxy: true`。

校验失败立即返回错误，不发送请求，无降级重试。域名策略（`fetchContent.domainPolicy` allow/deny）独立于 SSRF 层。UA 默认伪装 `OpenAI File Downloader, XaiImageApiFetch/1.0`（ssrf-protection.ts:91），可配；可选 curl-impersonate 后端（`fetchContent.curl`）对抗 TLS 指纹封锁，auth profile 走 Node fetch 而非 curl，防 cookie 上命令行（extract.ts:1315-1317 注释）。

## 6. 搜索后端（duckduckgo.ts 为免密钥保底）

- GET `https://html.duckduckgo.com/html/?q=…`，带自有 UA（duckduckgo.ts:57-71）。
- linkedom 解析 `.result` 节点，跳过 `result--ad`；解码 `uddg` 跳转参数，仅接受 http/https（duckduckgo.ts:42-51）。
- 机器人质询＝202 状态或质询表单节点 → 抛 `DuckDuckGoBotCheckError` 进冷却退避（duckduckgo.ts:79-82）。
- 域名过滤在客户端套用（allow＋`-`deny，duckduckgo.ts:20-40）。
- Provider 机制：约 30 个后端文件（brave/exa/tavily/searxng/jina/openai-search/gemini-search 等），请求可指定 provider 或走默认顺序回退。

## 7. 存储与内联截断（storage.ts、web-tool-core.ts）

- 内联正文默认 30,000 字符（`DEFAULT_MAX_INLINE_CONTENT_CHARS`，web-tool-core.ts:311；下限 1,000，上限 200,000）。
- 截断在行边界切，回退点不低于阈值 80%（`initialContentSlice`，web-tool-core.ts:346-368）；随结果返回 shownBytes/totalBytes/totalLines。
- 全文写磁盘缓存目录 `web-search-cache`：TTL 1 小时、maxEntries 128、maxBytes 128 MiB（storage.ts:9-16）；搜索结果与 fetch 内容都有 responseId/fetchId，`get_search_content` 是模型续读唯一入口。
- `structuredContent` 供程序化调用方（codemode 脚本），永不发给模型或 MCP（web-tool-contract.ts:17-18 注释）。
