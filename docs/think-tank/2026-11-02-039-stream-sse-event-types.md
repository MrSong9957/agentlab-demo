# SSE 事件类型简明规范

日期：2026-11-02。
适用：流式输出功能。计划暂定编号 039。
来源：用户与 AI 讨论整理。2026-11-02 按现有 006/007 契约校对。
标准：ASD-STE100 中文近似，约 80% 达标。
后续：[流式输出简明技术规范（第二部分）](2026-11-02-039-stream-api-host.md)。

## 1. 总则

- SSE 事件是流式处理的最小单位。
- 程序按事件到达顺序处理。
- 程序把事件内容分为三类去向。三类去向是文本片段、工具参数片段和完成事件。
- 三类去向不是完整事件清单。推理、签名、用量和心跳等事件按 024 规则处理。039 不显示推理内容。
- 字节可以任意切开。解码器把字节拼回完整事件。事件不完整时，程序不处理它。
- 程序区分显示与提交。显示不是提交。

## 2. 文本片段

- 文本片段包含要显示的文字。
- 程序收到文本片段后，立即显示它。
- 程序按到达顺序拼接文本片段。
- 拼接结果用于最终文本和历史保存。
- 文本片段有两个去向。第一是显示端。第二是最终文本组装器。两个去向使用同一份文本。

## 3. 工具参数片段

- 工具参数片段包含工具调用参数。
- 程序收到工具参数片段后，只累积它。程序不显示它。
- 程序按 006 规则组装参数。039 不改写组装规则。
- 工具参数片段不进入可见文本。
- 工具参数片段只有一个去向：工具调用组装器。

## 4. 完成事件

- 完成事件表示本次回复合法结束。
- 程序收到完成事件后，先保存 assistant 记录。记录包含文本和工具调用。
- 如果记录含工具调用，程序运行工具。工具结果按 006 规则逐条保存。
- 完成事件是提交边界。边界前，显示归显示，历史不动。
- 完成事件缺失或损坏时，程序不保存历史。程序不运行工具。程序把回复标记为未完成。
- 完成事件不产生可见文本。

## 5. 三类事件对照

| 事件类型 | 到达后程序做什么 | 去向 |
|---|---|---|
| 文本片段 | 立即显示。按序拼接。 | 显示端和最终文本组装器 |
| 工具参数片段 | 只累积。按规则组装。不显示。 | 工具调用组装器 |
| 完成事件 | 保存 assistant 记录。有工具调用时运行工具。 | 提交边界 |

## 6. 顺序规则

- 事件交错到达。程序不假设事件按类型分组。
- 收集与执行分离。参数在流式中累积。工具在完成事件后运行。
- 取消或断流时，程序丢弃未完成的组装。程序不保存历史。程序不运行工具。

## 7. 与现有实现的核对

2026-11-02 核对现有代码和契约。共有三处原表述需要校正。

- [turn.rs:1997](../../src/app/src/turn.rs#L1997) 和 [turn.rs:2010](../../src/app/src/turn.rs#L2010) 显示：assistant 文本或工具调用先入史。
- [turn.rs:2021](../../src/app/src/turn.rs#L2021) 显示：入史后回调 `on_record`。此时才运行工具。
- 原句“先保存历史。然后运行工具。最后保存最终文本。”改为“先保存 assistant 记录。如果记录含工具调用，然后运行工具。最终文本属于 assistant 记录。”
- 原句“文本片段只去一个地方：显示端。”改为“文本片段有两个去向：显示端和最终文本组装器。”
- 原句“事件分三类。”改为“处理去向分三类。”事件清单不只有三类。
- [api.rs:363](../../src/app/src/api.rs#L363) 和 [api/stream.rs:5](../../src/app/src/api/stream.rs#L5) 显示：现状先读取完整响应体，再整段解码。039 要把这条路径改为增量读取。
- [024 规格第 1.1 节](../specs/024-native-model-apis.md#L50) 要求收到合法完成事件后才提交。本规范沿用该门槛。
- [007 规格](../specs/007-session-persistence.md) 和现有 `on_record` 路径负责落盘。本规范不新增第二条最终文本记录。
