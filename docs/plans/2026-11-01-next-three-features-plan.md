# 下一批功能计划书

> 语言说明：ASD-STE100 是英文受控语言标准。本文件使用中文近似规则，目标约 80% 达标。文件使用短句、主动语态、一句一指令和统一术语。文件保留技术名、代码标识、文件名和产品术语。文件不使用完整受控词典。第 9 节列出达标项和差距。

## 1. 使用说明

- 本文件是计划书，不是规格。
- 开工前，先读 `rules/计划前调研.md` 和 `rules/规格文档.md`。
- 每个功能写一份规格。不要把三个功能合并成一份规格。
- 使用编号 039 至 041。如果编号已占用，使用下一个空闲编号。
- 先做 039。然后做 040。然后做 041。你可以调整顺序。三个功能相互独立。只有少量接口连接 039 与 040、040 与 041。
- 每个功能从 `main` 开工。使用独立分支。如果有其他 Agent 同时工作，使用独立 worktree。不要共用 Cargo 目标目录。

## 2. 总览

| 暂定编号 | 功能 | 解决的问题 | 建议顺序 | 相关规格 | 规模 |
|---|---|---|---|---|---|
| 039 | 流式输出 | 长时间等待时没有文本。用户无法判断程序在工作还是卡死。 | 1 | 006、007、008、024 | 中 |

## 3. 功能 039：流式输出

### 3.1 目标

模型输出到达时，程序显示输出。显示位置是终端用户界面（TUI）和命令行界面（CLI）。让用户看到进展。让用户能提前取消。收到合法完成事件前，程序不要保存历史。程序不要运行工具。

### 3.2 现状与依据

- [024 规格第 1.1 节](../specs/024-native-model-apis.md#L50)说明：程序支持 JSON 和服务器发送事件（SSE）。默认不流式。用户设置 `stream` 时，程序请求 SSE。但程序只组装完整回答。程序不逐词显示输出。
- [api.rs:327](../../src/app/src/api.rs#L327)：程序先读取完整响应体。然后调用 [stream.rs](../../src/app/src/api/stream.rs#L5)解析完整响应体。SSE 只是传输格式。程序不逐步消费 SSE 事件。
- [tui_host.rs:6](../../src/app/src/tui_host.rs#L6)：应用编程接口（API）不流式。用户轮同步运行。程序按行拆分完整回复。然后发送 `Delta` 事件。
- [tui_host.rs:813](../../src/app/src/tui_host.rs#L813)：程序只在此处发送显示事件。
- [main.rs:1189](../../src/app/src/main.rs#L1189)：CLI 在完整回复后打印 `Agent：{reply}`。
- 可复用部分：TUI 已有 `Delta` 和 `Final` 事件。TUI 已有 markdown 流式渲染和取消链路。五个协议的 SSE 解码器已存在。
- SSE 事件分类、显示与提交边界：[SSE 事件类型简明规范](../think-tank/2026-11-02-039-stream-sse-event-types.md)。
- API 层与宿主层改动：[流式输出简明技术规范（第二部分）](../think-tank/2026-11-02-039-stream-api-host.md)。

### 3.3 范围内

1. 在 `api` 中增加有界增量读取。按 SSE 事件顺序输出文本。保留总字节上限、总时限、取消检查和错误分类。累积工具参数片段。不要把片段显示为可见文本。
2. 在宿主中增加流式事件通道。把它接到 TUI。完整组装结果仍返回宿主，用于提交。只有最终回复结束时发 `Final`。工具批次中间不发 `Final`。在 CLI 中增量打印。在管道或非终端模式下，使用 001 契约的行为。
3. 收到合法完成事件后，先保存 assistant 记录（007）。记录包含文本和工具调用。如果记录含工具调用，程序运行工具（006）。工具结果按 006 规则逐条保存。取消或失败时，不要保存历史。不要运行工具。把回复标记为未完成。
4. 记录首字时间和流式字符数。用日志做性能检查和卡死诊断。

### 3.4 不包含

流式或并行运行工具。切换或回退协议。显示推理或思考内容。把部分文本写入会话文件。HTTP 重试（功能 040）。改变用户轮的 8 次请求上限。重写工具调用组装规则。

### 3.5 契约与风险

- 默认打开流式开关。保留关闭开关。开关关闭时，请求和显示行为不得改变。
- 只有收到合法完成事件并组装成功后，才能保存历史。然后运行工具。流式显示不是提交。
- 收到 SIGINT 后，停止读取。丢弃未完成的组装。不要保存历史。不要运行工具。为已显示文本选择一种处理方式。方式一：保留文本。加取消标记。方式二：清除文本。把选择写入规格。
- 断流、超时或解析错误在提交前失败。不要从 040 启动重试，除非 040 允许在用户没有看到输出时重试。
- 保存的文本必须等于完成时的组装文本。`/resume` 只恢复最终文本。它不重放增量。
- 风险一：读路径改动可能影响超时和 10 MiB 上限。风险二：它可能影响迟到响应丢弃（024 规格第 N16 项）。TUI 高频重绘和 markdown 块渲染可能引发性能问题。CLI 管道可能中断。测试需要确定性的 SSE mock，包含字节切分和延迟。

### 3.6 验收要点

- 对五个协议使用分段 SSE。测试任意字节切分、交错工具调用、缺失或损坏的完成事件。检查显示和提交边界。完成事件缺失时，任何工具都不能运行。
- 使用伪终端（PTY）和延迟 mock。证明用户在完整响应前看到文本。检查流进行中的屏幕。不要只检查日志。
- 在流中取消。CLI 必须保持存活。程序不要运行工具。程序不要保存历史。`/resume` 不得显示未完成文本。
- 保存会话。然后恢复会话。最终文本、工具显示和状态必须匹配当前行为。
- 运行全量回归。

### 3.7 待决

默认打开还是关闭流式。取消后保留还是清除文本。是否显示推理内容。非终端 CLI 的增量输出方式。

## 4. 功能 040：有界请求重试

### 4.1 目标

短暂传输故障后，不要结束用户轮。只在小范围安全重试。不要重放本地副作用。

### 4.2 现状与依据

- [api.rs:1](../../src/app/src/api.rs#L1)：模型适配层不重试，也不切换协议。
- [024 规格第 1.7 节](../specs/024-native-model-apis.md#L87)：HTTP 400、401、403、404、429 和 5xx 错误失败。网络错误、超时、坏 JSON 或 SSE、不完整输出也失败。程序不切换协议，也不重试。
- [006 规格](../specs/006-tool-call-loop.md#L44)坑 003：请求失败后，历史中可能已有调用和结果。重发请求的重试可能再次运行副作用。项目选择不重试。
- 当前失败点包括连接、DNS、超时、429 或 5xx、断开的 SSE 流、缺失的完成事件。

### 4.3 范围内

1. 对错误分类。对连接失败、超时、429、502、503、504 和完成事件前的断流重试。对 400、401、403、404、协议错误、解析错误和完整响应后的错误不重试。
2. 使用有界重试。使用带抖动的指数退避。遵守 `Retry-After`。设置最大尝试次数和最大总时间。取消时立即停止。每次尝试写日志。日志不得包含秘密。
3. 只在程序没有可提交响应且没有运行工具时重试。使用同一请求快照。不要再次读取配置或凭证（002）。
4. 在 CLI 或 TUI 显示简短重试状态。只显示一行。不要占满屏幕。增加关闭开关或默认上限。
5. 把上下文长度导致的 400 错误归为单独错误。不要重试它。把它交给功能 041。

### 4.4 不包含

供应商或协议回退。工具运行后的重试。除 429 外的 4xx 重试。无限重试。改变当前错误文本或退出行为。流式文本可见后的静默重试。

### 4.5 契约与风险

- 把每次 HTTP 尝试计入用户轮的 8 次请求上限，或设置独立总时限。选择一种规则。把它写入规格。不要让重试绕过上限。
- 程序显示流式文本后，不要重试。例外是 039 定义了丢弃并重启的路径。此时，040 必须使用同一边界和同一用户可见行为。
- HTTP 重试不得运行本地工具。历史只在得到完整可提交响应后改变。
- 重试不得再次读取 Key 或配置。使用功能 002 的快照。
- 定义默认行为和上限。开关关闭时，一次失败结束本轮，与当前行为一致。
- 风险：重试可能掩盖长时间故障。重试可能增加总延迟。测试需要虚拟时钟或受控 mock。预算、取消和流式的组合场景很多。

### 4.6 验收要点

- 使用 mock 测试：429 后 200、503 带 `Retry-After`、连接重置后 200。检查尝试次数、等待时间和最终成功。
- 401、400 和协议错误：不重试。错误文本不得改变。
- 退避期间取消：立即停止。不再发送请求。
- 完成事件前的断流：按规则重试。不运行工具。完成事件后：不重试。
- 完整流程中，每个本地工具只运行一次。检查预算计数。运行全量回归。

## 5. 功能 041：自动上下文压缩与 `/compact`

### 5.1 目标

在上下文达到上限前，压缩上下文。另一种触发是供应商返回上下文长度错误。生成交接摘要。然后切换活动上下文。保留完整历史。程序必须让用户能恢复会话。

### 5.2 现状与依据

- [032 规格第 1.1 节](../specs/032-context-management.md#L15)：第一版不运行自动摘要。它不调用供应商计数或压缩接口。它不裁剪历史。它不重试失败请求。预算不足时，模型必须请求切换。
- [turn.rs:2324](../../src/app/src/turn.rs#L2324)：只有模型调用 `new_context` 时，程序才切换。宿主没有阈值触发。
- [context_window.rs](../../src/app/src/context_window.rs)：估算、候选视图、V3 检查点和提交规则已有。复用它们。

### 5.3 范围内

1. 触发：在每个批次或轮开始前，用当前估算检查阈值。或者接收 040 传来的上下文长度 400 错误。然后发送一次摘要请求。要求模型给出交接摘要。应用当前 `new_context` 检查点。再次发送原请求一次。
2. 用户命令：CLI 或 TUI 中的 `/compact` 启动同一流程。
3. 限制：一个用户轮最多自动压缩一次。把摘要请求计入请求预算，或设置单独上限。问题未回答或工具批次运行时，不要压缩。失败时，保留当前窗口。报告失败。不要删除历史。不要重置权限、工具搜索集合或记忆。
4. 显示压缩原因、旧的和新的 `context_id` 和估算。记录摘要请求和切换结果。

### 5.4 不包含

供应商压缩或计数接口。后台摘要。自动裁剪历史。记忆合并。改变功能 032 的工具输入契约。如果需要改变，先修订规格。取得用户批准。

### 5.5 契约与风险

- 在规格中写明阈值和触发频率。写明摘要请求是否计入 8 次请求预算。写明第二次发送是否计数。
- 摘要失败、切换失败或第二次发送失败时，保留当前窗口。不要丢失历史。显示明确错误。
- 保留完整历史。V3 检查点只改变活动视图。`/resume` 必须工作。压缩不得重置权限、工具加载集合或问题状态（032 规格第 1.2 节）。
- 上下文长度 400 错误不进入重试。它进入压缩流程。第二次发送失败后，不要再次压缩。
- 1M token 的上下文窗口可能长期不触发阈值。按模型窗口比例设置阈值。不要使用固定 token 值。
- 风险：摘要可能丢失关键约束。每次摘要多花一次请求。触发循环可能用完预算。本功能与功能 032 的冻结范围冲突，因此先修订规格。测试需要受控估算和 mock 400。

### 5.6 验收要点

- 低预算：恰好一次摘要请求、一次切换和一次成功的原请求。`context_id` 增加。历史完整。`/resume` 工作。
- 供应商返回上下文长度 400：不重试。开始压缩。成功时，本轮继续。失败时，保留窗口。
- 未触发：零变化。请求字节、历史和预算保持不变。
- `/compact` 路径和自动路径使用同一核心。它们的行为必须一致。
- 问题未回答或工具批次进行中：拒绝压缩。说明原因。
- 运行全量回归。

## 6. 共性约束

- 每个功能写一份规格。开工时写 `docs/specs/0xx-*.md`。证据放入 `docs/logs/0xx-*/`。不要把三个功能合并成一份规格。
- 使用 AGENTS.md 第 4 节的顺序。运行 `ce-work`，然后运行 `comprehensive-testing`，然后运行 Security Testing（如适用）。然后运行 `ce-simplify-code`，然后运行 `ce-code-review`，然后做全量验证。只有工作产生代码和测试无法保留的项目经验时，才运行 `ce-compound`。
- 全量验证：在容器内 `/workspace` 运行 `cargo check && cargo test --workspace --no-fail-fast`。使用 `Cargo.lock`。不要升级依赖。过滤测试只用于诊断。
- 安全：039 显示未受信任的模型输出。040 涉及凭证和重试边界。041 把未受信任的摘要放入上下文。每个功能开工时，按 `.agents/agents/Security-Testing-Gate.md` 判定。
- 兼容性：039 和 040 关闭时，不得改变行为。041 关闭时，必须零变化。不要改变会话格式或恢复规则。
- 依赖：除非规格给出理由且用户批准，否则不要新增依赖。

## 7. 暂不排期

- 模型热切换、费用统计和其他用户体验（UX）项：本轮不排期。
